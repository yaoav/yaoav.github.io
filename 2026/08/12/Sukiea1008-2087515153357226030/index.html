读书不再是读完就完了｜我把《纳瓦尔宝典》变成了可调用的学习系统

发表于2026-08-12|行业观察
|浏览量:

本文转载自 X 博主 @Sukiea1008（Su） 的长文，原文链接，版权归原作者所有。

很多人缺的不是再多一份读书摘要，而是第 2 次打开。

凌晨 5:37，我还没睡。手机上翻的不是《纳瓦尔宝典》原文，是我自己做的学习地图 ——40 张概念卡，6 条路径，每张都能跳回原书页码。

不用重读整本书。睡前看一张卡，想一个问题，随时可以停。

白天遇到真实问题，同一份材料又会变成一个可调用的 Skill：先判断框架该不该介入，再找证据；不适用时不硬套，也不假装纳瓦尔本人。

读书不应该只留下一个摘要文件。它可以留下一个能复习、能查证、能调用、能积累、还能继续产品化的个人知识资产。

我把原书变成私有检索语料，把判断框架做成可调用的 Skill，再把概念、练习和来源做成适合手机阅读的学习地图。最后，它可以部署成一个随时打开的网页，也可以通过快捷提示词在需要时直接调用。
整条生产线我已经以 MIT 协议开源。仓库放在首评。

这篇文章会把下面这些一次讲全：

  • 为什么摘要、普通 RAG 和“模仿作者聊天”仍然不够；
  • 怎样把 PDF 或资料变成 Markdown 证据层；
  • 怎样从证据层同时长出对应 Skill 和学习地图；
  • 怎样把网页放到手机上，睡前随手复习；
  • 怎样用词环把长提示词变成随手调用；
  • 怎样用 Cloudflare Pages 完成低成本静态部署；
  • 怎样做部署台账，以及什么绝不能公开；
  • 这套东西如何继续变成内容、服务或学习产品。

文章比较长，但每一节都能单独使用。

你可以按标题跳读，也可以直接把全文交给 AI，让它先提取和你最相关的部分。

如果你现在就想带走

把下面整段复制给支持 Agent Skills 的 Agent：

请帮我安装这个 GitHub 仓库里的 su-learning-map Skill：
https://github.com/doublesq97-ui/su-learning-map/tree/main/su-learning-map
安装完成后，请告诉我：

  1. 安装到了哪里；
  2. 如何快速调用；
  3. 第一次使用需要准备什么材料；
  4. 给我一条可以直接替换内容的最短调用示例。

仓库里除了完整 Workflow，还有纳瓦尔、李笑来和马斯克三套已跑通的赠品。每套都包含在线学习地图、可离线打开的网页源码、对应 Skill 和调用方式。

我想解决的从来不是“怎样更快读完一本书”

现在让 AI 总结一本书太容易了。

把 PDF 丢进去，可以要章节摘要、核心观点、金句、思维导图，甚至让它模仿作者和你聊天。

问题是，很多人缺的不是第 11 份摘要，而是第 2 次打开。

摘要生成的那一刻很爽：几千字看起来很完整，仿佛已经掌握了整本书。但保存进文件夹之后，它往往和原书一起消失。下次遇到真实问题，还是想不起那条观点；即使想起来，也不知道它的上下文、适用条件和原文位置。

我自己再针对「AI时代如何阅读」过程中，反复遇到五个痛点：

  • 没时间重新进入。 完整摘要仍然是一篇长文，每次都要恢复上下文。
  • 看过，却没留下。 收藏、画线和总结很容易，真正形成自己的判断很难。
  • 输出很快却没法验证。 AI 的原文、综合和推断混在一起，越流畅越容易让人放弃核验。
  • 需要时不知如何调用。 读过“特定知识”“杠杆”“所有权”，做项目时却不会自动想到它们。
  • 整理完仍然是散件。 PDF、笔记、Prompt、Skill、网页和部署链接分散在不同地方，半年后自己都找不到。

所以我真正要的不是“把 242 页压成 20 页”。

我要的是：平时能一点点学，遇到事能随时调用，重要判断能追溯到来源，不适用时知道闭嘴，而且每次整理都会沉淀成我自己拥有的资产。

做完以后，它具体帮了我什么？

最直接的变化，是我真的会二次查看。

以前重新打开一本书，需要找进度、恢复上下文、决定今天读多少。现在打开收藏夹，pages 会带我回到一条明确的学习路径。我只处理一张卡：理解概念、看论证、回到来源、回答一个和自己有关的问题，然后标记进度。

这很适合作为睡前读物。它不像课程一样要求连续投入，也不像短视频一样刷完只剩情绪还会越刷越兴奋。

第二个变化，是知识开始参与真实判断。

《纳瓦尔宝典》对应的 Skill 不是“纳瓦尔语气生成器”。当话题涉及职业与项目选择、个人商业模式、特定知识、杠杆、所有权、长期复利、财富与自由，或者欲望与幸福时，它会先问：这套框架在这里真的有用吗？

有用，才读取对应概念和证据；只有部分有用，就说明成立条件；价值不大，就正常回答。

例如我问一个项目值不值得长期做，它不会只丢一句“使用杠杆”。它会继续拆：我是在出售更多时间，还是积累所有权、信誉与可复利资产？它是否匹配我的特定知识？它是一场可以重复的长期游戏，还是短期收益？哪些欲望、身份和社会比较正在干扰判断？

第三个变化，是重要结论可以查证。

回答至少分成四类：原文观点、多来源综合、基于框架的推断、需要联网确认的当前事实。涉及当前公司、市场、人物或投资事实时，旧书不能替代今天的核验。

第四个变化，是一份整理可以不断长出新东西。

同一份证据底座可以生成学习地图、对应 Skill、快速调用 Prompt、概念卡、练习题、移动网页和内容选题。以后想分享、复习或做成产品，不需要从 PDF 再来一遍。

这也是它和普通“读完一本书”最大的不同：我得到的不是一次信息消费，而是一项以后还能继续工作的知识资产。

以《纳瓦尔宝典》举例

这次使用的是 242 页完整 PDF。

我先生成一份私有 Markdown 检索层，每一页都有独立锚点，同时保留 57 个目录入口。Markdown 负责快速检索，PDF 继续作为精确引用的最终依据。

然后根据原书实际内容整理出 6 条能力学习路径和 40 张深度概念卡。具体多少张深度概念卡，不是由 Skill 指定数字，而是由材料深度决定。

每张深度卡都包含：

  • 它原本在回答什么问题；
  • 为什么值得学；
  • 至少三步的论证过程；
  • 原始内容的忠实摘要与页码定位；
  • 最容易被怎样误用；
  • 和其他概念的连接；
  • 一道必须联系自己生活回答的练习题。

网页支持学习路径、搜索、笔记、进度和来源跳转，并分别按桌面与竖屏手机尺寸验证。

公开网页不包含完整 PDF 和全文 Markdown。它只展示重新组织后的学习内容、必要的短引用、来源定位和官方链接。

这套学习系统的底层逻辑

如果用工程语言写，它是：

PDF / 资料
→ Markdown 证据层
→ RAG 检索
→ 对应 Skill
→ Learning Map
→ Cloudflare Pages

它说明了每一层的责任和真源。

但对于大多数用户而言，更重要的是：

把散落的资料收回来
→ 让重要结论找得到、查得清
→ 让 AI 在正确的时候调用
→ 让自己每天都能继续学
→ 让手机随时打开，也能继续分享和产品化

工程上是六个环节，学习上可以归成五层。

1. 原始材料：决定这套系统究竟知道什么

书籍、课程、论文、文章和访谈先做来源盘点。

完整书籍与付费材料默认留在本地。人物或时效性主题需要联网补充时，优先使用本人著作、官方网站、完整访谈和真实决策记录，再加入外部批评与冲突证据。

这一层不急着总结，先记录来源、日期、类型、覆盖范围、证据等级与使用限制。

原材料不可靠，后面的 Skill 只会更稳定地产生错觉。

2. Markdown 证据层与 RAG：先找证据，再组织答案

对于完整 PDF，我会生成带页码锚点的 Markdown。

Markdown 不是拿来公开卖的书摘，而是本地检索层：先快速找到相关段落，再回到 PDF 页码核对语境和准确措辞。随后 RAG 根据问题只取真正相关的证据，不必把整本书每次都塞进上下文。

证据至少分五类：

  • primary：本人著作、完整访谈、官方记录；
  • corroborated：多个一手来源反复出现的稳定模式；
  • external：可信的外部批评或观察；
  • inference：基于框架推导出的新判断；
  • current：需要联网并标注日期的当前事实。

这一步解决的是普通 RAG 经常忽略的问题：检索到相似内容，不代表有权把它写成作者的确定观点。

如果不想自己搭 RAG，也可以把合法持有的原始材料或整理后的 Markdown 导入支持知识库问答的工具，例如腾讯 ima，再用它完成检索问答和原文回查。根据腾讯云开发者社区目前公开的产品说明，ima 支持 PDF、Markdown 等多种格式导入、知识库检索和引用；实际能力与入口以后可能变化，使用时再核验。

这个替代方案能降低技术门槛，但它只替代“检索层”；证据分级、Skill 路由、学习地图和公开边界依然由这套 Workflow 负责。

3. 对应 Skill：规定 AI 什么时候开口、怎样判断

Skill 不应该只是把几十条金句塞进系统提示词。

至少要写清四件事：

  • 什么问题应该触发；
  • 触发后调用哪些模型和证据；
  • 哪些情况下框架会失效；
  • 最后怎样给出一个可验证的下一步。

人物 Skill 默认做“框架顾问”，不冒充本人。

4. 学习内容与地图：让人真的学，而不只是让 AI 会答

学习路径要围绕能力变化，而不是照抄目录。

“创造财富”只是主题，“识别能持续复利的杠杆”才是学完后获得的能力。

一张合格的卡至少让人完成三个动作：理解一个概念、回到一个来源、写下一次自己的判断。

当材料需要做成完整学习版时，再增加问题背景、论证链、来源精读、误用边界和概念连接。

卡片数量跟着证据深度走，所以我不在这个skill里约束，一本书、一个人物的了解过后你具体能得到多少张学习卡片。数量少了会很可惜也会有一些讯息被挤压，数量多了，AI会开始胡编乱造的给你凑，因为它的质量门成了数量。

5. 可持续交付：让它第二天还找得到

网页不是为了把知识“做得高级”，而是解决一个很现实的问题：如果这套系统只能存在于某次 AI 对话里，它很快就会丢。

静态学习地图可以直接在浏览器运行，电脑和手机使用同一份数据。页面负责阅读体验，内容 JSON 负责学习内容，Skill 负责调用行为，私有语料继续留在本地。

让人能够容易反复触及的内容，我将其称之为「可持续交付」。

同一条生产线，可以长出完全不同的 Skill

学习地图和 Skill 不是附属关系，它们共享同一份证据底座。

像我在这个开源内容中分享的一些现有的产物，就可以论证不同的物料、证据、适配的场景也不同：

《纳瓦尔宝典》更适合处理职业与项目选择、特定知识、杠杆、所有权、长期复利、欲望与幸福。

李笑来的材料会把重点转向概念重定义、注意力与时间、个人商业模式、成长学习、长期积累、决策和写作。

马斯克的材料则更适合工程、产品和公司问题：使命选择、第一性原理、理论极限、瓶颈、五步算法、制造、组织和快速反馈。

输入如果换成“交易系统设计”，又应该生成另一种 Skill：比较方法、风险约束、执行规则和失效条件，不模仿任何人的语气。

这就是这条生产线真正可复用的地方。纳瓦尔不是产品本身，只是一个真实案例。由此，你可以生成多套你所认可的、你所需要的，比如通过某些产品专家、传奇操盘手的人生经验或者书籍，来获得学习卡片和可溯源并且可调用的skill。因此，不得不补充的一件事是，那么原始证据变得较为重要。

GitHub 中我放了纳瓦尔、李笑来和马斯克这三套成品：在线学习地图、静态网页源码、对应 Skill 和最短调用方式。先打开成品，再决定要不要自己跑一套。

为了更方便的调用这些skill，我将提示词放进了词环

Workflow 的完整调用提示词比较长。每次寻找和复制，都会让调用摩擦变大。

词环是我自己开发的一个产品，我在这里顺带带一嘴，正在筹备上架Appstore（MacOS）。

它只需要用快捷键调出一个轮盘并进行快速选择，使用习惯后极容易成为肌肉记忆。

所以我把常用人物框架和学习地图的 Workflow 放进词环。

它没有增加新的推理能力，只是把“我知道有这套东西”变成“我随时能够快速调用”。

不用公开你的仓库，也可以将pages网页快速上线

对只有 HTML、CSS、JavaScript 和数据文件的静态学习地图，Cloudflare Pages 免费计划通常已经够个人使用。

根据 Cloudflare 2026 年 8 月官方文档：静态资源请求在免费和付费计划中都免费且不限量；免费计划包含每月 500 次构建、单站最多 20,000 个文件、单个静态文件最大 25 MiB，并允许每个账户最多 100 个 Pages 项目。只有使用 Pages Functions 时，请求才计入 Workers 配额；免费计划目前是 Workers 与 Pages Functions 合计每天 100,000 次请求。

对不带后端函数的个人学习地图，这个范围通常足够。额度以后可能变化，部署前应重新查看 Cloudflare Pages Limits 和 Pages Functions Pricing。

最短部署路线不需要把仓库公开，也不要求先购买自定义域名：

npx wrangler login
npx wrangler pages project create
npx wrangler pages deploy

Cloudflare 也支持在后台直接上传文件夹或 ZIP，完整步骤见官方 Direct Upload 文档。

部署后会得到一个 *.pages.dev 地址。但必须说清：它是公开网址，不是私人网盘。“我没有发链接”不等于“网站有访问控制”。完整 PDF、全文 Markdown、私人笔记、环境变量和凭据都不能进入部署目录。

为什么我推荐做一份部署台账？

当学习地图从一个变成五个、十个以后，真正麻烦的不是部署，而是忘记：它为什么存在、代码真源在哪里、哪个网址是生产版、最后一次验证是什么时候。

一张最小台账记录这些字段就够了：

Secret 只记录名称和“是否已配置”，绝不记录值。

不想自己设计表格，可以直接把下面这段交给 AI：

请为本次 Cloudflare Pages 部署建立一份项目台账。
至少记录：项目用途、归属主体、环境、Cloudflare 资源名称、公开地址、代码真源、部署方式、公开或认证状态、当前状态、部署日期、验证日期、验证证据和下一动作。
先检查公开包是否误含 PDF、私有语料、环境变量或凭据。Secret 只记录名称和是否配置，不得记录值。
只有在生产 URL、CSS、JavaScript、数据文件、桌面与手机页面以及关键交互全部验证后，才把状态标记为“已验证”。

仓库里放的是脱敏后的通用台账模板，不包含我的项目名、账号、网址或内部记录。

可直接复制的完整调用提示词

安装后可以直接用简版：

$su-learning-map
主题：[填写]
材料：[文件、目录或 URL]
交付：[完整流程 / 仅私有语料 / 仅 Skill / 仅学习地图]
联网：[需要 / 不需要 / 你判断]
Cloudflare Pages：[部署 / 暂不部署]

需要完整约束时使用：

请读取并执行 su-learning-map Skill。
当前主题：【填写】
当前材料：【附文件、目录或 URL】
目标学习者：【填写；未填写时根据材料与使用场景推断】
交付范围：【完整流程 / 仅私有语料 / 仅 Skill / 仅学习地图】
联网补充：【需要 / 不需要 / 你判断】
Cloudflare Pages：【部署 / 暂不部署】
直接按 Skill、references、scripts 和 assets 中的默认规则执行。不要复述完整规则，也不要要求我重复确认已经明确的信息。
只有在以下情况暂停：

  1. 材料缺失或证据质量不足，无法达到当前交付范围；
  2. 会覆盖或实质修改一个已有 Skill；
  3. 需要改变公开 / 私有边界；
  4. 部署需要新增付费资源、认证方式或尚未授权的外部写操作。
    完成时报告：产物位置、证据范围、推断边界、桌面与手机验证、公开状态、部署状态和下一个验证案例。

为什么我决定把这套 Workflow 开源？

因为我不想只分享一个好看的纳瓦尔网页。

真正可以复用的，是怎样处理材料、保留证据、生成 Skill、组织学习内容、验证手机体验，以及安全部署的整套方法。

这次 GitHub 可以带走：

  • su-learning-map Skill 与完整调用提示词；
  • 证据分级、学习内容 Schema 和质量门；
  • PDF 转页码 Markdown、深度卡合并与学习地图构建脚本；
  • 响应式阅读器、主题与 Cloudflare Pages 部署说明；
  • 脱敏台账模板；
  • 纳瓦尔、李笑来、马斯克三套真实成品。

值得注意的是，它不包含：

  • 任何完整书籍或付费课程全文；
  • 私有 Markdown 与 RAG 数据库；
  • 个人笔记；
  • Cloudflare 项目、账号、内部台账或 Secret；
  • 一个号称适用于所有资料的“万能答案”。

公开的是生产线和可移植成品，不是别人的原料。

如果你最近刷小红书变现，可能也注意到了

这套skill，只要你愿意，他是具备变现价值的，但不是靠把别人的书重新打包一遍。

一个用户愿意购买的，通常不是“这里用了 AI、RAG 或 Agent”，而是结果：不用自己重新整理几十个文件，不用反复翻找原文，不用从零设计学习路径，也不用研究怎样把网页放到手机上。

如果一定要把它写成一句产品定位，我会这样说：

帮助没有时间反复重读、又不想把判断完全交给 AI 的人，把一套重要资料变成能学、能查、能问、能长期使用的个人知识资产。

用户愿意付费是为了：

  • 节省重新整理与搭建的时间；
  • 避免摘要失真、来源丢失和做完找不到；
  • 得到一套可以立即学习、查询、调用和持续更新的成品；
  • 把自己的课程、行业资料或方法论继续做成产品。

真正可以收费的，是材料整理、证据结构、主题设计、适用场景、学习路径、练习系统、交互体验、定制实施和持续更新。

它可以长成至少四种形态的交付：

  • 个人学习版：把一本书、一门课或长期收藏变成私有证据层、学习地图和对应 Skill；
  • 创作者版：把自己拥有版权的课程、方法论和内容资产做成配套学习产品；
  • 专业主题版：围绕交易、行业经营、写作或工程等主题，建立多来源、可持续更新的学习系统；
  • 定制实施版：帮客户梳理材料、设置公开边界、部署页面，并交付后续维护方法。

如果放到小红书或其他内容平台，最安全也最有价值的卖点仍然不是“我有一本别人没有的书”，而是“我替你完成了整理、查证、学习设计和交付”。原始材料属于谁、哪些内容能公开，必须先于销售考虑。

但商业化只是这条路线能够走到的一个分支。我最先想解决的，仍然是自己读完、忘掉、找不到、用不起来的问题。这个仓库是MIT协议开源的，意味着即使你使用这套方法进行变现，不会有任何问题，但是如果你打算这么做，或者觉得这个内容真的不错，希望你能给我的仓库一个 Star。

最后说明一下：它和普通蒸馏 Skill 的差别

花叔是我进入AI领域里就非常敬佩的一个前辈，他的女娲（nuwaskill）擅长把一位公众人物的著作、访谈、行为和表达蒸馏成可调用的人物 Skill。如果只想要一个人物框架顾问，到这里已经够了。

su-learning-map 在输入是人物时可以调用这类专业能力，然后继续完成证据层、RAG、学习层、体验层和交付层。它的输入还可以是一本书、一门课程、一批论文或一个专业主题。

普通蒸馏主要解决：

AI 能不能使用这套知识回答问题？

完整学习系统还会继续问：

人能不能复习、查证、练习、记录进度、随时调用，并把它继续沉淀成自己拥有的资产？

所以它们不是竞品，而是工位与生产线的关系。哪天出现更好的蒸馏工具，替换其中一个工位就行；证据、学习内容等，页面和交付结构不需要推倒重来。

这套学习系统的适合人群

它适合：

  • 一本值得反复回看的书；
  • 一位有足够一手材料的公众人物；
  • 一套长期课程或访谈；
  • 一个需要比较多种观点的专业主题；
  • 自己已经积累多年、准备系统化的行业资料。

如果只是想知道一本书大概讲了什么，普通摘要已经够用，不必建一条生产线。

如果版权、隐私或证据质量不清楚，也不要急着公开。先保留本地版本，缩小公开范围。

最后

读完不是终点，生成摘要也不是。

一本书真正开始产生复利，是在你会反复回来、能在真实问题里调用、敢回到来源核验，并逐渐形成自己的答案以后。

我开源这条生产线，不是想让所有人都做一个纳瓦尔网页。

我更希望你拿走方法，把自己真正关心的知识，做成一个今晚愿意翻、半年后还找得到、遇到问题仍然能调用的东西。

完整 MIT 仓库与三套成品见文中的安装模块，也会放在首评。
