中文推特值得关注的 100 人：从每个人的一篇作品读起

我想知道一个 AI 工具能不能进企业，最想看的是它第一次出错的地方。比如有人请 AI 统计一瓶精华的差评，帖子里恰好提到两瓶，挨骂的是另一瓶。也有人用 AI 接婚礼视频订单，最费时间的一步，竟是跟新人问清楚两个人当年到底怎么认识的。

这类细节让我决定关注一个人。等我自己也碰到类似的问题，还能翻回去找他，看他当时怎么做。

我从自己的中文 X 关注列表里挑了 100 位作者，每人留一篇入门作品。做企业项目的，可以从第一组读起；正在做账号的，直接翻到第四组；已经做出了产品却还没找到客户的，我会先看第五组。文中涉及收入和流量的数字均为作者自述。

这份清单受司徒 K 的文章启发。司徒 K 的原帖

一、企业 AI 落地与 Agent 交付

01｜Smartpig

Smartpig 写企业里的 AI 分工，擅长把一个岗位拆成助手能接手的具体任务。他翻了 Grok Bot 场景库里的 56 个角色。费用助手要把收据、表格和系统记录对在一起，发票协调员要找出哪张单据还没人处理。给企业讲 Agent 时，这些例子能把“数字员工”说具体：谁提供材料，助手交回什么，哪个异常还得人处理。

代表作：我翻完了 Grok Bot 官方场景库：56 个 AI 数字员工，覆盖 9 大领域

02｜ninety是九零

ninety是九零 做 AI Agent 工程，关心模型给出的答案怎样变成用户能操作的产品。作者展示如何把 Agent 输出从 Markdown 改成安全的交互界面：模型只生成带组件 ID 与属性的结构化消息，客户端按白名单渲染并校验，不执行任意 HTML/JS；滑块等本地交互由前端更新，只有需要业务操作或推理时才调用后端/模型。文章以保险报价页演示方案，并坦承这是轻量实现、未覆盖完整协议与流式输出。适合做 Agent 产品的工程师参考。

代表作：Generative UI 实战分享，让模型输出变成能拖能点的界面

03｜Cloris 🌱

Cloris 写 AI 调研实操，她的教程尤其适合需要自己核验来源的人。她用一张调研表带读者走完 Claude Duet 的首个任务。拿到结果后，随机点两三条来源，看标的价格是按年还是按月、官网有没有写出对应承诺。有错就在同一个任务里改。想教同事验收 AI 调研，这个练习拿来就能用。

代表作：Claude Duet 保姆级教程：从排队到完成第一个任务

04｜@eze_is_1

一泽关注智能体的日常使用，他的经验能帮你判断什么时候该拆任务、什么时候该省算力。作者总结 Grok Bot 的十条实操经验：Bot 适合长期重复的非编码任务，先让一个 Bot 承担完整职责，等工作流稳定或上下文互相污染再拆分；用共享记忆、Skill 与云端文件管理上下文；标准化流程交给 CLI Agent、机械检查写成脚本以省额度，并用 webhook 唤醒长任务。还分享浏览器自动化、息屏限制和 Notion 看板取舍。对搭个人 Agent 系统有较具体的架构参考，部分能力会随产品更新变化。

代表作：10 条必备经验，让你的 Grok Bot 变得更好用

05｜姚金刚

姚金刚写 AI 搜索获客，给企业提供从内容投入追到实际咨询的办法。姚金刚讨论企业如何衡量 GEO 的获客效果。他建议从少量核心词试点，为线索设置来源标记，再追踪从 AI 回答到咨询、成交的过程。文章也指出，间接影响和延迟转化较难完整归因。对于要向客户解释投入和结果的服务者，这篇可以作为设计试点与记录口径的起点。

代表作：GEO到底该投多少钱？1.3万字讲透效果归因与ROI

06｜浙大曾哥聊 AI商业

这位有银行和科技企业工作经历的作者写企业 AI 和人才选拔，适合想招到能把项目交到业务手里的人读。作者复盘为企业招聘 FDE 的两场真实面试，整理七组追问：先判断需求值不值得做、跟岗发现真实流程、比较系统迁移成本、验证技术贡献与业务采用等，并附四维评分权重和 13 个问题。文章把面试回答如何映射到业务洞察、工程交付和组织推动讲得具体，老板可借作面试框架，求职者可用来检视项目经历；案例隐去内部信息。

代表作：老板怎么招 FDE，求职者怎么准备？复盘我在孚德文化的两场真实面试

07｜得否

得否从办公室里的琐事测试 AI 助手，能帮你看出哪些步骤可以交给工具。得否用招聘实习生的真实场景演示邮箱 AI Agent：先用自然语言要求整理简历和下载附件，Agent 会先询问统计范围、附件范围，再处理邮件；随后生成候选人 Excel，甚至补回主题不含“简历”关键词而漏检的一位求职者。文章强调把模糊需求拆成结果、边界与复核，同时展示邮件搜索、附件整理、表格输出的端到端流程，适合评估 AI 助手能否承担办公事务。

代表作：你看这事儿闹的！我本来是想招个实习生，结果先替我干活的是AI

08｜Miles Ma

Miles Ma 写企业 AI 项目的工程实践，尤其值得跟他学怎么验证一个数字是否可信。美妆客户问一款精华过去 30 天口碑如何。一条帖子同时提到两瓶精华，骂的是 B，系统却可能把差评记在 A 头上。Miles 把四种取数方案放在一起比较，最后让工具固定统计口径，让模型选工具，每个数字都带回原帖。准备把 AI 报表交给业务部门的人，可以拿这个反例做验收题。

代表作：FDE 实战案例：可信取数（AI 工具选型与四次踩坑复盘）

09｜黄啊码

黄啊码做企业 AI 培训和项目陪跑，关注 AI 项目交付，把团队该如何提测、验收讲得很具体。一位技术负责人用 AI 做出一批页面，团队却要花一周检查，最后还得大改。黄啊码追问了几个很朴素的问题：哪天交哪个功能，谁提测，什么情况要打回？这篇适合项目负责人看，尤其是当团队开始用“今天生成了多少”代替汇报“客户验过哪些”时。

代表作：what？堂堂博士大佬，为什么无法正常交付 AI 项目？FDE 这个词失效了？

10｜@runmaotui

奔跑的大毛腿从产品经理的工作入手，梳理 AI 能在哪些环节接过一部分工作。这份产品经理 AI 实践手册沿需求全流程展开，从项目资料初始化、市场分析、需求调研和分析，延伸到原型、PRD、评审、研发、测试上线与运营反馈。作者强调持续维护项目上下文、交代真实设计约束，并由产品经理做需求取舍和最终判断；PRD也要考虑成为 Agent 间的信息交接。适合希望把 AI 稳定嵌入产品团队流程的人参考。

代表作：深度长文｜2026产品经理AI实践手册

11｜成峰（AI产品自由）

成峰做智能体协作实验，他会把多台设备、多个助手一起工作时的限制写出来。几个 Agent 同时操作浏览器，一个刚打开资料，另一个就把页面切走。成峰试了给每个 Bot 分配独立屏幕，再把协作任务放进同一个群。特别值得读的是那句技术区分：屏幕分开了，文件、登录状态和计算资源仍然共享。要搭多智能体系统，这会直接影响你怎么分工。

代表作：Grok Bot，给 AI 配了一台自己的电脑

12｜饼干哥哥AGI（3.0）

饼干哥哥用数据分析做消费者研究，读他的文章可以学到怎么把零散评论整理成业务指标。他拿宠物安神咬胶做消费者调研。抓回 4,185 条评论，去掉推广、跑题内容，再限制一篇热门帖对样本的影响，最后 3,174 条进入统计。同一批标签能回答选品、卖点和竞品问题。关注他的理由是，你能看清从一条人话到一个业务指标之间，究竟丢了什么、保留了什么。

代表作：十年数据分析经验，被我打包成了4个跨境VOC Skill

13｜蓝哥AI

蓝哥AI 写日常工具实操，擅长从邮箱、账单这类小事里找到值得自动化的一步。蓝哥以多种 AI 服务的续费和收费变更邮件为例，演示把邮箱通知转成工具维护待办：搜索近 30 天 AI、开发工具及网站服务邮件，重点抽取收费变更、年费续订和付款异常，再整理待处理与已发生费用。它把邮箱 Agent 的价值具体落在订阅管理，帮助常用多种工具的人减少漏看提醒；文中也给出可按个人情况改写的检索提示词。

代表作：AI 管理工具订阅邮件的实用场景

14｜mousepotato

mousepotato 从个人办公场景试用 AI，适合想用手头的小任务检验助手能力的人。他从手机上处理一周积信，先让助手挑出今天要办的事，再拿熟悉的邮件核对；发现不对，就缩到主账号并排除广告，最后导出表格。这个案例胜在小：你当天就能判断助手有没有漏掉扣款通知，无须先搭一套庞大的个人知识库。

代表作：人在外面，一条指令把一周邮件收成今天要办的事

15｜@goan999999

G 哥写行业 AI 产品的早期探索，值得看他怎样从客户的实际操作里找需求。G 哥用故事写一款客服草稿工具怎样找到第一批价值。店主改了 AI 的回复，主角就记下原问题、已有事实、改了哪句和为什么改。对做行业智能体的人，这个观察很实用：客户改掉的那一句，往往比他说“挺好用”更能告诉你下一版该做什么。

代表作：6000字故事 ｜ AI 产品搞钱入门教程：普通人，怎么从0赚到第一桶金

二、AI 编程、智能体与开源实践

良竹有软件和项目管理经验，写 AI 建站实操，能帮第一次上线网站的人发现容易漏掉的安全检查。他把新人部署网站时容易漏掉的事情写成短清单，包括防止密钥进入 Git、泄露后轮换密钥、校验资源归属，以及给生成接口设置速率限制。做第一款 AI 网站时，可以拿其中一项实测：换一个登录账号，还能不能读到原账号的数据？

Dash 关注团队怎样组织知识，尤其关心人和 AI 能否共同读取、修改并追溯一份资料。文章提出把 GitHub 仓库当作 AI 原生知识协作底座：Markdown 等结构化文件便于模型检索，版本历史保留来源与变更，多个本地 Agent 可围绕同一份资料协作。作者也指出权限与可见性治理是前提，适合团队思考如何让知识既可读又可追溯。

代表作：为什么要用 GitHub 作为 AI Native 时代的知识协作底座

19｜@JefferyTatsuya

@JefferyTatsuya记录 AI Agent 的早期实验，给今天的读者留下了比较能力变化的参照。这组早期 AI Agent 实验记录展示了当时的能力边界：代理已能尝试建站、查数据库并写报告、做调研和销售线索搜集，也能编写与测试代码。作者用大量具体任务说明“能拆解并调用工具”带来的潜力，同时隐含呈现结果仍需人检查，适合作为 Agent 演进的历史切片。

代表作：AI代理人已经出现四星期，进入井喷状态，现在的一系列进展已经很惊人

20｜yan5xu

yan5xu 分享用 AI 写生产代码的经验，能帮工程团队设计任务交接和验收方式。作者把 Agent Coding 的日常痛点归结为上下文失忆，提出用 HANDOFF 交接、Sub-Agent 分工、Worktree 隔离并发，并让 Agent 自跑测试、看日志；SCOPE 文件则限定可写路径与禁区。文章把多年生产实践整理成可复用的 Code Relay 协议，核心是给 Agent 足够工具、可验证任务和最小权限。

代表作：Agent 工程师，是怎么用 AI 写代码的

代表作：我用 Claude Code 和 Opus 5.5 并行跑三个 loop

22｜idoubi

代表作：我的 Vibe Coding 项目

23｜铁锤人

铁锤人写个人研究工具，擅长把信息收集、知识整理和下一轮提问连在一起。作者搭建从优质 AI Newsletter 到 Hermes Agent 的研究管道：专属邮箱收信，日报初筛，再让 LLM Wiki 抽取概念、观点和问题并连入 Obsidian 知识图。最后把知识索引交给 AI 做脑暴、补盲和信息图，强调 AI 帮助深化理解与输出，不应把学习简化成自动摘要。

代表作：Hermes Agent 工作流：用顶级 AI Newsletter 构建第二大脑

24｜@gengdaJ

@gengdaJ做创作工具，把笔记、模型记忆和发稿接起来，适合有固定写作流程的人。逸尘把自己的创作助手 Ailu 装进 Obsidian，让 Codex 和 Claude Code 共用创作记忆，写好的文章能预览不同平台的版式，再送进公众号草稿箱。他还拆开解释了中转服务器为什么存在。关注他，可以看到笔记、模型记忆和发稿之间那些需要自己补上的接口。

代表作：这是掌管Obsidian创作的神！

25｜哥飞

哥飞分享开发工具的使用经验，能帮长期用代码助手的人把项目约定保存下来。作者实测 Claude Code 自动记忆，说明它会从对话中沉淀偏好、技术栈、设计决策与项目约定，并在新会话自动加载。文章还给出 MEMORY.md 的启用方法和前200行限制，建议全局索引搭配项目独立记忆；对比手工记忆方案，指出自动记忆可降低长期调教成本。

代表作：Claude Code 关于记忆的重磅更新

26｜大卫｜AI抄作业

大卫写给第一次用 AI 做网站的人，他把部署和调试拆成新手能自己验证的小步骤。他给初次用 Codex 建站的人留了一道小作业：只写网站名字，上线，再关掉 Wi-Fi 用手机流量打开。连这一步都没走通，就能先把部署问题和业务代码分开。文中还提醒把长期要求留在项目文件里、把接口密钥放在服务端，适合准备交第一个网站的人。

代表作：用 Codex 做网站之前，先抄这 5 份避坑作业！

27｜Tinyfool

Tinyfool 记录用 AI 开发网站的过程，适合想看一个原型怎样被反复改到可用的人。作者展示了从手绘草图出发，让 Gemini 生成页面，再把原型交给 Antigravity 改成 Laravel 网站的全过程，逐条列出真实提示词和反复修正：CMS、文章类型、图片上传、导航、部署等问题都在迭代中暴露。价值是把“AI 一句话做网站”的宣传还原为具体协作流程，也提醒读者上线仍需调试、部署和取舍。

代表作：一行代码不用写，从草图到可运行的数据库驱动的全功能网站，全面用AI生成，提示词全记录

28｜weijunext

weijunext 做出海软件，也写开源网站模板，他会把内容产品背后的技术选择讲给想动手的人听。作者从阮一峰周刊的长期影响切入，替非技术朋友搭建可运营的周刊模板，并开源完整实现。文中具体讲清信息筛选的产品机会、Next.js与MDX动态渲染、页面布局、评论和字体选择；价值在于把内容副业想法拆成能快速上线、持续迭代的技术路径。
