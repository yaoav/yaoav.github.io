开了 TUN 就是全局？一文讲清代理软件的「规则、全局、系统代理、TUN」（附最佳实践）

规则、全局、系统代理、TUN，我也花了蛮长时间才弄懂这些门道。

没弄清楚之前，很多人告诉我，要用 Claude Code 和 Codex 这样的 AI 应用，你就无脑开 tun 模式和全局就行了。

当时我就有困惑，开了 tun 模式，那系统代理还要开吗？这俩代表啥意思？

这一点倒还好，仅仅是困惑，至少不影响使用。但开了 tun + 全局，我发现刷个视频号开始变得巨卡，这已经完全影响到我的日常使用了，该怎么解决？

这篇文章就用最简短、最直白的文字，配上几张图，快速把里边的门道讲清楚。

如果你实在懒得看，把文章丢给 Agent 吧，里面有最佳实践和给 Agent 的配置提示词，让你的 Agent 帮你搞定所有事情。

这一套配置下来，该走代理的走代理，该走直连的走直连。AI 应用、国内网站丝滑无比，并且省钱（不浪费代理的流量，不该走代理的就不走代理）。

化繁为简：分两组配置来看

第一组：接管开关（决定谁被接管）

  • 系统代理：在系统设置里填一个代理地址，只对「会主动读取这个设置」的软件生效（如浏览器）。终端命令行、游戏和很多桌面客户端不会读取这个设置，仍然直接连网。
  • TUN 模式：在系统里建一张虚拟网卡。不管软件读不读系统设置，整台机器的所有网络请求都会先经过这张虚拟网卡，统一交给代理软件处理。

**开了 TUN，还要开系统代理吗？

**要！理论上开了 TUN 就能接管全部流量，可以不开系统代理。但最佳实践是同时开：

  1. 浏览器走系统代理，规则匹配更直接：开启系统代理后，浏览器会把要访问的域名（如 x.com）直接传给代理软件，代理软件按域名就能直接匹配分流规则。如果不开系统代理，只走 TUN 虚拟网卡，系统会先把域名解析成 IP 地址再发包，代理软件收到 IP 后还要额外还原出域名才能匹配规则；一旦 DNS（域名解析）没配好，就容易出现分流不准的情况。

  2. 两个接管开关同时开不会重复代理：读取系统设置的软件（如浏览器）直接走系统代理；不读系统设置的软件（如终端、桌面客户端）走 TUN 虚拟网卡，互不影响。

第二组：分流模式（决定往哪走）

  • 规则：按名单分流，规则可配置。一般国内地址走本地宽带（直连），海外地址走节点。
  • 全局：除了本机和局域网地址，所有进入代理软件的流量都走选定的节点。
  • 直连：所有进入代理软件的流量都不走节点，直接走本地宽带。

**开了 TUN，就是开了全局吗？所有流量都会走代理吗?

**不会！TUN 只负责把所有软件的流量接管进代理软件；接管之后，软件流量往哪儿走依旧由分流模式决定。选「全局」，所有流量都走代理节点，选「规则」，则根据你定的规则来（一般会设置国内流量依然走直连，海外流量才走节点）。

对号入座：举 3 个例子

1. 刷微信、淘宝、B 站等国内软件

  • 选「规则」：直接走本地宽带，速度最快，不消耗机场套餐流量。
  • 选「全局」：国内请求也会先发到海外节点，再转回国内服务器。是否变慢取决于节点线路和软件配置，但大多数普通节点延迟会明显增加，而且国内网页和视频也会消耗机场流量。

2. 用浏览器看 X、YouTube

浏览器会自动读取系统代理，接管开关打开系统代理、分流模式选 规则 即可正常访问。如果个别海外网页打不开，先检查当前节点是否可用、该域名是否包含在分流规则里，不需要长期切到全局。

3. 用 Claude、Codex、Cursor 等 AI 客户端

这类桌面客户端和命令行工具默认不读取系统代理。如果接管开关只开「系统代理」，即使分流模式选了「全局」，它们的网络请求也没有进入代理软件，依然会连接超时。

正确做法是在接管开关里打开 TUN 模式 接管这些软件的流量，分流模式保持 规则，并确认这些 AI 工具的域名或进程在规则里被分配到代理节点。这样 AI 客户端能正常连接，国内软件继续直连。

我实操后的最佳实践

如果你平时既要访问国内和海外网页，又要使用 Claude、ChatGPT、Codex 等 AI 工具或运营海外账号，可以按我目前在用的方式配置：

基础设置：接管开关同时开启 系统代理 和 TUN 模式，分流模式选 规则。

流量按规则分成三路：

  1. 国内流量 → 本地直连：直接走本地宽带，不消耗机场套餐流量。
  2. 常规海外流量 → 机场节点：日常查资料、看视频直接走机场节点，保证连接速度。
  3. AI 工具 / 海外账号 → 机场节点 + 静态住宅 IP（链式代理）：在普通机场节点后面再串一条静态住宅 IP（长期固定、不会随重连或换节点改变的公网地址）。

静态 IP 的介绍和配置请看这篇：

之所以不把所有海外流量都走静态住宅 IP，是因为平时购买的静态住宅 IP 通常有带宽上限。比如我实测手上这条洛杉矶静态 IP，下载最快 18.3 Mbps、上传 19.3 Mbps（约 20 Mbps 上下）。这个带宽用来跑 Claude、Codex 对话和写代码足够，但用来刷高清视频或下载大文件就会受限，所以日常海外网页和视频直接走普通机场节点，只把需要固定身份的应用分流到静态 IP。

给 Agent 的配置提示词

把下面这段提示词发给能操作你电脑的 Agent（建议使用 Codex），将方括号里的客户端名称替换成你实际使用的软件：

请帮我检查并配置本机的代理客户端，当前使用的是 [猫熊网络客户端 / Clash Verge / Surge]。

  1. 先备份：修改前先记录当前的接管开关、分流模式和配置文件路径，保留一份可以切回的版本。

  2. 开启推荐配置：接管开关同时开启「系统代理」和「TUN 模式」，分流模式设为「规则」。确保使用 Claude Code、Codex 这类桌面客户端或终端工具时，流量都通过 TUN 模式接管并按规则走代理。如果发现 TUN 接管了本地局域网或公司内网网段，保留或补上常见的内网绕过地址（Bypass），不要影响本地服务访问。需要输入管理员密码或弹窗授权时，叫我接手，处理完继续。

  3. 配完验收：分别测试国内网站直连、浏览器访问海外网页，以及 Claude Code / Codex 这类客户端或终端（如 curl）通过 TUN 模式访问海外接口是否正常。向我报告改了哪些设置、测试结果分别是什么；如果改动导致原有网络不可用且当场修不好，先切回原配置再告诉我。
