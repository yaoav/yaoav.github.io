一、这场直播是怎么搭起来的

  1. 问：这套直播是怎么做的？（3:45）
    答：Matt 说直播跑在他 MacBook 上的 Meld Studio 里。Meld 和 OBS 一类工具类似，用来配置画面布局，再推到 X。他点名感谢了 Meld Studio 团队和 X 直播团队。

叠加层是 HTML。他当时给大家看的，是一个载入网站的浏览器叠加层，用了 tldraw，并点名感谢 Steve。姓名条、模糊和淡入淡出都是 HTML。Matt 说自己用本地机器上的 Grok Build 终端，把这些叠加层写成代码，才能在浏览器视图和带姓名条的播客画面之间切换。这是他描述自己的制作方式，现场没有把它说成产品改名。

他还做了和录音时类似的音频处理，把两支麦克风的声音先做一层降噪，再送出去。聊天审核这边，他们先用开源的 Fossabot，Matt 说它基本上是正则；他又加了一个简单的 Bun 服务器，在聊天上再跑一个模型，用来补一些边角情况。语音识别把这个模型名听成 Jev 或 JEV，把握不高，这里不加猜测。

Matt 说这套流程几乎全是代码，加一些巧妙的配置。他说也许会写一篇文章。Eric 建议他做一个 Grok Bot，专门用来搭直播。Matt 说完全可以，也许会做成模板分享出去。这是打算，不是已经发出的模板。

二、旅行、购物和更丰富的卡片

  1. 问：Grok Bot 最近上了什么？（6:28）

答：Eric 说最近上了不少东西，他先点出旅行。他说 Grok Bot 现在能帮你找和预订机票、酒店，也能处理退款这类事。他在现场演示了在移动端查找从 SFO 到 LAX 的直飞航班，bot 出去找，再用行动卡片把推荐结果呈给用户。酒店也是同一套。

他觉得，把聊天界面和更丰富的卡片结合起来很合适，而且他们现在能比较快、也比较稳定地做出这类能力。购物是几周前上的，现在又加上了机票和酒店。他欢迎大家提出其他更适合用丰富卡片、而不是纯文字的场景。

三、电话

  1. 问：你们自己怎么用电话功能？（10:18）

答：Matt 问 Eric 用得多不多。Eric 说用过一点。他每年大概有两次要给保险公司打电话，要走语音菜单、排队，是他一年里最难受的两天。他说自己今年还没做到那一步，但已经用它打过别的电话。两人都提到，可以看实时转写，bot 能替你走语音菜单，结束后再把电话交回给你，你从断点继续。

Matt 说自己也只用过一点，还想拿它给父母打恶作剧电话，不过还没打，想等到假期。也有人私信他说，用这个给妻子打电话，对方会吓一跳。

Eric 注意到，电话开头会说自己是 Eric 或 Matt 的虚拟助理，是代表这个人来打电话。他认为，以前这类「代表别人打电话」通常要由人来做；对方要是越来越常接到这样的电话，也许会倒逼企业改接听方式，或开放别的联系渠道。Matt 则说，从客服角度看，一个每次都能听清、不说错的 AI，也许比跟人通话更清楚；像「请告诉我邮箱、随后再发一封重要邮件」这类容易听错的环节，在 agent 对人、或 agent 对 agent 时，可能会少一些。

两人还聊到，如果让 bot 去打给另一个 AI bot，会怎样。后面有一段提到用法语给同事祝生日，识别质量较差，只能听出他们试过、效果不太好，细节待核。

四、Grok Bot 1.0 里的会议

  1. 问：1.0 里的会议功能能做什么？（13:17）

Matt 补充说，他常提醒别人，这个 bot 会进会议聊天区，而且能在里面做事，这和一般的通话录音工具或会议机器人不一样。比如在公司会议里，你可以对它说，去 Notion 里查上周和 Eric 一对一谈了什么，再带回会场。

五、本地 MCP、Tailscale 和 webhook

  1. 问：有没有本地 bot 应用、MCP 连接，以及外部应用怎么把信息推回 bot？（15:13）

答：聊天区提了一串需求，Matt 说要拆开看。他先说，你可以在家庭网络上跑本地 MCP 服务器，再用他们的 Tailscale 连接去访问。比如家里有一台 Mac mini 在跑 MCP，你装好 Tailscale、建好 tailnet，再在 Grok Bot 里接上 Tailscale MCP，就能连到那台本地服务器。

至于外部应用怎么把信息送回 bot，他建议用 Grok Bot 里的 webhook。他对着 bot 说「给这个 bot 建一个 webhook」，就会得到一个网址，按标准 webhook 输出去接就行。也可以直接让 bot 帮你完成这套设置，再把地址填进外部应用。Eric 说，webhook 知道的人不多，他正在用它给自己做原型，想把工作委派进 Grok Bot。他认为 webhook 很适合先试各种以后可能做进产品的东西，例如从你所在的地方发送信息、唤醒 bot。他举的例子是一个待办应用集成。他们也请正在用 webhook 的人反馈使用情况和改进建议。

六、工具权限和 Auto-review

  1. 问：安装 connector 或应用之后，能控制每个工具怎么触发吗？（17:42）

答：Eric 说可以。现在安装会暴露一批工具的 connector 或应用时，你可以控制这些工具怎么触发。位置在 connector 的权限里，按工具配置。每个工具可以设为始终允许、走 Auto-review、需要批准，或直接屏蔽。

他接着把重点放到 Auto-review。几周前他们在纽约办了 Compile，工程师 David Gomes 做了一次关于如何实现 Auto-review 的讲解，他是这个项目的主要贡献者。Eric 是这样说明的。当 Grok Bot 或 Cursor 想跑某些工具时，Auto-review 会判断是自动执行，还是停下来征求你的批准或拒绝，并据此在以后类似情形里学到该怎么做。他举的例子是防止模型在磁盘上执行 rm -rf。他说模型本来也可能不会这么做，但如果发生了，Auto-review 会拦下来。他认为这件事很难做，却会在 agent 工具的体验里占很重的位置，那就是系统是继续自己跑，还是必须把人留在回路里。

官方介绍见：

  1. 问：Auto-review 用起来怎么样？（19:37）

答：Matt 说体验很好，好到你几乎会忘了它还在。他有时以为自己处在始终允许的模式，结果它会出来问：你确定要跑这个吗？他觉得好用的软件就该这样，理想情况是你甚至意识不到这个工具在运行，却能拦住 rm -rf 这类操作。

原话：「I think that’s what delightful software feels like. It’s like, oh, ideally you don’t even know that the tool is running.」

中文翻译，他觉得好用的软件就该这样，理想情况是你甚至意识不到这个工具在运行。

Eric 补充说，你会觉得控制权还在自己手里，因为它能帮你理解自己通常想做什么样的决定。

  1. 问：什么时候能看到 Grok Bot 的 Neuralink 演示？（21:13）

八、Cursor Projects

  1. 问：你现在用 Cursor Projects 吗？（22:08）

答：他们先读了 David Gomes 前几天的一条帖子。帖子里的大致意思是，Cursor Projects 已经非常强，但在他看来大概只到理想状态的 40%，以后还会再走完剩下的部分；建议现在就开始用，相比 agent 聊天是一次很大的提升，同时也请再给他们一点时间打磨细节。关于 40% 和仍需打磨的说法，都是他们当场读出的原帖判断，不是现场新做的基准测试。

Eric 说自己现在只用 Cursor Projects。在他看来，以前大家习惯为每一小块工作新开一个聊天，还要判断自己在分支、worktree 还是 cloud agent 里；项目更像一条持续的意识流，你把任务交给一个「幕僚长」，再由它为你开出独立的线程。每次要做项目时，他会先把开发环境配好，让 agent 能完成该做的事，然后开始列出任务。

Matt 说自己后来也转到主要用 cloud agents，现在很难回去。他在用项目搭自己的「软件工厂」，让 agent 在验证通过后继续往前走，读使用过程中的遥测数据，再改进。他主要把它用在小原型、个人项目和一些游戏上。他也说，要把上下文配好，需要花一点时间和功夫，你得适度去引导；一旦上手，就很难回到旧办法。他还说自己很喜欢在 Cursor Projects 里用 poteto mode。

九、聊天区里问到的具体能力

  1. 问：没有手机信号时，能在卫星模式下给 bot 发短信吗？（26:36）

答：聊天区的 James 说，他把 bot 接到一个号码上，在完全没服务、只能走卫星模式时仍能给它发短信，等于一直在线。Matt 的猜测是，那个号码大概会触发 webhook 一类的东西。他说这是很聪明的用法，也随口建议不如上 Starlink。他很想知道，James 能当时收到回复，还是要等到重新有连接？现场没有听到 James 的补充。这是观众的用法，加上 Matt 的推测，不是一份官方卫星短信说明书。

  1. 问：同一个 bot 用太久，会不会变差？（27:36）

答：有人用几个 bot 去跑和录产品演示，并反馈，同一个 bot 用太久会出现退化。Matt 把它归到上下文管理，说这是一直存在的问题。他给的办法很直接，既然 bot 有自己的电脑，可以直接让它帮你做出来并录下来；也可以交给 Cursor Cloud Agents 去做。他当天还把一个项目的演示录像发给 Eric，而不是甩代码或截图，那些录像就是 Cursor agent 给他的。Eric 也觉得，有时发一段视频比发链接更清楚，agent 可以按不同使用路径把演示走一遍。

  1. 问：Slack 里的 bot，能不能去找一个不在 Slack 里的私有 bot？（28:54）

答：有人问：同事的 bot 在 Slack 里请他的主 bot 去查一个不在 Slack 里的私有 bot，主 bot 会不会自己转过去，还是只有写了规则才会转。两人先把问题拆清楚，然后当场试了一下。Matt 的结论是，即使是你自己在调用，Slack 里的 bot 也读不到你的其他 bot；他以团队所有者和创建者的身份试过，仍然不行。私有 bot 会保持私有。Matt 还开玩笑说，这样他就没法在 Slack 里对 Eric 的 bot 做提示注入了，而这大概是件好事。

  1. 问：能用 Grok Bot 报税吗？（30:19）

答：聊天区有人说 bot 在帮他报税。Matt 说，在让 AI 报税之前，应该先咨询注册会计师。他对这个用法表示兴趣，但没有把它说成官方支持的报税产品。

  1. 问：有人做了 PII 遮罩，视频里的敏感信息怎么办？（30:56）

答：有人说给自己的 bot 做了 PII mask。Matt 说这句话可以有几种理解。他补充说，bot 和包括 Cursor 在内的视频编辑工具，很擅长把画面上的敏感信息模糊掉。他自己剪视频时，会让工具逐帧看，遇到电话号码一类内容就处理掉。

  1. 问：为什么不用一个 bot 来管这场直播聊天，并挑出有意思的问题？（31:27）

答：聊天区的 Andrew 这样问。两人觉得这个主意很好，当场试了起来。Matt 去找自己的 bot，对 Dr. Eggbot 说，做一个直播观看者。Eric 问是不是用 webhook 把聊天喂进去。Matt 说先看看它能不能直接看聊天，也许直播团队已经做过类似的东西；如果没有，就给直播团队提个功能需求。Eric 说如果再做一个 webhook，把挑出来的问题投到屏幕上，会更方便。这是现场在试，不是已经做好的官方直播插件。

  1. 问：Directory 是什么，怎么发布自己的 bot？（32:40）

答：有人做了看食物照片、返回菜名、菜谱、教程视频和附近餐厅的 bot。Eric 请大家把这些 bot 发布到 Grok Bot Directory，地址是 grok-bot.directory。他说这个目录本周上线，已经有一千多个 bot 提交上来，大家也在上面找到各种用法。Matt 在直播里打开了这个网站，称赞 Eric 做得很出色，并问他是不是在亲自检查每一条。Eric 回答「当然」。Matt 说自己当天早些时候也提交过一个，还提到 Dr. Eggbot 已经出现在目录里。聊天区不能发链接，所以他们请大家自己去这个地址看。

官方介绍见：

  1. 问：有没有闹钟集成，能不能让 bot 早上把人叫醒？（33:56）

答：有人做了私教 bot，早上 4 点叫他起床，并给出训练计划。Matt 说很喜欢这个用法，但不确定这个 bot 是怎么在 4 点把人叫起来的。他不知道现在有没有现成的闹钟集成。他提到，如果有 8 Sleep 这类设备，也许可以接上；他们也在和 8 Sleep 团队沟通，以后「也许会有点东西」。这是接触和可能，不是已经上线的集成。

他接着说，你可以把 Grok Bot 接到家庭网络。只要有智能闹钟或智能设备，就可以用。他自己用 Apple Home，家里有灯，可以对 Grok Bot 说，每天这个时候开灯，用灯把人叫起来。

  1. 问：本地智能家居怎么接，比如 Hue 和 Sonos？（43:34）

答：聊天区的 Craig 说，Hue 是经由他的 Mac 接上的，问 Sonos 时则得到了已有原生 connector 的答复。Matt 建议，做本地网络上的设备时，先看有没有原生 connector，直接问 Grok Bot，或者让它帮你查。聊天区后面还有不少人在讨论 Sonos connector。Eric 说接上之后可以在起床、和灯或传感器联动时放歌，甚至可以在某人来信或某条 Slack 消息到达时放一段固定的声音。这些是用法建议，不是一份设备兼容清单。

  1. 问：教练想把手机或边线摄像机接上，自动剪每个队员的集锦并评价动作，现在能做吗？（44:12）

答：提问的人是 Ava Thompson。Matt 说自己已经在用 Grok Bot 做不少视频剪辑，他认为要先想清楚，这一套反馈要怎样转起来。他说这是可能的，但他会反问：你怎么从录像里认出某个队员？这会涉及到分割，难度不低。如果录像带声音，可以接入音频，让 Grok Bot 用 xAI 的一些接口做转写；有人在画面里提到某个队员，就有机会对上。他举的例子是，你站在摄像机后面录的时候直接说「这是 22 号，是 Eric」，Grok Bot 会做得比较好。所以关键是怎样把可识别的信息放进视频里。视频剪辑他想另找时间再展开讲。

  1. 问：有没有比常规 X 数据导出更好的搬数据办法？（45:45）

答：聊天区有人这样问。两人当时没有立刻给出一份现成方案。Matt 提到，X 的 API 在几周或几个月前重新上线了，现在用起来很愉快。如果有反馈、改进想法或建议，可以发给他们，他们会转给相关团队。

  1. 问：能把别的 AI 助手里的记忆导进 Grok Bot 吗？（46:21）

答：Eric 说可以，入口在设置页。点开始导入后，如果你在用另一个 AI 助手，可以把那里的记忆导入 Grok Bot，让它跟上你的背景。聊天区随后有人说，已经把以前的 Grok 对话导进了 Grok。

  1. 问：能用普通的 Grok 聊天，或通过 X，来控制 Grok Bot 吗？（51:20）

答：有人说自己才知道这件事。Matt 说可以，你可以通过 Grok 或 X 控制 Grok Bot，他们已经做了一些集成。

  1. 问：现在最受欢迎的模板是什么？（51:29）

答：有人问前三个模板。他们欢迎大家分享，但这场直播聊天不能发链接，所以请大家报名字。Eric 说，Grok Bot Directory 上现在最受欢迎的是 live bot map，它会做成一幅动画地图，显示你的各个 bot 如何互相配合。Matt 觉得可以先试试，并说以后如果把类似能力直接做进产品，也许会不错。这是他觉得值得做的想法，不是已经排期的功能。

  1. 问：日历和跨工具同步，怎样用才最值？（52:04）

答：有人说自己现在几乎不再直接打开 Google Calendar，只跟 bot 说，由它处理。Matt 同意，并给出他常对别人说的起步办法，想马上用出价值，就装上 Grok Bot，接上日历、邮箱、你用的笔记应用（比如 Notion），再加上你和别人沟通的地方，比如 Slack 或 X。Eric 说自己也常记错时间、漏事情，现在可以让 Grok Bot 去看邮件、改日历。Matt 还说，做产品发布时计划常变，如果日历、Notion、Slack 里的信息已经过时，你可以直接对 Grok Bot 说「全部帮我改好」。它会去更新 Notion 文档，并让日历保持同步。

Eric 补充，Cursor 里也有类似的订阅，你可以让它盯着某条 Slack 线程，或订阅 GitHub 上某个 PR 的评论，再据此更新 PR。Grok Bot 也可以做同类事，比如看着一条 Slack 线程里老板对演示文稿的反馈，再去改那份演示。

  1. 问：会不会做付费的 Grok Bot 模板市场？（53:41）

答：Matt 说不会，而且他们大概永远不会做。

原话：「No, and we will probably never do that.」

中文翻译，不会，而且我们大概永远不会做那件事。

他估计社区里也许已经有人在做 Grok Bot 模板，其中也包括付费的。他觉得这对创作者经济是个有意思的方向，也就是在 Grok Bot 之外再长出一层平台，但没有把它说成官方计划。

  1. 问：Obsidian 仓库有什么建议？（54:21）

答：他们先对了一下这件事是不是已经公开。Eric 说 Obsidian 的 X 账号最近发过相关内容，确认是公开的。他们支持 Obsidian，插件已经上线，在 Grok Bot 里搜索即可。

  1. 问：语音聊天开始时，Grok Bot 能不能先打个招呼？（54:43）

答：这是给 Parker 的反馈。现场把它记下了，并说这样可能会更好。他们没有宣布已经改好，或给出上线时间。

  1. 问：会和 News Research 合作吗？（55:57）

答：他们说自己很喜欢 News Research，也提到 News Research 在使用 Grok 的模型，并表示一直乐于合作。这是态度，不是一份已经公布的合作细节。

  1. 问：iPhone 的动作按钮能调 Grok Bot 吗？（56:12）

答：Matt 说现在就可以，可以把 Grok Bot 设成动作按钮上的一项操作。他以前发过相关帖子，现场没有来得及把那条帖放到屏幕上。

官方介绍见：

https://x.com/bot/status/2112252507762368684

更详细的介绍见：

https://x.com/mattyp/status/2112891221576389063

  1. 问：两个账号时，是不是只有当前选中的账号能收到通知？（56:36）

答：有人说自己有一个个人账号、一个创业公司账号，却只能在当前选中的账号上收到通知。Matt 把它当成有效反馈收下了。现场没有说已经在修，也没有给修复时间。

  1. 问：有没有 Android Auto，或 Apple CarPlay？（56:53）

答：有人先点了 Android 支持，接着问 Android Auto。Matt 说 Android Auto 和 Apple CarPlay 都是大家经常提到的需求，他们听到了。现场没有给出时间表，也没有说已经在做或即将上线。

  1. 问：会不会出 Apple TV 上的 Grok？（57:35）

答：有人提出 Grok for Apple TV。Matt 觉得会很有意思。他接着说的是另一件事。他发现 Apple TV 可以当 Tailscale 的 exit node。只要有一台 Apple TV 在某个网络上，你就可以经 Tailscale 连到那个网络，也就意味着可以经 Grok Bot 连过去。这是网络接入办法，不是在宣布 Apple TV 客户端。

  1. 问：会不会做 Apple Watch 上的 Grok Bot？（58:08）

答：Matt 说他经常听到这个需求。接着聊天区到了下一题，现场没有再补充进度或时间表。

  1. 问：能不能做一个跟在主管身边、随着项目走的商务 bot？（58:14）

答：有人希望有一个商务 Grok Bot 账号，把一个 agent 交给主管，让它了解对方，并在项目中一直带着。Matt 认为，如果是团队或企业账号，现在大概就可以用团队 bot 做类似的事。由创建者管理这个团队 bot 记住的内容，把它发给主管，让对方正常使用，bot 会从互动里学习。

Eric 则对中小企业主说，他很想看到 Grok Bot 能在多大程度上像一名员工那样被委派工作、能从你的待办里拿走多少事。用法可以包括开通新账号、写岗位说明、对接客户，或和内部同事协作。如果有这样的场景，可以私信他。他愿意提供一些 credits，让人去试，并看看短板在哪里。

  1. 问：企业账号有零数据保留吗？（59:45）

答：他们的回答是相信有。现场的说法是，企业账号是零数据保留，也可以随时把这项设置关掉，建议去自己的设置里查看。这是他们当场的表述，说的是相信有，不是一份单独核对过的条款说明。

  1. 问：这种直播多久做一次？（1:01:30）

答：这是收尾前的最后一个问题。他们说目前是周五做，也在争取把周五固定下来，晚上进来回答一些问题，并希望以后更稳定。收尾时，他们还向最近身体不适、现在好转的 Bacon 致谢。随后互相道别，祝大家周末愉快。

十、聊天区里大家分享的用法

下面这些是观众或他们自己提到的用法，不是新功能发布。

有人用 bot 整理音乐库，靠音频指纹识别未知文件的元数据，再对照 Discogs 补全信息，并拉封面。Matt 说自己小时候曾花大量时间给 MP3 补专辑信息，没有 agent 时这件事非常耗时。Eric 现在主要用 Spotify；他录视频时文件夹也常很乱，Grok Bot 能帮上忙。他们还提到，去年就有音乐制作人用各种 AI 工具整理曲库。

有人把 Mac mini 当服务器，经 Tailscale 和 webhook 托管要测试的应用，并说这能省 token。两人都很喜欢这种 Mac mini 用法。还有人用 Grok Bot 管理 T3 Code 里的多个项目，并决定每个线程用哪一个模型。Matt 说，Grok Bot 很适合和 Cursor 或其他工具一起用，因为它容易扩展。

Matt 自己把训练逻辑做进了 Grok Bot。他主要练力量举，也做一些健美，训练里混用周期化和线性递增。bot 能调用与进阶有关的工具，每天给出计划，并维持训练节奏。Grok Bot 把当日训练发给他，他再用语音记录实际完成的组数和重量。数据放在 GitHub 上的 JSON 文件里，作为持续账本。他和 Eric 也谈了灯的摆法，以及他为「What’s new」视频准备的打印提词单，他会看 changelog、网上的信息和一点代码，按固定格式打出来。眼下主要用在这类视频上，他还想再做一些离线工作流，包括日记。

聊天区还有这些用法。有人每天给夫妻发几个关于当天的问题，再视情况通知祖父母，并在年底做成一本纪念品书；定时查看理发店周六空位并提前预约；让 bot 盯着热门餐厅的取消位，有空位就提醒，Matt 自己前几周这样订到过位子；用 bot 看食物热量和宏量，拍照或口述比手工录入容易；把杂货小票发到 bot 的邮箱，汇总开支、盯预算；用 Home Assistant 控制全屋自动化；在车上让 bot 点 Jimmy John’s 或 Chick-fil-A，并使用积分；用 Yahoo Fantasy 的数据更新 Discord；一个短租社区在互相交流怎样用 Grok Bot；把会议名片拍照后交给 bot，写入 CRM；看着 CRM 里的问题和解决方案、再配上视频和图片去做社媒。Eric 还说，有同事和他聊过小企业怎么用 Grok Bot。

Matt 在快结束时说，偶尔看这些直播聊天，会觉得应该把当天出现的用法整理发出来。他记得上一场也攒过一些，其中有人在会上拍下别人递来的名片，交给 Grok Bot 录入 CRM。他们还提起今夏的 Galaxy 直播，但那一小段识别质量很差，这里不展开。
