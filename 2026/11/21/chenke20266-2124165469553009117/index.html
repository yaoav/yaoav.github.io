GPT 做分析 · Grok 做裁决 · 波动与仓位交给本地规则 · 零显卡

依据一段真实的开发者对话整理：对方用 GPT + Grok 跑 BTC 5 分钟永续，靠规则而不是靠预测赚钱。
两个模型全走 API，不需要本地显卡。
声明：收益数字是对方自述，我不背书；50 倍杠杆能亏光，这不是理财建议。

1这套系统在做的四件事

任何一套能跑住的交易机器人，骨架上都是这四件事，缺一件就不稳：

一句话总结：它不是靠更聪明的模型，是把「什么时候不下手」写成了规则。

2两个模型的分工

为什么不用第三个模型做波动预警？

ATR 突增、量能异常、布林带宽变化——这三件事几行代码就算完了，花 token 去问模型属于浪费；更麻烦的是，它会变成第三个“跟谁都不一致”的噪音源。

裁决顺序不能乱：

第 2 步和第 3 步不一致就停在原地——这条“不一致就不开”的规则，比任何模型都值钱。

三、API 与凭证：三把钥匙怎么管

要把这套东西跑起来，必须提供三类凭证。它们风险完全不同，必须分开管。

3.1 三把钥匙

钥匙给谁用能干什么泄露的后果GPT API Key分析层调模型刷爆额度Grok（xAI）Key裁决层调模型刷爆额度交易所 API Key执行层下单、撤单能拿走你的钱

前两把是“调用凭证”，第三把是“资产凭证”。真正的风险只在第三把。

3.2 交易所必须拆成两把

  1. TRADE_KEY 关闭提现权限——这是底线，不是建议。
  2. 绑定 IP 白名单——换网络就失效，反而是保护。
  3. 两把 key 不能相同——代码里要做断言，相同就拒绝启动。
  4. 定期轮换——30–90 天换一次，旧的立即撤销。

3.3 钥匙放在哪里

放本机 .env 文件，只读环境变量；不进代码、不进 prompt、不进 Git、不发聊天。

配套的三条代码级保护：

3.4 必须留的兜底

  • 额度上限：OpenAI / xAI 后台各设月度上限。key 泄露最坏是刷爆额度，不该是刷爆银行卡。
  • 模型失效即停：模型超时或报错时，程序只能平仓，不能开仓。Grok 国内链路不稳，这条是保命的。
  • 只读验证：拿 READ_KEY 去调一次下单接口，必须报权限错误才说明你真分开了。

想省心：先用 LIVE=false 干跑 30 笔。这一阶段只需要两把模型 key + 一把只读 key，出不了事。

四、BTC 5m 完整策略

4.1 周期与节奏

4.2 指标池（本地算，不进 prompt）

只把 12 个数字 + 持仓摘要喂给模型，不要把 200 根 K 线塞进去——这是省钱第一原则。

4.3 开仓条件（做空版，做多镜像）

全部满足才开：

  1. 15m 向下：收盘 < EMA20，且 EMA20 < EMA60
  2. 5m 结构向下：最近 3 根形成更低的高点
  3. GPT：p_up ≤ 0.38
  4. 规则层：risk_level ≤ 中
  5. 不追空：价格离布林下轨 > 0.3×ATR
  6. Grok 同意：输出 OPEN + SHORT
  7. 冷却：距上一笔平仓 ≥ 3 根 5m

4.4 仓位：50 倍只是保证金效率

例：权益 500 U → 风险 6 U → 名义约 800 U → 占用约 16 U（3.2%）。

杠杆放大的是资金效率；止损距离才决定你亏多少。

4.5 出场：四个出口，没有“再等等”

出口条件动作止盈2.5×ATR 目标，或 15m 趋势反转全平移动止损每根 5m 收盘后向有利方向移动，保持距现价 75bp只移不撤认错开仓后 2 根 5m，浮盈 < 0.3×ATR立即平**超时**持仓 > 24 根 5m（2 小时）无条件平

4.6 日级风控

  • 日目标 +15% → 冻结新开仓（只允许平仓）
  • 日止损 −6% → 全天停手
  • 连续 3 笔认错 → 冷却 30 分钟
  • 波动预警“高” → 不开新仓，存量仓位止损收紧到 40bp

五、参数表（一页抄完）

六、认错机制为什么省钱

一位跑这套的开发者说过一笔账：他手工硬喊了两单，机器人马上给平了，只亏 3 块钱手续费。

  • 手工硬开 → 方向不对 → 2 根 5m 没走出预期 → 认错平仓
  • 损失 = 手续费 3 U
  • 若“再等等”：按 ATR 拖到止损亏 6–9 U，拖到趋势走坏可能 15 U+

认错不是认输，是把“不确定”定价成手续费。 前提是开仓那一刻就定义好“什么叫走对了”：开仓后 2 根 5m 内浮盈 ≥ 0.3×ATR。

七、两个 API 的 token 成本

三条省钱法，按效果排：

  1. 改成 K 线收盘触发 → 直接省 80%。
  2. 只喂摘要：12 个指标数字 + 持仓，不喂原始 K 线。
  3. 分级调用：常规扫描只调 GPT；只有快触发开仓/认错时才调 Grok。

波动预警用本地公式算，0 token——这就是两个 API 够用的原因。

八、代码骨架

执行层沿用四件套：单一入口 → 只读数据 → 受控执行 → 风控闸门，钱只有一条路能出去。

九、上线前检查表

  1. 回测 ≥ 6 个月 5m 数据，含手续费与滑点
  2. 纸上跑 30 笔，记录每笔 MFE / MAE
  3. 认错率 25–40%（低于 15% 说明阈值太松）
  4. 手续费占毛利 < 15%
  5. 日目标、日止损都真实触发过一次
  6. 断网或模型超时后能恢复到“无仓位”
  7. 50 倍下单笔保证金占用 < 8% 权益
  8. 只读 key 下单必须失败（实测）

十、边界

  • 不预测未来：这类系统里模型的方向准确率通常在 30–40%，比抛硬币好不了多少；赚钱靠“错得快、对的时候拿住”。
  • 50 倍会爆仓：跳空、插针、交易所故障都可能归零。
  • API 会挂：Grok 国内链路不稳。模型不可用时只能平仓，不能开仓。
  • 参数会过期：波动率环境一变，同样的参数就失效。

一句话

两个模型足够，第三个用规则代替。让这套系统成立的，是三条规则：

不一致就不开 · 每根 K 线只移不撤止损 · 两根 K 线没走对就认错。
