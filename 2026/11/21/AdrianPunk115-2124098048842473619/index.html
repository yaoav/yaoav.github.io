零基础用Fable5.2做视频：从代码原理到电影感拆解，附完整提示词

发表于2026-11-21|行业观察
|浏览量:

本文转载自 X 博主 @AdrianPunk115（Adrian Punk） 的长文，原文链接，版权归原作者所有。

Fable 5.2 上市一段时间了，𝕏 上的时间线涌现出了越来越多用代码做的视频。比起刚开始 Opus 5.5 出来那会儿，大家还停留在做一些酷炫的网页动效、像素小动画，到了 Fable 5.2 这波，时间线上已经能刷到越来越多连贯、有光影变化，甚至带点电影感的叙事小短片了。

每天刷推啧啧赞叹之余，我也开始琢磨：这玩意儿到底是怎么实现的？

既然底层逻辑都是让大模型写代码来出片，我自己也第一时间用 Claude Code 折腾了起来。结果一上手我就踩了个大坑：别人做出来的是电影感短片，我捣鼓半天导出来的，简直就是一份会自动翻页的高级 PPT。

同样是让 AI 写代码，差距到底出在哪？为了搞明白这件事，我把这几天刷到的热门案例全扒了一遍，顺带把前端图形库、三维渲染和音视频合成的原理都摸了一遍。今天这篇教程，就把我研究出来的这套方法论和完整提示词分享给你——哪怕你一行代码没写过，看完也能直接指挥 Claude Code 帮你出片。

一、Claude Code 写代码做视频，和 Sora、Seedance 有什么区别？

先解决一个大家最常问的问题：用 Claude Code 做视频，和 Seedance、Sora 这些视频模型到底有啥不一样？

同样输入一段提示词去描述一个场景，这两条路干的完全是两码事。

视频模型：靠“猜像素”预测画面

Seedance 这类视频模型，是根据海量训练数据里学到的物理规律和视觉特征，直接去“预测”下一秒每个像素该长什么样。你让它画一个人开灯，不用告诉它灯罩的坐标和光线角度，它自己就能脑补出来。

这特别适合拍写实人物、复杂自然风景。但做长视频时，有个绕不开的痛点：穿帮了怎么修？前后镜头都已经满意了，偏偏中间某一秒道具变形，或者人物动作接不上。

Seedance 2.5 已经支持片段修改，但底层依然是局部重新“抽卡”。 对于缺少这类编辑能力的模型，往往只能改提示词全部重抽；或者保留满意的首尾，靠首尾帧约束把中间那段重新抽出来，最后再用传统剪辑软件拼起来。

Claude Code 路线：在电脑里搭个“数字片场”

Claude Code 本身是个纯文本编程工具，它不会直接给你吐出一个 .mp4 文件。它干的活，更像是在你的电脑上充当“编剧 + 美术 + 摄影师 + 剪辑师”。

以网页动画这条路线为例，整个流程大概长这样（Blender 等三维软件则有自己独立的渲染方式）：

  1. 写剧本与布景：它在你本地新建一个代码项目，用数学坐标精确定义画面里有什么（比如一张桌子、三张卡片、一盏灯），并规定好“第几秒谁动起来”。
  2. 后台架摄影机：代码写好后，Claude Code 会在后台启动一个无头浏览器（比如 Playwright）——你可以把它当成一个没有显示器的隐形 Chrome，默默打开网页按时间轴播放动画。
  3. 高速连拍截图：无头浏览器一边播，一边像高速相机一样，按每秒 30 张或 60 张（30fps / 60fps）的速度，把每一瞬间的画面截成高清 PNG 图片存进文件夹。10 秒视频就是 300 张剧照。
  4. 剪辑压制出片：最后，Claude Code 调用命令行神器 FFmpeg，把这几百张截图按顺序压成 MP4，再把音效混进去，交出一份成片。

这两条路其实还能混着走：用视频模型生成一段真人特写镜头，再交给 Claude Code 用代码叠加上精准的数据图表和品牌包装，两边的好处全占。

二、从“PPT 感”教程，到真正能看的演示视频

弄懂区别后，回到咱们的重点：怎么用 Claude Code 做出不像 PPT 的视频？

我刚上手那会儿，想把自己的长文做成教程视频，里面讲到了各种视频运镜。当时我只会跟 AI 说：“根据教程里提到的运镜，模拟演示一下。”结果跑出来的成品让我哭笑不得——全是一张张知识卡片淡入、淡出。讲到“镜头推进”，弹出一张写着“推进”的卡片；讲到“环绕”，再换一张卡片。知识点是全了，可镜头到底怎么动，观众还是两眼一抹黑。

后来我才反应过来，问题出在我自己的表达上。脑子里有画面，但嘴上说不出专业词，也不知道该用什么技术去实现，只会笼统地说“模拟演示”，AI 自然只能按最省事的“翻页卡片”来交差。

随着我把要求越说越具体，视频才慢慢有了我想要的样子，也逐渐沉淀出了固定风格（这时候就可以顺手写一份自己的 design.md，让 AI 以后都按这套审美来）。当然，模型本身的能力差距也很明显。拿我自己的体验来说，同一篇内容，交给 Codex 和在 Claude Code 里用 Opus 5.5 做，出来的观感差了一大截。跟 Claude 沟通，我更容易把“感觉”说清楚，它给的排版、配色和动效也更合我胃口。

这里面其实藏着三个拉开差距的环节：

  • 理解需求：同样一句“做得更有画面感”，有的模型只理解为加个炫酷转场，有的则能展开成具体的场景、动作和镜头调度。
  • 补齐细节：字号、留白、配色、构图、动作快慢，这些你没明说的东西，全靠模型自己做审美判断。
  • 落地与迭代：能不能把想法稳稳写成代码，并且在看完预览后发现穿帮、继续微调。

就在我刚摆脱 PPT 感、开始用 Opus 5.5 尝试各种特效的时候，Fable 5.2 出来了。我一刷时间线，好家伙，大家居然已经开始用代码做电影级别的动画短片了。

同样是让 AI 写代码，那些画面到底是怎么拼出来的？为了以后能精准指挥 AI，我把提示词里最常出现的 22 个技术名词全理了一遍。你完全不用先学写代码，只要知道“想做什么效果时，该点谁的名”就够了。

三、小白也能看懂的技术词典：想做啥效果，该点谁的名？

下面这 22 个词经常在教程和提示词里扎堆出现，看着唬人，其实分工特别明确。我按用途把它们分成了四组，你按需查阅就行。

第一组：搭架子、做排版（适合文字、卡片和界面动效）

1. HTML：告诉电脑，画面里要放什么

做一张知识卡片，你得先告诉电脑：上面放标题，下面放解释，旁边放图片。HTML 就是干这个的，它负责把内容摆出来、分好组。至于文字多大、卡片什么颜色，那是 CSS 的活。

2. CSS：决定这些东西长什么样、怎么动

同样一句标题，换个字体、颜色和行距，高级感立马不一样。CSS 管的就是外观和排版，顺带还能做平移、缩放、旋转、淡入淡出。我最初做的卡片动效基本靠它。它很适合精致的文字和界面动画，但要搭一个有灯光、人物和运镜的 3D 房间，就得换工具了。

3. JavaScript（JS）：告诉画面，接下来发生什么

HTML 放内容，CSS 管颜值，JavaScript 则负责按时间算动作：比如到了第 3 秒，卡片该移到哪，摄像机该往前走几步。它也是后面 Three.js 等工具的底层语言。

4. React：同一种卡片，不用重复搭十遍

如果视频里有十张长得一样的知识卡片，只是字不一样，React 可以先做一个“卡片模板”（程序员叫组件），再往里填不同内容。它擅长管理复杂界面，但不会自动帮你设计镜头。后面要讲的 Remotion 就是基于它来编排视频的。

5. GSAP：把一堆动作排好先后顺序

画面里经常要同时发生好几件事：卡片先移开，图片再出现，箭头最后指向重点。GSAP 就是专门管动作排期和节奏的动画库。它能轻松做出“先快后慢”的自然停顿，比死板的匀速滑动顺眼得多。

6. SVG：画怎么放大都不糊的图标和箭头

普通图片是由一个个像素点拼的，放大就糊；SVG 记录的是“这里画个圆、那里拉条曲线”，所以特别适合画示意图、流程图和镜头轨迹。不过导出成视频后，清晰度还是受视频分辨率限制，线条太细一样会看不清。

第二组：画平面、玩创意（适合粒子、线条和手绘感）

7. Canvas：网页里的一块空白画布

Canvas 就是网页里划出来专门用来画画的区域。星空、波浪、像素小人，甚至 3D 场景，最后都要画在这块布上。注意它的实际像素尺寸要跟导出视频对齐，千万别画一块小画布再硬拉大，不然全糊了。

8. Canvas 2D：在画布上直接画平面图形

它是在 Canvas 上画二维图形的常用方法。每一帧重新画一遍、稍微挪动一下位置，就成了动画。很适合做粒子、声波、星空、像素画这类效果。

9. p5.js：让代码画画更省心的创意工具

p5.js 把很多绘图和规律随机的方法打包好了，不用每次从头写。特别适合做生长的线条、动态图案和艺术化演示。不过画面好不好看，核心还是看你的配色和构图，不是挂上 p5.js 的名字就自动变高级。

10. p5.brush：给代码加上手绘笔触

它是配合 p5.js 用的笔刷库，能画出彩铅、水彩和纸张露白的感觉。用它做动画有个大坑要注意：笔触必须稳定。如果每一帧都随机重新生成纹理，静态截图看着像手绘，动起来就会像电视雪花一样疯狂闪烁。

第三组：建 3D、打光影（电影感的真正来源）

11. Three.js：在网页里搭一个能转着看的 3D 空间

用它可以在网页里摆地面、墙壁、人物和灯光，再架一台虚拟摄像机。比如做运镜演示时，人物站着不动，让摄像机绕着他转半圈，画面的透视和遮挡会实时变化，观众一眼就能看懂“环绕运镜”是什么意思。想展示精细物体时，直接加载现成的 3D 模型就行，没必要逼着 AI 用几个方块硬拼。

12. WebGL：让浏览器把画图交给显卡干

显卡最擅长同时算大量图形，WebGL 就是浏览器连接显卡的通道。平时用 Three.js，底层默认走的就是 WebGL，你不用自己从头写一套。

13. WebGPU：更新一代的显卡通道

和 WebGL 类似，但设计更新，除了画图还能做更通用的计算。小白知道有这么个东西就行，用不用得看浏览器和设备支持情况，它本身不会让丑模型自动变好看。

14. Shader（着色器）：决定表面材质和特效怎么画

它是在显卡上运行的小程序，能管水面起伏、二次元色块阴影、发光描边、老电视扫描线等等。同一套 3D 模型，换个 Shader，观感天差地别。不过要注意，镜头动起来时，笔触和纹理得跟着物体表面走，不能像贴在屏幕上的玻璃纸一样飘着。

15. Blender：电脑里的专业 3D 摄影棚

它是一套完整的免费三维动画软件，建模、布景、打光、做动作、架机位一条龙全包。比如拍一个房间从黄昏到深夜的变化，你可以一直在同一个房间里调窗外光线、开台灯、换机位，不用像视频模型那样每次换角度都重抽。

16. Python：用代码遥控 Blender 干活

在 Blender 这条路线里，Claude Code 就是靠写 Python 脚本来指挥它的——“窗边放张桌子，桌上放盏灯，第 5 秒亮起来”。Python 负责发号施令，Blender 负责把画面算出来。

17. NumPy：一次算好成千上万个物体怎么动

NumPy 是 Python 里专门批量处理数字的工具。比如画面里有一万颗火星，每颗都有自己的位置、速度和亮度。如果逐个安排，会很麻烦；NumPy 可以把这些数据放在一起，按写好的规则成批计算。

做偏电影感的特效时，它能帮上不少忙：算烟花粒子向四周飞散的轨迹，算海面不同位置的波浪高度，或者给大片草地生成有规律的摆动。算好的数据再交给 Blender 等工具，变成看得见的形状和动画。改一组参数，就能一起调整飞散速度、波浪起伏或摆动幅度。

它负责把大量细节算出来。 最后火星有没有发光、海面反射什么、镜头怎么拍，还要配合材质、灯光和渲染来完成。这也是代码做复杂场景的一种办法：先写出变化规则，再批量生成细节，不用把每个物体逐一摆好。

第四组：排时间、出成片（把画面变成 MP4 的流水线）

18. Manim：把数学公式和推导做成丝滑动画

大名鼎鼎的 3Blue1Brown 同款工具，特别适合讲公式、几何和硬核知识。点沿曲线动、图形变形、公式一步步展开，逻辑清清楚楚。

19. Remotion：用 React 精确控制视频的每一帧

它能让你像写网页一样写视频，把字幕、声音、卡片和 3D 场景统统绑在同一个时间轴上。30fps 的视频，第 3 秒第几帧该干嘛，分毫不差。

20. HyperFrames：把网页画面编排成视频

同样是围绕网页技术做视频编排的工具，能把 HTML 卡片、已有视频和 3D 画布统一塞进时间轴里导出。它负责管同步和组织，画面本身好不好看，还是取决于你往里放了什么内容。

21. Playwright：帮你自动打开网页、逐帧截图

它是个浏览器自动化工具。在网页出片流程里，它负责把动画定格到精确的某一帧、等字体和图片加载完、咔嚓截图、再切下一帧，完全不受你电脑实时播放卡不卡顿的影响。

22. FFmpeg：音视频处理的终极命令行神器

把几百张 PNG 压成 MP4、混入旁白和配乐、裁剪压缩，全靠它收尾。帧率别设错（不然视频会变快放或慢放），码率也别压太狠，免得文字边缘发虚。

记住一个原则：先想清楚你要呈现什么画面，再挑趁手的工具。 千万别在提示词里把这 22 个词全堆上去。

五、拆解真实案例：从画面效果，反推制作方案和提示词

前面认识了工具，现在通过在x看到的优秀案例，来解读一下目前可以实现的某些风格及技术手段。有些案例作者已经给了完整提示词，方便大家拆解学习～

案例 1：悬崖城堡与电影感光影

作者先提供两张参考图，再让 Claude 写 Blender Python，生成城堡、地形、材质和相机。成片通过远景、沿瀑布上升、建筑近景与塔楼环绕，让观众逐渐进入同一个三维空间。参考图负责确定外观，建筑的体积、遮挡和光影仍由三维场景计算。

原提示词没有逐秒规定这七个镜头，而是给了画面目标、制作时间和资源限制，之后继续要求增加细节、压低过亮的灯光。两张参考图未随工程公开；照着尝试时，需要另备建筑与环境参考图。配乐和音效使用外部素材。

案例 2：1930年代老卡通

作者说明，原片由一个 JavaScript 文件和一个 Python 文件制作，没有图片生成器和现成素材，钢琴也由代码合成。这里可以选择 Canvas 2D 来绘制：头和帽子是形状，弯曲四肢是曲线，表情和背景逐帧重画。这是我选用的路线，原帖没有公开具体绘图库，如有不对，欢迎视频大佬批评指正！

要让人物表演，必须把“整个人朝右移动”和“腿怎么迈步”分开控制。脚踩地时暂时停在地面上，身体继续向前；看见小狗后，视线先转过去，再停步、弯腰。胶片划痕和米黄色调只负责外观，这些动作衔接才决定故事能不能成立。

**准备什么：**这个版本不需要图片或人物模型。若要还原自己的角色，可以补充人物与小狗的正面、侧面参考图，让 Claude 重新绘制成可活动的部件；一张完整人物图片直接左右平移，做不出下面这些动作。提示词把原片的相遇情节改编为32秒。

案例 3：毛毡与纸板定格

作者明确说人物、纸板小镇、毛发、毛毡和吹胡须的动作由 Python 驱动 Blender 完成，也说明自己参与了导演和多次提示。

要做出相近效果，可以让 Blender 先生成有体积的玩偶，再在表面添加短纤维曲线，长胡须单独做成可变形的曲线束。纸板要建出厚度，切口处露出夹层；胶带有微弱反光，毛毡则偏哑光。帽子单独建模、单独设置动画，才能在身体落地后继续运动。近景能看见这些材料和动作细节，比给光滑模型套一层“毛毡色”有效。

**准备什么：**建议给一张牛仔全身图、一张面部或毛毡细节图、一张纸板布景图，统一造型和材料。它们是建议提供的参考。下面选用程序化玩偶，简单的分部件关节即可完成动作，不依赖外部动作库。

案例 4：热气球穿越童话世界

这条短片用同一个男孩和热气球串起8个世界。作者的提示词把人物造型、材质、灯光、环境和动作都写了进去，还规定每个世界安排两个镜头：先展示环境规模，再靠近人物或换一个角度。这些要求一起决定了画面的丰富程度和叙事节奏。

写在最后

折腾了这么多天，我最大的感受是：用 Claude Code 做视频，最容易掉进的坑就是“沉迷技术名词”，总觉得只要把 Three.js、WebGL、Shader 全堆上去，视频自然就高级了。

其实代码只负责把画面画出来，真正让观众看进去的，是你在分镜里安排的“变化”。下次开始做视频的时候，最好先在脑海里有一个大概的画面方向，构思好：“画面里的主角遇到了什么状态，做了什么动作，带来了什么改变？” 把这件事交代明白，Claude Code 写出来的每一行代码，才会真正变成一条让人看得进去的好片子。
