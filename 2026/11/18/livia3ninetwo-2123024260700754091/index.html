顶级AI萌宠博主猫子柒拆解：从角色设定到60秒成片保姆级教程（附全部提示词和skill）

发表于2026-11-18|行业观察
|浏览量:

本文转载自 X 博主 @livia3ninetwo（livia） 的长文，原文链接，版权归原作者所有。

这篇带你用 Codex＋Renoise MCP，做出两张猫咪角色母图、一份分镜和一条复刻猫子柒风格的60秒田园短片。

每一步都给可复制的指令，最后还附带一个专用skill。

先看我这次做出的《桂花红薯饼》。大橘负责捣蛋，也会靠踩奶把饼压好；半半管过别人，自己又被绳头勾走了注意力。

我在早期做了一个15秒试片的问题很多：猫挺真，小院也好看，可一直认真做饭，故事太平。后来补上捣蛋、互拍、失手和补救，才有了现在这条60秒成片。

下面按六步来：
建项目、定角色、写分镜、分段生成、剪辑验收、装成 Skill。

这张参考截图记录了猫子柒单平台52.7万粉丝、567.6万获赞，属于截图时点的数据。这篇赛道拆解也提到视觉传播、角色辨识度和可复用流程。

放到自己的账号上，先做出让人记得住的两只猫。换食材可以继续拍，角色的脾气、小院的样子和相处方式，要逐渐稳定下来。

Part 1｜建好项目，让工具先跑通

你先准备三样东西：Codex 、Renoise 账号、一个本地项目文件夹。有参考视频、截图或拆解文字，也一起放进去。

网页端：Renoise 官网；

手机端：下载或打开 Renoise App。

本次分工很明确：

Codex 整理脚本和文件，内置生图生成角色；
Renoise MCP 生成视频；
Codex 调用本地脚本拼接、加字幕。

MCP 是 Codex 调用 Renoise 的入口。先从 Renoise 入口登录，再按 MCP 连接说明操作；授权完成后，先检查连接，再提交生成任务。

第一步，打开项目，把这段发给 Codex。 方括号换成自己的目录和预算，其他内容可以先照用。

我要制作一条60秒、9:16的写实田园双猫短片。
项目目录：[完整路径]；本轮视频预算：[积分上限]。
角色图用Codex内置生图，视频用Renoise MCP，剪辑和字幕在本地完成。

  1. 检查项目目录能否读写、Renoise是否连接，读取账号积分和当前模型能力。
  2. 建立“设定、角色图、分镜、生成记录、原始片段、导出”六个子目录。
  3. 把目标、分工和缺少的材料写入brief.md；先不要提交收费任务。
  4. 如需我登录，给出具体入口，等我完成后重新验证连接。

你应该拿到：明确的连接结果、一个 brief.md，以及能找到的项目目录。若只收到“已连接”的文字，却没有实际读取账号的结果，就继续让它检查。

第二步，确定这集做什么。 第一次可以直接跟本例做桂花红薯饼。想换题，先用下面的指令筛选。

围绕[季节/食材]，给我3个两只写实猫能完成的田园做饭选题。
每个用短段写：成品、主要工序、能用上的猫本能、两次转折、结尾回扣。
标出最难生成的动作，推荐其中一个，并给一个更简单的动作替代方案。
我选定后，把故事写进设定/story.md，先不生成视频。

红薯饼适合这次练习：

食材会从带泥红薯变成金黄熟饼，面团可以接上踩奶，滚动物和篮边绳头又能引出捣蛋。

跟本例做，就接着告诉 Codex：“选桂花红薯饼。大橘捣蛋、半半制止，半半又因追绳失手，大橘用踩奶补救，最后两猫同篮。把这个故事保存到设定/story.md。”

选定后检查：你能否用一句话说清“它们想做什么、谁弄乱了什么、最后怎样做完”。说不清，就先改故事。

这一节完成的标志：工具能用，选题确定，文件有家。 接下来再给这个故事挑演员。

Part 2｜先定两只猫，再生成角色母图

先给角色各分一项本事和一个毛病。大橘会踩奶、能压稳东西，但看见滚动物就想拨；半半做事细，却忍不住追绳。

这样安排，捣蛋者能帮上忙，认真者也会失手。后面的反转可以直接从它们的习惯里长出来。

两只猫的角色卡：本事、毛病与相处方式

2.1 生成两张独立母图

把下面的指令交给 Codex。已经有满意的角色图，就先让它读取并沿用；新项目才从零生成。

用内置生图分别生成两张独立的全身猫咪角色母图，不拼成一张双猫海报。

共同要求：真实成年短毛猫，正常猫脸、猫掌和身体比例；自然坐姿，头、四肢、尾巴完整入镜。浅灰干净背景，柔和自然光，清楚毛发；不穿人类服装，不加文字或道具。

大橘：敦实橘虎斑，琥珀眼，奶油白下巴，额头M纹，尾巴有环纹。
半半：黑橘白三花，黄绿眼，白胸白爪，额顶少量橘毛，胸前两枚小金铃。猫自身右半头黑、左半头白；正面看是画面左黑右白。

把两猫外形和性格写入设定/characters.md：大橘会踩奶但爱拨滚动物，半半细心但爱追绳。
母图保存到角色图目录，分别展示结果，等我选定后再用于视频。

看图时按这个顺序检查：身体是不是猫，四肢是否完整，脸型能否辨认，花纹和饰物是否正确。背景好看不能抵消多出来的一只爪。

我这次把搭档从白猫改成三花，又把头部黑毛改成半边。局部改图时，限定修改区域，能减少其他特征跟着变化。

编辑我选中的半半母图，只改头部黑毛分布。
保留猫自身右半头的黑毛，把左半头黑毛改成自然白毛。
保持脸型、黄绿眼、额顶少量橘毛、身体花纹、尾纹、体型和双金铃不变。
输出同一只猫；其他区域保持原样。

左右要按猫自身来写。正面时画面左侧的黑毛，转头以后仍属于它的右半头，不能随镜头翻到另一边。

通过的母图保存为确认版，例如 大橘_确认.png、半半_确认.png。以后每一段视频都复用这两张。

下面是本片最终采用的两张独立角色母图。半半已经完成半黑脸修改，后续各段视频都沿用这两个确认版本。

2.2 给小院和道具也立一张卡

光锁住猫还不够。篮子大小、碗的颜色、面团数量也会影响连续性。把下面这段接着发过去。

为本集建立设定/world.md和设定/continuity.md：
秋日桂树小院，旧土墙在后，柴灶在左，低水台在右，矮木案居中。
自然侧光，土、木、竹、粗陶质感；劳动主机位大橘在左、半半在右。
固定道具：青绳补边的浅竹篮、一棕一青灰两只浅碗、左前角有缺口的木案。
浅篮要能容纳两猫贴坐；青绳补片位置固定。
从分团开始始终是两份面团，煎后变两枚饼。
按工序记录食物状态和物件位置，变化需要有画面交代。

我这次的浅篮在结尾还是变成了深竹篓。下次要加强这一点，就单独做道具参考图，持续核对尺寸和形状。

这一节完成后，你应有两张确认母图、一份角色设定和一份连续性记录。 先把这些保存好，再开始拆镜头。

Part 3｜把故事拆成能生成的镜头

先安排节奏，再写每个动作。本例把60秒分成六段：采收、备料、冲突、补救、出锅、收尾。

60秒目标节奏：从采收到共同生活

图里是目标时间，剪辑时会按真实动作微调。原来的19镜也按这个顺序展开，不要求每隔几秒就安排一次打架。

3.1 把“情绪”改成看得见的动作

“半半生气了”很难执行。改成“按住被撞歪的面团，抬头看大橘，收着爪尖拍一下”，画面就有了起因、接触和结果。

把角色卡、世界设定和故事交给 Codex，再复制这段。

读取本项目已确认的角色、故事和连续性记录，写出60秒文字分镜。
节奏：0–6秒采收扑篮；6–21秒洗蒸压泥；21–30秒分团互拍、绳头分神；
30–40秒压歪、踩奶补救；40–50秒慢煎装盘；50–60秒分享、同篮盯绳。

每镜写：镜号、时长、景别、动作前状态、主要动作与接触点、动作后状态、字幕、声音。
每镜一个主要动作，双猫接触用看得清双方的中景，食物变化用特写。
先拍清大橘拨歪面团，再拍互拍；先交代绳头，再拍半半回爪压歪。
保存为分镜/shots.md。逐镜检查时长、因果和食物状态，暂不提交生成。

你应该拿到能逐镜读懂的稿子。看到“调皮、治愈、有电影感”这类词时，继续追问：具体是哪只爪、碰到什么、最后停在哪里。

这里给一个能直接放进分镜的动作示例：大橘拨动面团，面团挤歪半半那份；半半按住、抬眼、轻拍，大橘挡住再回拍。顺序清楚，笑点才成立。

3.2 分清母图、首帧和视频抽帧

角色母图、单镜首帧与视频抽帧各管什么

本次实际走的是“角色母图＋文字分镜→分段视频→抽帧检查”，没有提前做19张首帧。

母图用于保持身份，首帧用于安排镜头开始时的构图，抽帧则是生成后拿来检查的。三者不能互相顶替。

如果扑篮、互拍这些镜头总是摆不好，可以为其中一镜补首帧。停在动作开始之前，给后面的动作留空间。

为镜头[镜号]生成一张9:16首帧候选，沿用两张确认母图和小院设定。
画面停在[动作发生前的状态]，明确猫掌、目标物、支撑面和落点。
不要提前画完动作，不加字幕。生成后检查构图和角色外形。
先查当前视频模型是否支持这种首帧模式；如仅支持普通参考图，明确说明。

这个分支按需要加。拿到首帧也仍要检查生成视频中的运动和接触；一张正确的起始画面，不能保证全过程都正确。

这一节的交付是文字分镜，复杂镜头可另附首帧。 下一步才把它们变成实际任务。

Part 4｜先生成小样，再接成60秒

本例重写脚本后，先做33秒预览，再补27秒。采用素材分四段生成：6秒、15秒、12秒、27秒；一段里可以包含多个剪辑镜头。

这组时长是本次案例。换模型以后，要按当前单次时长和参考素材限制重新拆，不能假定所有模型都接收27秒。

4.1 上传母图，先拿到素材对应关系

把两张确认母图的路径交给 Codex，让它通过 Renoise MCP 上传登记。任务里要实际附带参考素材，光在提示词中写“沿用上一只猫”不够。

将[大橘母图路径]和[半半母图路径]登记为当前Renoise账号的参考素材。
先检查素材库，已有同一素材就复用。
保存“角色名→本地文件→素材编号→参考用途”的映射，逐项展示给我。
后续任务必须附带对应素材；不能只把编号写在提示词正文里。

核对映射时，确认大橘和半半没有接反，半半用的是半黑脸确认版，旧白猫图没有混进去。

4.2 整理任务包，核对报价后执行

每段生成词都要讲清四件事：参考图锁什么，镜头从哪里开始，怎样动作，结束时停在哪里。

本片的田园感也要写具体：柔和自然侧光，旧土墙和竹编，缓慢观察机位，蒸汽、水珠和饼面的近景。只写“李子柒风格”，还不够指导制作。

读取shots.md和素材映射，为前33秒整理可提交的生成任务。
按当前模型能力拆段；每段写完整提示词、时长、画幅、清晰度、声音和参考素材。
提示词包含：角色身份、田园摄影、起始状态、逐镜动作、结束状态。
保持真实猫掌与身体比例，工具有支撑，不做腾空翻饼，不在画面生成步骤文字。
展示本轮报价与预算占用；在我确认这版任务后提交，不超出授权范围。
返回任务编号、实际参数和扣费，查询同一任务直到完成，下载原始片段。
检查本地剪辑依赖，按分镜临时拼成导出/33秒小样.mp4，保留原片并展示小样。
若客户端超时，先查原任务状态，再决定是否重试。

提交前，先看 Agent 给出的报价卡片。 这次前 33 秒拆成 6 秒、15 秒、12 秒三个任务，分别为 96、240、192 积分，合计 528 积分。核对模型、画幅、时长、声音和费用后，再确认生成。

看到结果后，先完整播放小样。重点看三处：猫有没有换脸，打闹前有没有原因，最后一秒的站位和面团状态能否接下去。

发现问题时，直接指出秒数和动作。 比如“分团这段没有看见碰撞，先补清撞歪的起因”，比“还不够生动”更容易改对。

前33秒满意后，再发续拍指令。

保留已确认的前33秒，只补后27秒：踩奶压饼、半半模仿、慢煎、装盘、同篮盯绳。
两张母图继续锁身份；前段视频只参考台面、站位和食物状态，别把互拍动作重新演一遍。
先描述前段结束状态，再写续拍提示词、参考分工和当前报价。
若模型不支持单段27秒，按自然动作边界拆开。
按确认后的方案执行，保存任务记录；不要重生成已经满意的前段。

续拍也会单独报价。 后 27 秒的卡片列出本轮提示词、角色参考、生成参数和预计 432 积分。确认这版续拍方案后，再提交生成。

后 27 秒续拍报价：432 积分。与前 33 秒的 528 积分合计为 960 积分。

本次实际使用 Seedance 2.5、9:16、480p、原生声音，四段分别花了96、240、192、432积分，共960积分。早期未采用的15秒试片另花90积分。

这些是本项目的已知视频生成费用。新任务看当前报价，订阅、生图和人工时间另计。

这一节结束时，应拿到可播放的原始片段和任务记录。 字幕和节奏调整放到下一步。

Part 5｜后期加步骤字，按真实画面验收

先把片段下载到原始片段目录，按故事顺序整理，再让 Codex 检查本地的 ffmpeg、ffprobe、Python 和 Pillow。

本片的步骤字有八条：收红薯、洗净、蒸软、压泥加粉、分团、压成小饼、小火慢煎、开饭。

字幕跟动作走。本次“开饭”落在约47.167秒的装碗画面，不能只照脚本上的47秒整数位置机械叠字。

把片段路径和步骤文字一起交给 Codex：

读取[原始片段目录]与已确认分镜，先检查本地剪辑依赖。
按实际动作切点拼成60秒、9:16视频，保留原文件，输出到导出目录。
用八条步骤短字幕交代工序，每条显示约2秒，避开猫脸、猫掌和食物。
保留可用原生音轨，检查突变、爆音、异常静音；不新增收费配乐或生成任务。
交付：MP4、SRT、片段顺序、切点与可重跑脚本。
用ffprobe核对时长、尺寸、帧率和音轨，做完整解码与字幕抽帧检查。

交付后先静音看一遍，检查因果；再开声音完整播放，检查听感。仅凭几张漂亮抽帧，判断不了动作和声音是否连贯。

下面这张检查单可以直接交给 Codex；你自己也照着看一遍。

检查最终成片，按“具体秒数｜问题｜处理建议”输出：
[ ] 两只猫外形一致，半半黑毛没有翻边，双铃没有变化。
[ ] 猫掌接触明确，没有人手、多肢或身体粘连。
[ ] 互拍有起因，半半失手有刺激物，大橘补救有效果。
[ ] 两份面团、两枚饼及竹篮形状前后接得上。
[ ] 八条步骤字完整可读，没有盖住关键动作。
[ ] 时长与画幅正确，声音无明显突变，文件能完整播放。
只提出必须修、可剪辑缓解、可接受的问题；先不重生成。

本次面团跨段变色，我剪掉了一秒最突兀的镜头，把时间留给蒸汽特写。篮形变化、装盘后看似多出的半块饼，则保留在复盘里。

这也告诉我该在哪里改：短暂的接缝可以剪；整个镜头里的身份、道具和数量错误，要回到素材生成环节处理。

最终成片为480×854、24fps，视频轨60秒。视频生成累计1050积分，包括那条没采用的15秒试片；没有为上述偏差追加付费重做。
