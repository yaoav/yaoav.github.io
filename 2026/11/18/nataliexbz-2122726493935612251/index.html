My AI Employee Works Almost for Free. Here’s How to Set Yours Up the Same Way (Full Guide)

发表于2026-11-18|行业观察
|浏览量:

本文转载自 X 博主 @nataliexbz（natalie） 的长文，原文链接，版权归原作者所有。

6 repos, one maintainer, and no idea which job was eating my credits.

I had a theory, though. Like most people, I assumed the model was the expensive part. Use the smartest one, pay the most. Use a lighter one, pay less. So the whole game is picking the right model, right?

Then I opened Viktor’s Usage page and read it line by line.

The check that reads all my repos twice a day, every single day? 18 credits for the whole month. Most of its runs don’t show a single credit.

The most expensive line on the page was a chat. One chat, 93% of everything I’d spent.

My chat. The one where I hired him, explained my projects and set up every job.

So the model wasn’t eating my budget. The way I worked with him was. Once I saw that, I stopped picking models and started sorting jobs instead.

That’s what this article is: how I sort every job I give my AI employee now, from the one that costs almost nothing to the one that cost me the most. For each job you’ll see what it is, what it runs on, why, and the first thing you can do today.

One rule before we start: every number here comes from my own Usage page. Viktor runs on what I set. He doesn’t choose a model for each job by himself, and nothing changed without my yes.

The four settings that actually matter

Viktor runs on modes you set for the whole team. Ultra is for the hardest work. Smart is for everyday work, and it’s the default. Balanced is for routine work in volume. Cheap is for quick lookups and checks.

On top of that, each scheduled automation can run on its own model, you can switch models inside a chat (Claude, GPT, Grok and more), and in any chat !fast gets you a quick answer while !deep takes on a hard problem.

Here’s how I think about them now. They’re not really “models”. They’re how hard you want him to think. And most of my jobs don’t need him to think hard at all.

The job that costs almost nothing

Every morning and every evening Viktor reads all six of my repos, compares them with the last run and tells me only what’s new. On most days that’s nothing, which is exactly what I want from a check.

Why it’s almost free: it runs as a script. Think about what a check actually is. Pull the latest, list what changed, run the same comparisons, format the result. None of that needs thinking, so the fixed steps run without the model at all.

The result is my favorite screen in the whole app: weeks of runs, every one of them succeeded, and the credits column next to them is empty.

First move: find the job you run most often and ask yourself which of its steps are exactly the same every time. Those steps shouldn’t cost you thinking.

Stop asking a genius what time it is

“Which of my repos has no license file?” “When did I last push to this one?”

If you ask that in a chat on the default mode, you’re asking your smartest setting a question a quick lookup could answer. It works. It’s just like asking a senior engineer what time it is.

In my Viktor workspace !fast points to Balanced, and !deep uses the default model. Quick question, !fast. Hard question, !deep. I don’t think about models anymore.

First move: start your next quick question with !fast and see if the answer is enough. It usually is.

The boring report doesn’t need a genius either

Every Friday Viktor sends me one community digest: new stars and forks, new issues and pull requests, anyone waiting for my reply, and a draft reply for each.

It’s a lot of reading, but it’s the same reading every week. That’s what Balanced is for: volume, not difficulty. Running it on Smart would mean paying for thinking the job never uses.

First move: pick one report you put together by hand every week and give it to him as a scheduled job on Balanced.

Still reading? Then you’re exactly who I write these for. Follow me: I test this stuff on my own setup and post what I find.

Where I let him think

Every Monday Viktor clones each of my repos on a clean machine, runs every command exactly as the README says, and reports only real problems, each one with a fix.

This one stays on Smart, and I’m happy to pay for it. Here he isn’t just noticing that something broke. He has to work out why, and that’s the kind of work the default mode is for.

First move: ask Viktor to run your own README the way a stranger would. Nothing gets pushed until you say yes.

The only place I’d pay for the best

Release notes, the changelog and the last check before a tag. Do the version, the changelog and the README all say the same thing?

A mistake here reaches every user and stays public. So this is the one place where I want the strongest reasoning I can get, and I can afford it because I’m not paying for it anywhere else.

To be honest, Ultra is the one Viktor mode I haven’t used yet. My first release is the job it’s waiting for.

First move: write your jobs in two columns, “the same every time” and “a mistake here is public”. Only the second column gets the top mode.

Plot twist: my priciest jobs came with the setup

When I sorted my scheduled jobs by credits, the top of the list surprised me. The two most expensive ones were background jobs that came with my Viktor setup. They ran on the team default, and the priciest one cost 269 credits a run. I paused both myself.

Further down the same list sits another one of his background jobs, set to its own lighter model, a GPT model at low reasoning. That one costs 14 credits a run.

They’re different jobs, so it isn’t a lab test. But it’s the same employee in the same month, and the gap between those two lines is the whole point of this article: what a job runs on decides what it costs.

First move: open Usage, then Scheduled tasks, sort by credits and read the “per run” line under each job. If one looks too high, that’s the one to move to a lighter setup. You can also give each automation a monthly cap, so a surprise shows up as a cap and not as a bill.

And then there’s me

So what was the most expensive thing on my page? The long chat. Hiring him, explaining my projects, setting up every job, running each first report, asking follow-up questions.

The chart tells the story. Two tall bars: the day I hired him, and the evening I gave him three new jobs and asked for every first report at once. On most other days, it’s almost flat.

I don’t regret a single message in that chat. Every job in this article started there. But it changed how I see the whole thing: setting up is the expensive part, and running is cheap. Once a job is set up right, it can run for weeks for almost nothing.

First move: when you set up a new job, keep that chat about that one job. When it’s ready, the routine moves to a schedule and the long chat stops growing.

Where to start this week

  • You run the same check again and again: make the fixed steps a script
  • You ask a lot of small questions: !fast
  • You send the same report every week: Balanced
  • You need real problem-solving: Smart
  • You ship anything public: the top mode, and only there
  • You’ve never opened your Usage page: sort it by credits per run
  • Your bill is mostly one chat: separate the setup from the routine

When I still pick a model myself

For single questions in a chat I still decide: !fast for a lookup, !deep when it’s genuinely hard. And when my first release comes, I’ll switch to Ultra by hand.

Viktor doesn’t choose the best model for each job by himself. That part is mine. What he gives me is a bill I can read job by job and run by run, so I can see when I got it wrong.

What I got wrong

I spent weeks wondering which model is the smartest. Wrong question.

The right one is simpler: which of my jobs need thinking at all? For most of mine, the answer is almost none. The thinking goes where a mistake would be public, and everything else runs as light as it can.

Pick one job you already have. Make it one step lighter this week and watch your Usage page.
