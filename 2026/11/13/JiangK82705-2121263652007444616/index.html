裁员潮下，失业的互联网人该不该做独立开发？

发表于2026-11-13|行业观察
|浏览量:

本文转载自 X 博主 @JiangK82705（蒋云何） 的长文，原文链接，版权归原作者所有。

先来分享一下数据，我在 TrustMRR 上的个人经常性订阅收入（MRR）刚刚超过 6,000 美金，赶上了以前上班时的收入：

同时，我今年 7 月组建的小团队，成立 4 个月，月营收也突破了 20,000 美金：

把这两个数字摆出来，不是为了炫耀——放在互联网大厂的薪资总包面前，这点收入真不算什么。我只是想借此聊一个很多人关心的话题：一个人或一个小团队，不依靠公司，靠做产品养活自己到底可不可行？

网上聊起 AI 红利和独立开发，总让人觉得遍地是黄金。但真正下场才知道，从零做产品很难：起步慢、前期没有正反馈——很长一段时间里，闷头做出来的东西发出去没人用、赚不到钱，才是常态。

独立开发这两年半，为了先把现金流跑通，我也试过别的路子：做自媒体、接商单、做课程。说实话，内容变现比做产品快太多了，最多的时候我靠自媒体和课程单月营收接近 30 万人民币。

不少朋友因此好奇：明明跑通了一条来钱更快的路，为什么今年我反而坚定地把重心转回来，非要死磕“做产品”这件又慢又难的事？

与此同时，互联网的寒意每个人都能感受到。不管是应届生还是工作十来年的老程序员，找工作都越来越难；公司里岗位合并、裁撤已成常态，国家级政策文件里甚至首次提出了“鼓励企业探索建立失业缓冲期制度”。很多年轻人和像我这样的“中登”都很迷茫，开始看副业、看独立开发。

这篇文章是我最新一期单人播客的文字精编版。我想结合这两年半走过的弯路，集中回答一个问题：

对于程序员和互联网从业者，在 AI 时代，我们有没有机会靠自己的产品做到月入 5,000 美金？

5,000 美金，折合人民币三万多块。跟以前大厂的高薪和年终奖比确实不算多；但如果生活在国内任何一个二三线城市，控制好欲望，每月稳定的三万多块钱已经足够过上非常体面、从容的生活。

更重要的是，这件事对互联网人来说完全有机会达成——而且上限远不止 5,000 美金。

一、先建立信念，但别忽略试错成本

做独立开发的第一步，是你得先相信这件事有人做成了。如果不信靠一个小产品能养活自己，你根本不会迈出第一步。

建立信念最直接的方式，就是多看真实案例。

去海外社媒看看那些 Build in Public 的独立开发者，月入几千甚至几万美金的人大有人在；或者去我做的产品 BizPeel 上翻一翻，上面收录了大量月入几千美金的真实产品，完全可以作为起步参考。

每次聊到这，国内很多朋友的第一反应都是：“真赚钱的东西，人家怎么可能公开说出来？”

这种商业认知其实是错的。很大程度上，商业本来就是透明的——一款产品畅不畅销、流量大不大，看一眼数据就知道，大家都在一张桌子上打明牌。别人愿意公开收入，是因为公开分享能换来更多曝光和信任，就像新能源车企天天发销量海报、晒定金数据一样。说出来，能帮他赚更多钱，就这么简单。

但硬币的另一面，我也必须把丑话说在前面：相信这条路可行，不代表你做一款产品、干三天两头就能成。

公开案例里一定存在幸存者偏差。强如字节跳动，坐拥顶级资源去做新业务，照样会死掉大批产品。所以，先通过真实案例相信这条路走得通，同时做好做多款产品、反复试错的心理准备，这是下场前最重要的一课。

二、为什么今天外面的机会，比待在公司里大？

如果现在有人问我：“到底该不该出来做独立开发？”

我的判断标准很明确：准备好一年左右的生活费缓冲，短期内没有负债压力，并且家人支持你。 只要满足这三条，我非常鼓励你出来试一试。

我知道最“安全正确”的说法是劝所有人留在公司苟着。但我的真实观察是：今天外面的机会比公司里大，因为公司和组织的原生结构，正在严重限制大多数人对 AI 的使用。

1. AI 供给的代差

了解企业内部采购的人都知道，很多公司走的是 API 按量计费，预算和权限卡得很死——要么只配国产模型，要么严格限制 SOTA 模型的用量。

而个人用户今天最大的红利，其实是每月 200 美金的顶级订阅套餐：直接用最强的 SOTA 模型，额度给得极足。当外面的开发者每天敞开额度试探最强模型的边界，而你在公司里处处受限，时间一长，对 AI 能力和新机会的认知就会拉开代差。

2. 自掏腰包会彻底改变心态

如果只是为了上班，让你每月自费 200 美金买工具，谁都会觉得贵。

但做自己的产品时，账就变了：200 美金约合 1,400 元人民币，在市场上雇不到任何人，却能雇一个顶尖 AI 帮你写代码、做调研、推产品。因为钱是自己掏的、产品是自己的，你会逼着自己把它用完、用透。

3. 大公司的组织摩擦

退一步讲，哪怕公司给每个人配齐了最强模型和无限额度，大公司的部门墙、数据权限、合规审查和利益分配，依然会锁死 AI 的上限。

在公司里，部门墙就是数据墙，而 Agent 恰恰需要完整的上下文数据；大家都知道建知识库重要，但让员工把经验交出来落库对个人并没有好处，推进成本极高。

打个比方：一个目标拆成 10 件事，以前公司分给 10 个人做；有了 AI 后变成 5 个人每人做两件，美其名曰“AI 提效两倍”。但在我这里，这 10 件事由一个人 + 最强模型 + Agent 顺着目标直接干完——这就是本质区别。

如果你们公司的产品今天还是按周迭代、按周发版，那就太慢了，还算不上 AI Native。真正的 AI Native，是一天发几版。

举个更具体的场景：双十一给网站价格页改个半价促销、加张优惠券。在大公司里，产品出方案，拉上算法和风控评估定价与资损，再找设计出图、研发排期上线，整套流程最快也要一天。

而我自己做产品，跟 AI 说一句直接改，连改带测一个小时上线。一天对比一小时，这就是 24 倍的效率差距。小团队没有部门利益拉扯，只需要和 AI 一起对结果负责。

4. 别拿公司的岗位分工把自己“螺丝钉化”

让你做前端、做后端或者做算法，本质上是公司为了规模化管理在定义你——把大工程切碎，一个萝卜一个坑。

最怕的是待久了，你自己也认了这个设定：遇到写代码之外的事，第一反应就是“我是后端不懂前端”、“我是研发不会做产品和增长”。

在 Agent 时代，人的能力边界被成倍放大，原有的岗位切分反而成了 Agent 执行的摩擦。我现在甚至鼓励团队里的产品经理直接拉代码、改代码上线——虽然偶尔还是有点担心他们搞混分支，但这就是未来的协作方式，管理者要做的是把 Agent 友好的基础设施搭好。

真正出来做事后，你还会发现一个变化：办法永远比困难多。

在公司里，业务能力再强，升职加薪的卡点始终是老板和晋升名额；出来做产品后，社媒、SEO、Google Ads 全成了你手里的工具，服务商和平台真心希望你赚到钱，因为他们需要你这个客户。这条路不通就换一条，主动权完全握在自己手里。

三、我看到的 AI 未来：为什么放弃单月 30 万卖课转做产品？

回到开头的那个问题：自媒体和课程最高单月能赚近 30 万，为什么今年我执意转向做产品？

虽然资本市场上偶尔有人讨论 AI 泡沫，但模型能力传导到具体业务本就有滞后性，各行各业最终都会被 AI 重塑。更关键的是，前两年 AI 只是“单点辅助”（写段脚本、剪个片子、补几行代码），而现在 Agent 已经可以放进一门生意的完整闭环里了。

我为此定义了一个概念：生意的“Agent 渗透度”——即 Agent 能接管整条业务链路的比例。

1. 更高的 Agent 渗透度 × 更高的商业上限

单看普通人最有生意机会的两件事：自媒体和做产品。

做像我这样真人出镜的 IP 型自媒体，从选题、资料收集、写大纲脚本到剪辑上传，AI 大概能接管 60%；剩下 40% 必须人来盯方向、抓网感、架起机器真人表达，六四开基本就到头了。（如果是做不露脸的 faceless 账号，用现在的 Opus 5.5 和 Fable 5.2 做到 90% 交给 AI 没问题，但商业模式与信任资产不同。）

再看做产品。按我目前的体感，产品业务已经能做到 80% 交给 AI，往后推到 90% 非常清晰。X 上甚至已有顶尖开发者用 Agent Loop 把产品的 Agent 渗透度推到接近 100%，每天晚上只需花一点时间收尾“铲铲屎”。我个人判断，Agent 自主完成“定义需求—开发测试—上线营销”的完整闭环，明年就有机会实现。

内容变现起步快、正反馈快，但天花板低；做产品起步难、反馈慢，但商业上限极高，对个人的复利效应也更强。更高的 Agent 渗透度叠加更高的商业上限，这就是我坚定转向做产品的核心逻辑。

2. 智力供给爆发，让“过去算不过账”的小生意成立

很多人担心：“人人都能 Vibe Coding 了，都在喊 SaaS 已死，我还有什么机会？”

恰恰相反，大多数人严重低估了 Agent 带来充足智力供给之后的新机会。

过去几十年的工业化只让标准化制造品过剩了，但个性化产品与服务的供给其实极度不足。以前不是没有需求，而是沟通和交付的人力成本太高，生意算不过账。

举个我自己的例子。我来北京北漂正好十年，刚来头两年住自如的合租房，典型的大白墙配粉红窗帘。当时我特别想花 3,000 块钱（差不多一个月房租）把屋子改造得温馨一点：1,000 块给设计师当设计费，2,000 块照着清单去宜家或淘宝买东西。

在以前的商业模式里，这单生意根本不成立——优秀的设计师花一两天跟你沟通、看户型、列清单，只赚一千块，完全不划算。

但放到 Agent 时代呢？我拍下房间照片，我的 Agent 直接和设计师的 Agent 对接；设计师的 Agent 调用他独有的审美库和商品库生成采购清单与 3D 摆放预览，设计师本人只需花 20 分钟把关确认。一旦沟通和执行成本降下来，一单收一千、一天接十单，这门小生意立刻就成立了。

更有意思的是，一个需求跑通还会顺带拉出一串配套生意：换了新桌椅，出租屋原本那套丑旧桌椅放哪？这时候会有独立仓的 Agent 主动对接：“旧桌椅丢我这儿寄存，一个月只收 50 块，一年 600 块。”

过去即便有闲鱼（海鲜市场）和小红书，人与人沟通协调的交易成本依然太高。就像当年 Uber 和滴滴 把打车的交易成本打下来后，不仅养出了全新的出行习惯，还顺带托起了支付与新能源汽车产业链；再比如现在的 红果短剧，因为 AI 视频供给爆发，整个平台的买量与商业化逻辑已经和真人短剧时代大不相同。当 Agent 把智力与交易成本打穿，大量新商业模式会重新长出来。

最后顺带分享一个职场观察：我是 2016 年毕业的，错过了更早的千团大战、外卖大战和网约车大战。当年那些混战里绝大多数公司都倒下了，但那批真正打过仗的基层员工，今天很多成了大中厂的中高层。如果你选择继续走职场路线，尽早投身 Personal Agent、人形机器人这类新浪潮，后半场同样可能吃到时代红利。

四、月入 5,000 美金的账本与“工程化”打法

聊完大方向，我们来算一笔最实在的账：每月赚 5,000 美金到底难不难？

  • 按月营收算：做一个定价 50 美金/月 的产品，只需要 100 个持续订阅用户。
  • 按净利润算（假设净利率 50%）：想要拿到 5,000 美金净利，需要每月 10,000 美金营收——也就是 50 美金 × 200 个用户，或者降到 25 美金 × 400 个用户。

放眼全球市场，给自己几年时间，靠一款或几款产品组合找到几百个愿意持续订阅的用户，真的没有那么遥远。

在这件事上，互联网人和工程师有天然底子。在互联网公司待过的人，自带用户视角、漏斗转化与留存的数据常识，不会写代码现在完全可以交给 Agent；而如果你是程序员，优势就更大了。

当然必须承认，单纯“写代码”这门手艺正在被 AI 替代。有人觉得程序员的工作不止写代码，还有和产品经理对齐、设计系统架构——这其实是被现有公司框架限制了想象。未来产品经理会直接和 Agent 对话开发；至于常规架构，只要选用 Agent 友好的技术栈和 Cloudflare 这类云服务，Agent 大概率设计得比人更好。

工程师真正的壁垒从来不是敲代码，而是“工程化思维与工程化能力”——把模糊问题拆解成确定性系统、搭建自动化流水线、设计数据反馈闭环的能力。在“找需求、开发迭代、营销增长”整条链路里，这种能力都是极高的杠杆：

  1. 找需求：搭自动化数据看板。 独立开发挖需求常见有“新站打法”和“品牌站打法”。以新站打法为例，核心是盯 Google Trends、搜索数据和社媒热点。外行只能每天靠手刷，工程师完全可以写好 Agent 自动采集，给自己搭一套自动化需求看板。
  2. 开发迭代：把控边界与复杂度上限。 简单原型靠 Vibe Coding 就能跑，但能长期收钱的产品涉及复杂 Agent 工作流编排、上下文管理与系统稳定性。新项目没有历史包袱，工程师直接上最适合 Agent 的架构，排错速度和产品复杂度上限都远高于普通人。
  3. 营销增长：把增长当成系统跑“实验”。 很多工程师怵营销，其实增长的本质就是跑一个又一个可量化、可验证的“增长实验”。我现在直接把增长当成一套独立产品来做——用 AI 快速开发邮件营销、社媒视频制作与排期、Influencer 批量建联（DM）等内部小工具，不断加速“提出假设—上线实验—验证数据”的闭环。

这里分享一个视角转变带来的乐趣：

以前在公司配合做增长研发，总觉得加埋点、改文案、调按钮没技术含量，程序员都爱啃底层硬骨头或做大功能；但自己做产品后，前置的商业逻辑接通了，亲眼看到每一次按钮调整直接带来真实的营收增长，感受完全不同。不要抗拒职业边界的扩张，进一步有进一步的欢喜。

我很喜欢《硅谷增长黑客实战笔记》里的一句话：

Everything is an experiment, you win or learn.（任何事情都是一场实验，你不是收获增长，就是学到经验。）

顺着这套闭环，分享我现在做产品的两个核心习惯：

  • 第一，需求想 50 分就动手，但“怎么运营推广”在开发前先想 80 分。 单干最容易踩的坑，就是闷头把功能打磨到满分，上线才发现不知道去哪找用户。不同产品适配的渠道完全不同（有的适合 Reddit + SEO，有的只适合 Influencer 营销），动工前先评估清楚推广渠道匹不匹配你的能力。这方面推荐去看看我们的 BizPeel.com，里面拆解了很多真实赚钱产品在不同阶段的获客渠道与数据打法。
  • 第二，把个人和小团队最大的优势——“快”发挥到极致。 没有跨部门排期，合理需求立马上、出了 Bug 立马修，真正做到**“用户想要，用户得到”**。底层模型一升级，产品定位、新功能上线和增长实验也要跟着快跑。

只要跳出以前公司的岗位分工，保持这种高频实验的节奏，把周期拉长到一年左右（切忌指望一两个月速成），达成月入 5,000 美金完全可期。

五、一个确定性的大方向：给 Agent 做产品

如果要分享一个目前我看到最确定的产品大类机会，一句话就是：给 Agent 做产品。

我现在团队里绝大部分项目——无论是公开构建的 Skillry（给 Agent 用的技能市场，把网页、PPT、视频等经过验证的审美和方法封装给 Agent）、BizPeel（给人和 Agent 用的产品增长与营销数据库），还是尚未公开的新项目——全都围绕这条主线展开。

原因很简单，现在的 Agent 生态明显缺两块东西：

  • 第一块：外部数据与易用接口。 海外做 SEO 数据接口的 DataForSEO 今年因为 Agent 涨势极好；像 AIsa、Monid 这类给 Agent 提供聚合数据的产品，以及早期 OpenRouter 式的模型聚合中转服务，本质上都在把分散的数据与能力变成 Agent 易调用的标准服务，这里面有大量创业机会。
  • 第二块：对人友好的 UI 展示与协作交互。 从第一性原理看，Agent 靠写代码和底层工具几乎能搞定一切，但对话框绝不是人和 Agent 协作最好的方式。人依然需要直观的可视化反馈——哪怕某件事底层硬跑 Agent 也能做完，只要有一款产品把展示和交互做得足够直观愉悦，我依然更愿意为它付费。表面上它是给人看的界面，本质上依然服务于 Agent 协作。（广义上，针对垂直场景直接做执行型 Agent 也包含在内。）

我为什么这么笃定这个方向？基于三个观察：

  1. 极强的付费意愿：以前做产品优先做苹果 iOS 用户，因为付费习惯好；今天愿意给大模型和 Agent 掏钱的群体，认知高、使用高频，几乎就是“苹果用户里付费意愿最强的那拨人”。
  2. 明确的增量市场：一个人只要习惯了用 Agent 就再也回不去，未来每个人手里都会并行跑好几个 Agent。Cloudflare 最新报告也显示，2026 年互联网上的非人类流量已在历史上首次正式超过人类访问流量。
  3. 目标用户高度集中、好触达：这批核心用户高度聚集在 X 等平台，关注着相对固定的 AI Influencers，早期获客路径非常清晰。

高付费意愿、快速膨胀的增量市场、受众集中易触达——这是我现阶段看到最好的产品切口。

六、独立开发两年半，我身上的三个变化

AI 时代，不少程序员会感叹“我热爱的手艺消失了”。其实喜欢写代码、喜欢 build 东西的那种愉悦感并没有消失，只是不再局限于敲代码，而是去构建产品——甚至把你想达成的生活方式当成一个工程，去构建自己的人生。

回看这两年半，我有三点感受最深：

  1. 放大个人 Scope（边界），补上商业认知。 程序员是职场上极少有的、到了三四十岁依然保持极强学习能力的群体，学新框架飞快。只要把这份学习能力放到商业和营销世界里就够了——何况有了 AI，以前半年一年才入门的新领域，现在几周就能摸清门道。
  2. 建立“老板思维”。 自己出来扛业务后，突然理解了以前老板的很多决定：站在经营视角，核心永远是商业利益与存活率的最大化。从一人公司到小 Studio，再到未来做更大的企业，这种思维转变至关重要。
  3. 把 Agent 使用强度拉满。 人和人使用 Agent 的能力差距大得惊人。千万别在这件事上省钱：每月 200 美金的顶级 SOTA 套餐，是目前普通人最大的红利，订阅它，在真实工作里把它用完、用透。

常见 Q&A

最后集中回答四个评论区问得最多的问题：

1. 出海收款、注册海外公司怎么解决？

无论是开通 Stripe、使用 Creem，还是注册美国公司、办 Apple 开发者账号，网上一搜全是现成教程。

在我看来，注册美国公司和办收款的流程难度，跟预约一家米其林餐厅一模一样：联系对方、填表提交个人信息、等时间下号。千万别让这种纯流程问题成为你迟迟不动手的借口。

2. 独立开发者该不该做自媒体？

非常建议做。 生意的本质是完成交易闭环，而现代社会的交易依然基于信任。自媒体是积累信任最好、复利最强的方式——就算你做十款产品败了八款，分享过程攒下的信任，也会变成剩下两款产品启动时的资本。

3. 要不要 Build in Public（公开构建）？

看一件事：你在这个平台的粉丝画像，和你的产品目标用户是否一致。

如果一致（比如我的 Skillry、BizPeel 和我的社媒受众高度重合），就用个人号 Build in Public；如果不一致，就别硬拿个人号发，去老老实实做 SEO、渠道投稿，或者专门开一个身份清晰的垂直账号，深入对应的垂直社区交流。

4. 产品被人抄袭了怎么办？

第一，合法合规维权。该注册商标就注册商标，在用户协议里把数据使用条款写清楚，真遇到一比一恶意照搬或爬数据的，直接发函警告或起诉（我甚至觉得以后会有专门协助起诉的 Agent）。

第二，心态上不必内耗。抄袭者对产品的理解永远比你慢半拍，靠我们的“快”持续迭代就够了。说句实在话，网上很多 Builder 公开谴责抄袭者，也不纯粹是为了维权，某种程度上也是借这件事给自家产品多换一点曝光。

AI 时代的机会很多，但未来具体长什么样、哪条路一定能成，没有人能提前知道。

想要看清未来，最好的方式就是亲自下场去 Build。希望在 AI 时代，你也能 Build 出属于自己的产品，和理想的生活。
