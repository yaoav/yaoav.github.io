Codex 总说你看不懂的话怎么办？3 步写进设置，让 GPT-6.2 改说人话

发表于2026-11-19|行业观察
|浏览量:

本文转载自 X 博主 @danta_aigc（爱吃蛋挞） 的长文，原文链接，版权归原作者所有。

Codex 的汇报总让你看不懂，OpenAI 里做 Codex 的 Tibo 给了一句话解法，这条帖子的浏览已经超过 29 万。

帖子下面的追问一直没停，ELI5 到底是什么意思，写了到底有没有用，为什么让 Codex 自己写这一句要等好几分钟。这篇把这些追问和官方文档里的做法放在一起，整理成一条能从头走到尾的路。先讲 Codex 为什么总说你看不懂的话，再用 3 步改好设置，最后回答最常被问到的几个问题。

开始之前只需要一个能正常使用的 Codex。桌面 App 里改设置最方便，用命令行的话直接改一个文件，两种改法后面都写了。

1、Codex 为什么总说你看不懂的话

1.1 抱怨集中在同一件事上

GPT-6.2 发布后，AI 圈里传得很广的几条帖子，说的都是同一件事，它的汇报越来越难懂。下面这三条措辞各不相同，有的说它不说人话，没办法协作，有的把不说人话列成口碑问题的第三条，还有的说它做出来的设计，自己都看不懂。这篇只处理其中一件事，Codex 的汇报看不懂。

1.2 官方文档里有两个原因

官方文档里能找到两个原因，各自还附了一段对症的提示词，原文在 OpenAI 的 Using GPT-6.2 页面 https://developers.openai.com/api/docs/guides/latest-model

第一个原因，GPT-6.2 Astra 默认就比前几代写得更简短、更直接，文档的原话是 more concise and direct by default。写得短本来是优点，可对没有跟过整个过程的人来说，被省掉的往往就是背景。

第二个原因，长任务里模型会把自己推理时用的简写和行话，甚至其他 Agent 之间的用语，带进最后给你的回答，文档里写的是 can carry shorthand from its reasoning or from other agents into its final answer。你看到的缩写、内部代号和没见过的词，和这一条对得上。

GPT-6.2 有 Astra 和 Sol 两个版本，官方的提示建议对两个版本都适用。两个版本怎么选、在哪里用，我之前写过一篇，链接在这里 https://x.com/Mileson07/status/2122902496830234729

1.3 你要的是一份写给你看的汇报

所以解决办法也要从两头下手。一头让它把话说得完整一点，别只剩一个结论。另一头让它重新为你写最后那段话，别把脑子里的简写带出来。

做这两件事都要靠一份说明，它在 Codex 里有两个名字。设置里叫个人指令，Tibo 的帖子里叫自定义指令，说的是同一份。它实际是你电脑上一个叫 AGENTS.md 的普通文本文件，Codex 每次启动都会先读它。

我的判断是，光写一句请说人话不够用。这四个字没法检查，AI 不知道你要的标准，你自己也说不清它做到了没有。把标准拆成你读完就能核对的几条，AI 才有东西可对照，这也是第三步要做的事。

我一直觉得，Agent 用久了，最烦的成本是反复交代偏好。把偏好写成一份放在固定位置的说明，写一次，每个项目里的 Agent 都能读到，我管它叫偏好资产。个人指令放的就是这种东西，后面三步都是在往里写。

2、怎么做，3 步让 Codex 改口说人话

2.1 第一步，一句话先救急

先用 Tibo 给的那句话，让 Codex 马上改口。把下面这句发给 Codex。

ELI5 是英文 Explain Like I’m 5 的缩写，意思是像讲给五岁孩子听那样，用最简单的话把事情讲明白。这句话里留了出口，你要求深入讲解时，它才会展开细节。

Codex 收到后会自己去改个人指令文件。官方说明里，个人指令存放在全局的 AGENTS.md 里，Codex 会在启动时读取它。

改完以后，对话里会出现一条已编辑 AGENTS.md 的记录，说明那一行已经写进去了。下面是照着做的结果，这次用了三分多钟。

这一步要等一会儿，嫌慢的话直接做第二步，在设置里粘贴，写进去的内容是一样的。只想先试试、不想改设置的话，把引号里的那句直接发在一个对话的开头，它只管这一个对话。

写完这一步，你会得到一句已经写进个人指令的话，之后不用在每个对话里重复交代。

2.2 第二步，把官方的两段话也写进去

ELI5 这句主要调的是语气，上面两个原因它没有直接对上。官方的两段话才是对着原因写的，我建议也放进去。它们原本是官方写给开发者放进系统提示词的建议，Codex 每次启动都会读个人指令，放在这里等于给它一份开场说明。

先找到入口。桌面 App 里按 Cmd + ,（Windows 按 Ctrl + ,）打开设置，进入 Personalization（中文界面里的名字可能略有不同），里面有编辑个人指令的入口，点开就是你那份全局指令。

不用桌面 App 的话，直接编辑 ~/.codex/AGENTS.md，没有就新建一个。设置过 CODEX_HOME 的话，改那个目录里的同名文件。

写完这一步，你会得到一份放在固定位置的说明，之后每次启动，Codex 都会先读它。

2.3 第三步，新开对话测一次，再微调

保存以后新开一个对话，让 Codex 改一处无关紧要的小地方，比如某个文件里的一个错别字，改完让它汇报。官方文档里写明，Codex 启动时读一次指令文件，所以用新对话来测最稳妥，旧对话里可能还是旧内容。

用下面三条给这份汇报打分。

  1. 开头先给结论，改了什么、结论是什么，一眼能找到。
  2. 生词有解释，没见过的词，第一次出现时带一句说明。
  3. 说清验证和下一步，跑过没有、还差什么、要你做什么，都交代了。

三条都过了，这一步就做完了。哪条没过，只改指令里对应的一句，再新开对话测一次，一次改一处，才知道是哪一处起了作用。

这三条就是你的验收标准。提示词不用背，把标准说清楚就够了，怎么说清楚，我之前写过一篇，回答 7 个问题就行 https://x.com/Mileson07/status/2122943440531128596

用命令行的话，可以用官方文档里的这条命令确认个人指令有没有被读到。

官方说明里，它会先把你写在 ~/.codex/AGENTS.md 里的条目复述一遍，再开始干活。

写完这一步，你会得到一次前后对比，知道设置有没有起作用，也知道下一句该改哪里。

3、常见问题

3.1 ELI5 是什么意思？会不会是在把我当小孩？

ELI5 是 Explain Like I’m 5 的缩写，意思是用最简单的话讲明白。看到这个词觉得被嘲讽的人不少，不过在这里它只是一个写作要求，先讲人话，你要深入时再讲细节。上面那张截图里，Codex 自己的解释就是少堆术语，先用简单的话和熟悉的例子讲明白。

介意这个词的话，换成一句更直白的也行，开头先给结论，术语第一次出现时解释一句，意思差不多。

3.2 写了之后它开始打比方、像在讲课，怎么办？

试过的人评价不一，有人觉得比默认顺很多，也有人说它一直给自己讲课笔记，比喻还多。遇到后一种，把 ELI5 那句换成第二步的两段话，再补一句。

3.3 听说这句话几乎没效果，我还要试吗？

要试，但别只试这一句。吐槽的 Theo 后来回复说，这是他最先试的办法之一，几乎没有进展。

我的判断是，ELI5 管的是语气，默认写得短和简写漏进汇报这两个原因，要靠第二步的两段话来处理，所以这篇把它们放在一起用。Tibo 的帖子里也写着团队正在处理，具体什么时候改好没有说。先试一次，有效就留着，没效果也不用硬撑。

3.4 让 Codex 帮我写进去，等了好几分钟，正常吗？

等几分钟的人不止你一个。前面那张结果截图里用了三分多钟，Tibo 那条帖子下面也有人等了四分钟，期间还压缩了三次上下文。这一步要让 Codex 自己去改文件，想省时间，就在设置里直接粘贴，或者手动改 ~/.codex/AGENTS.md，写进去的内容是一样的。

3.5 写了没生效，先查哪几处？

先看是不是新开的对话。Codex 启动时读一次指令文件，已经开着的旧对话可能还是旧内容，新对话里也没生效的话，重启一次 Codex。还是不行，再查官方排错清单里的三处，清单在 https://learn.chatgpt.com/docs/agent-configuration/agents-md

  1. ~/.codex 目录里有没有 AGENTS.override.md。有的话 Codex 只读它，不读 AGENTS.md。
  2. 文件是不是空的。空文件会被跳过。
  3. 有没有设置过 CODEX_HOME。设置过的话，Codex 读的是那个目录里的文件。

3.6 以前写过“尽量简洁”，要不要删？

要重新看一遍。官方在迁移提示里说，GPT-6.2 默认就更简洁，系统提示里写过 be concise 这类要求的，要回头检查。你现在的问题是看不懂，这类要求会和第二步里给足背景的要求互相拉扯，我建议先删掉，或者改成“简洁，但不省背景”。

3.7 个人指令要写多长？

尽量写短。官方建议只放 Codex 从代码、测试和文档里推断不出来的要求，日常怎么做事交给它自己决定。

按这篇的做法，一句话加两段官方的话再加一条补充，写到这里就够了，不用再往里堆。想知道某一段到底有没有用，就用同一件小事，删掉它再测一次，汇报没变差就不用留。官方没有说明 Codex 自带的提示词有没有包含这些内容，所以最可靠的办法还是前后对比。

3.8 项目里也有 AGENTS.md，听谁的？

两份都会读，先读全局的，再读项目里的，离你当前所在目录越近的越靠后，也就越优先。想让某个项目换一种口吻，在那个项目里放一份很短的 AGENTS.md 就行，别的项目不受影响。

3.9 它老停下来问我，能让它多做一点吗？

可以，官方在 Using GPT-6.2 页面的 Task completion 一节给了一段对应的提示词，下面是精简后的中文版。

这段更适合你放心让它自己跑的事。涉及删除文件这类不可逆的动作，原文本来就要求它先停下来问你。

如果你身边也有总说 Codex 看不懂的朋友，把这篇转给他，照着三步做完，他就知道设置有没有起作用。想把 Codex 和 GPT-6.2 这类新东西变成自己顺手的用法，可以关注我，我会继续整理小白照着就能做的教程。你最近一次没看懂的 Codex 汇报，卡在哪个词上？写在评论区。
