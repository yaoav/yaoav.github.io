The 6 levels of coding with agents

发表于2026-11-14|行业观察
|浏览量:

本文转载自 X 博主 @yifanxu_ephai（Yifan Xu） 的长文，原文链接，版权归原作者所有。

Level 1: The default setup

You open up a terminal window and type claude. Kick off a prompt, and watch your agent work while you babysit the whole time. Maybe you check Slack or scroll X while it’s running.

But one chat session at a time leaves so much more work to be done.

Once you have several things you could delegate, opening another session to parallelize is the obvious next step.

Level 2: Multiple agents across multiple terminals

Now you’re spinning up multiple terminal tabs/windows, an agent in each one. One agent works on a new feature while another fixes a bug. You’re making progress on several tasks at once and unlocking real productivity gains.

But eventually, you’re juggling too many sessions and the mental load of tracking which terminal belongs to which task, which agent is waiting for you, and which one has finished is painful. You wish there was a better interface to manage all your threads.

Level 3: Enter the ADE world

The next level-up is starting to use an agent development environment (ADE). Tools like @cmux, @orca_build, @t3dotcodes, @ParadevAI, and @conductor_build help you manage more agent work without juggling terminal windows or panes yourself.

Our team uses ADEs heavily. ADEs are great. BUT the fatal flaw is that they (and everything Level 1-3) are still ultimately limited by your laptop.

Even with a 128GB RAM MacBook Pro, our CTO @tonychang430 hit memory limits, his laptop started sounding like a helicopter, and his machine froze all the time.

A few repos running Docker Compose alongside several parallel claude code threads was all it took to fry our laptops. The ADEs helped us push parallel work to new heights for us, but we came to the realization that our laptops were now the bottleneck.

Another huge issue was that our agents would stop if our laptop lid closed, went to sleep, or lost Wi-Fi connection. We found ourselves walking around with our laptop lids cracked open.

We needed to free our local machines and send our work to the cloud.

Level 4: Agents running in the cloud ☁️

Now you’re moving the execution of your agents onto a remote computer. You talk to them from your laptop while the actual agents, subagents, builds, and tests run in the cloud through SSH.

With the agent running in a persistent remote session, your laptop can disconnect while the work continues, no problem. You can finally close your laptop without the fear or your agents stopping.

You’re no longer waiting for your agents to finish before you can close your laptop and leave your house, the office, or a coffee shop. You can even connect to your remote machines from your phone and start coding with agents on the go.

But putting several agents on one or two VPS’s carries a lot of the same conflicts. Memory, CPU, disk, filesystem, and ports are all still fixed constraints or areas for conflict.

The work is finally off your laptop, but you need something more flexible and on-demand to support all the work you’re doing.

Level 5: One cloud machine for each task

Instead of packing many agents onto one big server, you give each task its own machine. Start a PR, and spin up a fresh cloud VM for it. It clones the repo, installs packages, and starts the dev server. Then the agent goes to work. When the PR merges, the box spins down immediately.

Each agent now has a whole computer to itself. They don’t fight over memory, CPU or port 3000.

You can even publish the dev server’s port on an HTTPS URL, so you can open the agent’s work in your browser just like localhost:3000 on your laptop.

Setup has to be fast. We start ours from a snapshot that already has everything set up + installed, so it’s ready in <1s.

Now you can have dozens of agents working around the clock, while your laptop stays cool and quiet.

But one problem still remains: you’re still the one running all these sessions.

You start each agent, check which ones are done, and wrap up work after the PR is merged. The work is off your laptop, but you’re still orchestrating everything. Unless…

Level 6: A central orchestrator

Now you stop opening sessions yourself. You hand the work to an orchestrator: one agent that manages all the others. Tell it what you want built, and it breaks the work into tasks, starts a coding agent (and maybe multiple subagents) for each one, checks on them, and brings you back the results.

At this stage, the agents shouldn’t wait for you to give them machines anymore. They get the compute for themselves.

A coding agent can start its own subagents, run tests, spin up dev servers, and more, each on new cloud VMs. Any task that needs compute, your agent can just spin up a box, do it, then spin the box down, and report the results back to the orchestrator agent.

For example, I literally just talk to my @bot now. I don’t care about talking to individual Claude or Codex agents anymore. My Grok Bot just surfaces important questions or details, and otherwise just prompts and manages the lower-level agents for me.

Closing

The space is moving incredibly fast, and it feels like there’s new levels being unlocked every month. We can’t wait to see what comes next. Or if you think you’ve gone past Level 6 already, let me know about your setup below!
