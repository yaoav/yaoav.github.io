Toto, we're back on canvas.

发表于2026-11-04|行业观察
|浏览量:

本文转载自 X 博主 @figma（Figma） 的长文，原文链接，版权归原作者所有。

Code layers just rolled out to everyone! I’m incredibly excited for this to be out in the wild and to work with you to make it even better.

Some thoughts on how we got here…

In a Maker Week in the summer of 2024 a few us were dabbling with AI and code — as one does — and we explored this idea if we could generate code when you attach Dev Mode annotations to designs and use AI to build them in code.

And holy moly it worked. During that maker week I lost hours just … playing with it; creating interactive behaviors in Figma I could have only dreamt of in the many years before, where I worked on the prototyping features of Figma.

Suddenly it seemed that the ceiling was broken. And damn right it was.

We then aimed to build a first version of code layers for our upcoming Sites product — lots of first missteps and deep discussions later we not only talked about code layers in Sites at Config 2025, but through heroic effort by the original Make team, also Figma Make as a standalone product on top of everything. Crazy sprint!

But throughout all of this — it was clear; we wanted this in Figma Design. So post Config ‘25 we set out to bring this into Figma Design? How hard could it be? Lol…

The first challenge to tackle was how to interact with code on the canvas. We spun out a first version and shipped Make embeds. But we knew this wasn’t enough: it still required users to create individual Make files — which slowed down iteration and collaborative exploration; one of the key value props we see users to this day missing dearly when they’re working in standalone agentic coding tools.

But bringing in code not just as a playable artifact, but as an editable project wasn’t straightforward; of course we needed to make sure that it’s performant for the wildly explorative workflows we know designers and their teams have every day in Figma.

On top of that, by being on the canvas in Figma Design users expected seamless workflows between existing design layers and code layers; design layers offer a great way to not just fine-tune the details, but also communicate effectively to your entire team, what your idea entails.

Additionally — at the same time — a different team was working on the Figma agent, too; into which we integrated code layers, so you can ask your design agent to create 15 different code layer iterations!

And if that wasn’t all — as we were working on this the landscape shifted under us; users weren’t just using AI to vibe code 0-1 prototypes anymore, but worked with real codebases.

This led us to build workflows for code layers to import code from your local folder or clone repos from GitHub cloud — this last part is the wildly exciting part; not only can you intuitively explore with code; when done you can create a PR back into the repo!

So you can see how the scope kept increasing, the world around us being as fluid as never before, and the quality bar to get something into y’alls hands is high.

But I’m so stoked that code layers is out in beta to all Figma users!!! 🚀

At this point an absolutely humongous congrats to all the folks at Figma and all our early testers who helped make this a reality!

But Niko — are y’all done? Fuck no: we’re at the starting line: Our goal is the same. We’re building a full-stack-creative canvas in which you can work with any material you like side-by-side and not alone, but together with your colleagues, friends, and agents.

Because you find the best ideas fastest through experts and agents working together, creating a mess, finding the wrong ways of doing something or connecting ideas—creating clarity and direction.

I’ve been doing this for a while (9 years at Figma soon) but my favorite thing still is building this for and with you; I wanna hear where it falls short, how you use it and most importantly I want to see what you create! Let’s fucking go!
