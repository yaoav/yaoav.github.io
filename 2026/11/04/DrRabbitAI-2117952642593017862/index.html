AI如何赋能科研完整工作流（第一期）

发表于2026-11-04|行业观察
|浏览量:

本文转载自 X 博主 @DrRabbitAI（Roxy） 的长文，原文链接，版权归原作者所有。

大家好啊，我是兔老师。

昨天，我在学校给研究生上的课终于结课了。

这门课叫“大数据和人工智能”。整个课程里，我有一半的内容在讲 AI 如何赋能科研。因为我理解，这门课的意义，是给研究生做科研提供工具上的支撑。

趁着刚结课，我想把这部分内容系统地梳理一遍。内容比较多，会分几期来讲。

今天是第一期，主题是文献检索。

内容由易到难，涉及的工具包括 YILA、Grok Bot、Codex 和 WorkBuddy。我自己不是 WorkBuddy 的用户，但课上很多研究生在用，所以这一期也会讲讲在 WorkBuddy 里怎么操作。大家可以根据自己的习惯，挑需要的部分读。

01｜先说一个常见的坑：只靠开源检索 Skill

现在网上开源的论文检索 Skill 非常多，装起来也很方便。

但很多检索 Skill 有一个问题：它们只连了少数几个免费来源，比如 arXiv 这样的开放获取平台，或者用不带 key 的免费接口，搜几次就被限流。

结果就是，你用它搜一个方向，只出来十几篇论文。

最危险的不是搜得少，而是它会给你一个错觉：这个方向的论文就这么几篇。

其实不是这个方向没人做，而是你的工具没有搜到。很多人因此误判了研究空白，开题时才被导师一句话问住：“这篇你怎么没看？”

所以，如果想让 AI 帮我们检索到权威、高质量的论文，不建议只靠一个 Skill。

02｜一句话总结：两种更靠谱的方式

在文献检索这个环节，AI 辅助有两种更靠谱的方式：

  1. **直接用接入了论文数据库的 Agent。**不用配置，打开就能搜，适合大多数同学。
  2. **自己给 Agent 接入论文 API。**相当于给 Agent 装上手和脚，让它能查到更多论文。适合动手能力比较强、想自己掌控检索过程的同学。

按我自己用下来的难易程度，从易到难排一下：

  • | 难度 | 方式 | 工具 | 适合谁 |
  • | — | — | — | — |
  • | ★ | 直接用接入论文库的 Agent | YILA | 不想折腾配置，想马上开始搜 |
  • | ★★ | 给 Agent 接入 API | Grok Bot | 第一次自己接 API |
  • | ★★★ | 给 Agent 接入 API | Codex、WorkBuddy | 习惯用本地 Agent 做科研 |

工具这件事，没有标准答案。选自己用着顺手的就好。

03｜方式一：直接用接入论文库的 Agent

最简单的方式，是用已经接入论文数据库的 Agent。打开就能搜，不需要自己配置任何东西。

我平时用 YILA 做文献检索，它接入了 Google Scholar、Semantic Scholar、arXiv 和 Google 专利等数据库，论文和专利都能直接搜。

下面是我最常用的几个场景，提示词可以直接抄走。

场景一：写申报书或开题报告，找立项依据

我在申报一个省社科课题，题目是”人工智能赋能高校思政课实践教学的机制研究”。请按”现状、影响机制、实践路径”三个研究内容，分别检索近 5 年中英文代表性文献，用来写立项依据。

YILA 同时检索了万方、OpenAlex 和 Google Scholar，去重后留下 57 篇，按”现状、影响机制、实践路径”三块各挑出代表文献，还附了一份 Excel 候选文献池。它也老实告诉我：英文文献里直接研究中国思政课的很少，适合当作”国际参照”来引用。这种提醒，比硬塞给你几篇不相关的英文文献有用多了。

场景二：中英文文献一次搜齐

帮我检索近 5 年关于”短视频使用与大学生睡眠质量”的中英文实证研究，中文和英文各列出代表性文献，优先高质量期刊。

结果分成中文、英文两张表，每篇都标了样本量和期刊信息，比如 Frontiers in Psychology（JCR Q1）、Acta Psychologica（JCR Q2）。它还提醒：现有研究大多讲的是”成瘾或问题性使用”，而不是普通的刷视频时长。

场景三：临床或药物方向的研究进展

查找近 5 年 SGLT2 抑制剂治疗心力衰竭的研究进展，优先随机对照试验、系统综述和指南，按”疗效、安全性、适用人群”分类整理。

这次它检索了 PubMed，挑出来的是 DELIVER（NEJM 2022）、EMPULSE（Nature Medicine 2022）、2023 年 ESC 指南更新这些硬核证据。它还主动提醒：DAPA-HF、EMPEROR 这类奠基性试验在 5 年时间窗之外，需要的话要单独补。

场景四：刚进入一个新方向，先补经典文献

我是刚转到公共管理方向的研究生，想了解”社区韧性”这个概念。请先给我奠基性的经典文献，再补近几年的代表性研究，帮我建立这个领域的基本脉络。

它没有直接甩给我一堆论文，而是先给了一条阅读路径：概念奠基、社会资本与协同治理、中国情境下的应用。经典部分从 Norris 等人（2007）、Aldrich & Meyer（2014）读起，每篇都写了”为什么读”，最后还建议”如果只读三篇，就读这三篇”。对刚转方向的同学来说，这比一份长长的书单友好得多。

场景五：查某项技术的相关专利

我在做钙钛矿太阳能电池封装方向的研究，想了解这项技术的专利布局。请检索近 5 年中国和全球的相关专利，按技术路线分类整理，列出主要申请人，并说明每类专利主要解决什么问题。

这次我用的是 YILA 的专利助手。它同时检索了万方专利和 Google Patents，把结果分成了 9 条技术路线：有机/无机交替薄膜阻隔、专用封装胶膜、低温与光固化工艺、边缘密封、柔性超薄封装、封装设备等，每一类都写清楚了主要解决什么问题，比如水氧渗透、层压损伤、边缘渗漏。申请人这块，国内有极电光能、天合光能、南开大学、华中科技大学等，国外有宁德时代、韩华、Jusung 等。

更难得的是，它很清楚自己的边界：这里列出的是”值得跟踪的申请人”，不是按专利数量做的排名；海外专利的同族关系也没有核实完整；而且这不能当作侵权风险判断（FTO）来用。

不管用哪个工具，拿到结果以后都要做两件事：随机抽几篇，回到数据库核对论文是否真实存在；再看看有没有漏掉你知道的重要论文。

04｜方式二：给 Agent 接入论文 API

如果你动手能力比较强，也可以给自己的 Agent 接入论文 API。

这些是我用过、觉得比较好用的三个：

  • | API | 收费方式 | 能搜到什么 |
  • | — | — | — |
  • | OpenAlex | 免费，申请 key 后每天有 1 美元的免费额度 | 3.2 亿多篇学术作品的信息：题目、摘要、作者、机构、被引次数、开放获取链接 |
  • | Semantic Scholar | 免费（申请 key 后限速更稳） | 2.14 亿篇论文信息、24.9 亿条引用关系，还有 AI 生成的一句话摘要（TLDR） |
  • | SerpApi | 每月 250 次免费，入门档 25 美元一个月 | Google Scholar 的检索结果 |

下面一个个说清楚：它们到底收录了哪些论文。

一、OpenAlex：覆盖面最广的“学术总目录”

**收录多少：**官方说法是 3.2 亿多篇作品，每天新增几万篇。“作品”不只是期刊论文，还包括会议论文、书和章节、数据集、学位论文、预印本等。

**数据从哪来：**最早是接手了微软学术（Microsoft Academic Graph，2021 年停止）的数据，另一大来源是 Crossref（管 DOI 注册的机构）。另外还汇集了 PubMed、DataCite、HAL，以及各个大学和学科的知识库。

同一篇论文的 arXiv 预印本、正式发表版、学校知识库里的版本，它会尽量合并成一条，不用自己去重。

**能拿到什么：**题目、摘要、作者、机构、期刊、被引次数、参考文献、是否开放获取。按我这次查的数字，有摘要的大约 1.7 亿篇，开放获取的大约 1.3 亿篇。

还有一个很多人不知道的：对 6000 多万篇开放获取论文，OpenAlex 自己缓存了全文 PDF，能直接下载（下载按次计费，每天免费额度大约够下 100 篇）。

**中文论文：**按语言字段筛，中文作品大约 590 万篇。相对它的总量，这个比例很小。中文核心期刊、国内学位论文，还是要去知网、万方查。

**使用建议：**做综述、摸清一个方向的整体情况时首选它。按年份、期刊、机构筛选很便宜，适合让 Agent 做“某方向近 5 年发文趋势”这类统计。

OpenAlex 每天 1 美元，能搜多少次？

很多同学看到“1 美元”会担心不够用。按 OpenAlex 官方给的标准：

  • **关键词检索：**每天大约 1000 次。每次最多返回 100 条结果，一天就是 10 万条；
  • **按条件筛选（比如按年份、期刊筛）：**每天大约 1 万次；
  • **用 DOI 查单篇论文：**不限次数，免费。

**官方还给了一个参考：**一天做 20 次检索、200 次筛选、50 次单篇查询，大约只花 0.04 美元。所以对一般的文献检索来说，完全不用付费。

额度每天北京时间早上 8 点（UTC 零点）刷新。另外要注意，它对调用频率有限制：用免费 key 每秒最多 30 次请求，不带 key 只有每秒 10 次，而且每天的额度只有十分之一。新注册的账号，第一笔 1 美元的额度还会限速使用，大约 50 分钟后才解除。如果 Agent 提示“请求太多”（429 错误），等一会儿再试就好，不会额外扣费。

二、Semantic Scholar：查引用关系最顺手

**收录多少：**官方页面写的是 2.14 亿篇论文、24.9 亿条引用关系、7900 万位作者，数据持续更新。

**覆盖哪些学科：**所有学科都有，每篇论文会标学科领域，可以按领域筛。

它的特色：

  • **引用网络。**一篇论文引用了谁、被谁引用，都能直接拿到。顺着引用链往前、往后找文献，很方便。
  • **TLDR。**很多论文有一句话 AI 摘要，扫一遍就知道这篇在讲什么。
  • **相似论文推荐。**给它一篇论文，它能推荐一批相近的。
  • **开放获取 PDF 链接。**有免费版本的论文，会给出 PDF 地址。

**要注意两点：**一是摘要可能缺失，官方说明因为版权原因，有些网页上能看到的摘要，API 里不返回；二是关键词检索最多只返回 1000 条按相关度排序的结果，要更多得用它的批量检索接口。

不申请 key 也能用，但所有没 key 的用户共享一个限速池，高峰期容易被拒；申请 key 后起步是每秒 1 次请求。

**使用建议：**已经有几篇核心论文，想“滚雪球”找相关文献时用它。

三、SerpApi：间接用上 Google Scholar

Google Scholar 本身没有官方 API，官方帮助页也明确说不提供批量获取。SerpApi 是第三方服务，帮你抓取 Google Scholar 的搜索结果页，整理成结构化数据。

所以它能搜到什么，基本就等于 Google Scholar 能搜到什么：期刊文章、学位论文、书、摘要、法院判例，来源包括出版社、学会、在线知识库、大学网站等。

**能拿到什么：**标题、作者、来源、片段（不是完整摘要）、被引次数、“被谁引用”和“所有版本”的链接，可以按年份筛。拿不到全文，Google Scholar 自己也说，多数文章摘要免费，但全文可能需要订阅。

每次请求最多返回 20 条结果，按成功的检索次数计费，返回多少条都算 1 次。

SerpApi：用量大再考虑

SerpApi 每月有 250 次免费检索，入门档是 25 美元一个月、1000 次。它是订阅制，当月没用完的次数，下个月就清零了。

**使用建议：**OpenAlex 和 Semantic Scholar 搜不到的东西（比如某些书、学位论文、小众会议），再用它补漏。

另外两个免费的，按需取用

  • **PubMed（E-utilities）：**生物医学方向必备，收录 4000 多万条文献题录和摘要。
  • **arXiv API：**物理、数学、计算机等方向的预印本，能直接拿到全文 PDF。官方要求每 3 秒最多请求 1 次，让 Agent 写代码时记得加等待。

怎么选？

  • | 你的需求 | 用哪个 |
  • | — | — |
  • | 摸清一个方向的整体情况、做统计 | OpenAlex |
  • | 从几篇核心论文出发找相关文献 | Semantic Scholar |
  • | 想要 Google Scholar 那样的结果，补漏 | SerpApi |
  • | 生物医学 | 再加 PubMed |
  • | 计算机、物理等看最新预印本 | 再加 arXiv |
  • | 中文文献 | 这几个都不够，还是知网、万方 |

我的习惯是：OpenAlex 打底，Semantic Scholar 顺引用链补充，SerpApi 留着补漏。

有一点要说清楚：API 搜到的主要是论文信息，不是全文

题目、摘要、作者、DOI 都能拿到。开放获取的论文，OpenAlex、Semantic Scholar、arXiv 能给出全文链接；但付费论文的全文，还是要通过学校图书馆的权限下载。

怎么接入？

接入其实不麻烦：找到 API 的官方文档，直接交给 Agent，让它自己写调用代码。

  • OpenAlex：https://developers.openalex.org
  • Semantic Scholar：https://api.semanticscholar.org
  • SerpApi：https://serpapi.com/google-scholar-api
  • PubMed：https://www.ncbi.nlm.nih.gov/books/NBK25497/
  • arXiv：https://info.arxiv.org/help/api/

注意：不要把 API key 直接发给 Agent

API key 相当于你的账户密码。别人拿到你的 key，就能用你的额度。直接粘贴在对话框里，它会留在聊天记录里，不太安全。

更稳妥的做法是：

  • 如果工具提供了专门填 key 的输入框，就填在输入框里；
  • 如果没有，就把 key 写进项目文件夹里的 .env 文件，让 Agent 写的程序从这个文件里读取，并告诉它不要打开、不要显示这个文件。

05｜三个工具，分别怎么配置

Grok Bot：我觉得最丝滑的方式

整体用下来，我觉得用 Grok Bot 接入 API 是最快的。整个过程只要三步。

**第一步，新建一个专门搜论文的 Bot。**我给它起名叫“论文搜索助理”，以后搜论文都在这个 Bot 里进行。

**第二步，直接告诉它你要做什么。**我只说了一句：“我想通过 API key，然后搜索 OpenAlex 的论文。帮我去设置一下。”

它会直接弹出一个填 key 的输入框，并且提示 key 会被安全保存，Bot 本身看不到。这正是前面说的“专门填 key 的输入框”，不用自己处理文件，也不用把 key 发进对话里。

**第三步，保存后直接开始搜。**保存好 key，它会自动测试一次：用“large language models peer review”检索，返回了排在前面的论文和被引次数，还告诉我这次查询花费 0.001 美元。

按这个价格，每天 1 美元的免费额度，差不多就是前面说的约 1000 次检索。

之后我接着问：“帮我搜索一下人工智能在媒体中相关应用比较火的论文。”它按被引次数排序，列出了 2018 年以来这个方向引用最高的论文，每篇都附了年份、被引次数和一句话说明。

Codex：还能顺手做一个检索网页

在 Codex 里，我先说了需求：“我要搜索 OpenAlex 的论文，然后我一会可以给你一个 API key，帮我接入以后帮我去搜论文。”

它先提醒了一点：OpenAlex 的 key 也是登录凭证，不要写进代码或公开文件里，会优先放进本地环境变量。然后列出需要我准备的内容：API key、检索主题、筛选条件（年份、期刊、引用量等）和结果格式。

这里注意，Codex 说的是“你发来后”。按前面说的原则，key 最好不要直接粘贴进对话，而是自己写进 .env 文件，再告诉它从环境变量读取。

接着我又提了一个需求：“帮我做一个网页，然后每次我可以在本地自己通过这个 key 搜索论文。”

大约 4 分钟，Codex 做好了一个本地检索网页：输入关键词就能搜，可以按年份、开放获取和文献类型筛选，结果能导出成 CSV 或 BibTeX，key 在网页的“API 设置”里填写。以后搜论文，打开这个网页就行，不用每次都和 Agent 对话。

WorkBuddy

WorkBuddy 的用法和 Codex 基本一样：把 API 文档交给它，key 放进 .env 文件，再让它写检索脚本。所以这里就不重复截图了。

写在最后

文献检索是整个科研流程的第一步，也是最容易被 AI “带偏”的一步。

工具搜不到，不代表论文不存在。用 AI 检索文献，最重要的不是找到一个“最强的工具”，而是知道你的工具能搜到哪里、搜不到哪里。
