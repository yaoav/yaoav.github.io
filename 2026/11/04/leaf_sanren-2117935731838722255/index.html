10 万人看过的 Grok Bot 省额度帖，背后是这一整套带 Bot 的方法

发表于2026-11-04|行业观察
|浏览量:

本文转载自 X 博主 @leaf_sanren（Leaf Yeah!） 的长文，原文链接，版权归原作者所有。

Grok Bot 天机泄露，完整版来了！！😮

上周写的额度机制，10.9 万人看了、1000 多人收藏👇

评论区问得最多的是：到底该怎么带 Bot？

正好 Grok Bot 的明星工程师 @poteto（土豆女神）把自己的用法全讲了一遍。我一条条对过去：我踩过的坑，她几乎都给过解法；她没讲的，是国内用户才会踩的坑。

这篇就把两边合在一起：她的方法当骨架，每一条配上我的实测和翻车现场。

小目录

  • 1｜先想清楚：哪些活交给 Bot，哪些留给你
  • 2｜起步：先把一个 Bot 用透（信任四步）
  • 3｜额度：每一步都在花钱
  • 4｜记忆：别信它的记性，信文件和代码
  • 5｜组队：Bot 不用多，几个好的就够
  • 6｜闭环：交活必须带证据，最后一步留给你
  • 7｜国内用户才会踩的 4 个坑
  • 8｜一页速查 + 7 天上手

这篇也可以直接丢给你的 Bot，让它照着帮你配置。

───

1. 先想清楚：哪些活交给 Bot，哪些留给你

poteto 每次分享，都会绕回同一个词：信任。

她在 X 演讲里说过这么个意思：你没法从 1 个、5 个智能体走到 100 个，是因为你还不信任它们干的活。

不信任的时候，开 100 个 Bot，只会得到 100 份要返工的东西。

所以第一步不是多开 Bot，而是问自己一句她常问的话：

这件事里，哪一步还非得我来？

你还在复制粘贴、还在替它转述上下文、还在一条条检查，那一步就是你在当瓶颈。

我自己的分法很简单：

  • 交给 Bot： 找、填、盯、催。报名、填表、走售后、领券、盯数据。
  • 留给自己： 判断、表达、付钱。

我买的代理 IP 被标成了机房段，就让 Bot 自己登进后台，去跟客服谈换货。它谈完一轮发现换来的还是机房段，又自己回去二次交涉。

把报名、填表、售后交给它以后，我邮箱里的报名成功和退款邮件就没断过😂

但付款那一下，永远是我自己点。为什么这么分，第 6 节细说。

───

2. 起步：先把一个 Bot 用透

她给新手的第一条建议：先只用一个 Bot。 别一上来就搭一个团队。

起步只做三件事：

  • 像带实习生一样先自我介绍。 你是谁、平时干什么，然后问它能帮你自动化哪些。
  • 把工具都给它。 连上连接器、用 Vault 存登录信息；还可以让它给自己开个邮箱、注册自己的账号，和你的分开。
  • 语音倾倒，再让它复述。 这是她最爱的一招：开语音一口气把想法倒出来，最后让它「用你自己的话复述一遍」。

不复述就开工，它理解偏了，你要等到交活才发现，额度已经花出去了。

然后是她方法里最核心的「信任四步」：

看着它做 → 存成技能 → 测一次做对 → 设成例行。

我那套让 Grok Bot 点美团外卖的 skill，就是这四步一步步磨出来的。

第一步，看着它做。 第一次跑就翻了三次车：

  • 我说送到”某某健身房”，地址簿里没有这个名字，它就想去地图上新建一个地址。饭送错地方，钱还是你付。
  • 点”再来一单”，原单 5 样菜，进购物车只剩 2 样。
  • 订单详情页的时间和列表差了约 15 小时，它据此判断我今天吃过什么，给我推了一顿重样的。

第二步，存成技能。 每一次翻车都变成一条限制：只从地址簿选地址、逐项对照原单、时间以列表为准、先勾最大红包再报价。最后整理成开源的 grok-eats。

第三步，测一次做对。 只说一句”晚饭吃点高蛋白的”，它从选店到勾红包，一路走到收银台。不勾红包 ¥41.6，勾上 ¥24.6。

第四步，设成例行。 这一步我故意没开。我点外卖挑，”每天 11:30 推候选”这个模块默认是关的。

能设例行，不代表该设。第三步还不够稳，就别进第四步。

───

3. 额度：每一步都在花钱

poteto 在 10-31 那条带队指南的评论区，自己补了一句很实在的话：

例程跑太勤会很贵。定时的最多每小时一次；订阅式的，先把事件过滤一遍。

这跟我额度那条帖子算的账完全对得上：

  • 每 15 分钟跑一次 = 一周 672 次唤醒
  • 每小时一次 = 168 次
  • 一天 3 次 = 21 次

没有任何变化，也照样扣。

为什么这么贵？ 我扒了自己一个半月（9-15 到 10-30）的用量后台：

  • 所有 Bot 的聊天调用，一共 6952 次
  • 90% 的 token 花在重读已有的上下文上，真正写出来的不到 1%
  • 最夸张的一次：读了 21.6 万 token，只写了 55 个

Bot 每走一步，都要把整段历史重读一遍。聊得越久、跑得越勤，越贵。

她的第二条：能写成脚本的，别让 Bot 手动做。

有海外玩家拿同一个网站实测过（@Michael_Fenech_）：

  • 让 Bot 截图、点点点：约 21.3 万 token
  • 在浏览器里跑脚本：约 5.1 万
  • 纯脚本执行期间：模型 0 token

我的做法再往前一步：Bot 当包工头，别当搬砖工。

我在它的云电脑里装了 Grok CLI 和 Codex CLI，重活让 CLI 跑，Bot 只负责调度。X Premium+ 送的 Super Grok 额度、这个月忘了退订的 Codex，就这样都榨干了hhh

一个坑： 要给足文件和执行权限，不然 CLI 根本跑不起来。

另一个坑我天天踩： CLI 跑完没有提醒，Bot 派完活就睡了，经常忘了回来验收，你就干等半天。解法是 Webhook 叫醒：CLI 一跑完就把 Bot 叫起来，范凯和一泽都开源了现成的。

───

4. 记忆：别信它的记性，信文件和代码

这一节她讲得最狠。

她给”怎么让 Bot 别再犯同样的错”排了个倒金字塔（10-16 那条长推，75 万浏览），越往上越靠得住：

  1. 改结构： 代码和架构本身就不让它错
  2. 自动检查： lint、测试、CI
  3. 写成规则： AGENTS.md、Skill 这类写在纸上、没法强制的东西
  4. 靠人盯： 她的评价是 ngmi（没前途）

写在纸上的规矩只排第三，你每次手动纠正排在最后。

我在记忆上的翻车，正好一条条印证：

  • 我把”每个 Bot 都要写 summary 和 run log”写进共享记忆，结果它们想起来才做。官方说的共享记忆，只是名字、时区这类少量事实；记忆是按需调出来的。
  • 记忆越用越乱。今天派了什么活就单独记一条，不合并也不去重；同一条规矩改过三次，三个版本都留着。
  • 它只记结论，不记过程。哪个方案被否了它不记，下次一问又端上来🥲

对应的解法：

  • 所有 Bot 都要守的规矩，做成例行任务或 Skill，别写进记忆。
  • 任务收尾让它写一份决策记录：选了哪个、没选哪个、为什么，存成文件。
  • 聊了好几天的 Bot，用 Reset chat：聊天清掉，记忆、Skill、文件都还在。别直接 Duplicate，复制出的新 Bot 会把学到的记忆丢掉。
  • 价格、功能这种会变的事，只让它记”去哪查”，答之前先打开来源。

她还有个提醒我觉得特别准：坏习惯会传染。

Bot 很爱模仿已有的东西。一个临时凑合的写法，几天就被别的 Bot 抄得到处都是。所以你给 Bot 的模板、参考文档，要像拔草一样定期清理。

───

5. 组队：Bot 不用多，几个好的就够

她的原话很直接：几个好 Bot，比一大队好管。

一个好 Bot 的标准：

  • 只干一件事，只有一种语气
  • 写清楚它不该做什么
  • 不给它用不上的工具
  • 你只跟”幕僚长”说话，由它去分派

她还专门做了一个”设计 Bot 的 Bot”，叫 Dr Eggbot，加进团队就能让它帮你设计其他 Bot：

https://x.ai/bot/_jOdbfkB16zxu7MRcmReE

组队这块，我踩过两个烧额度的坑：

别开 Bot 群聊。 群里每条消息，每个 Bot 都要读一遍。铁柱转述过一个团队账号的数据：约三分之一的轮次，是 Bot 在互相叫醒。

别让主 Bot 一次给所有 Bot 派活。 我有个定期更新记忆的任务，主 Bot 每次给所有 Bot 群发一遍，每个 Bot 就各自把文档重新总结一遍。可它们平时已经总结过了，这一轮纯属重复烧额度。

───

6. 闭环：交活必须带证据，最后一步留给你

她在长文《Loops You Can Trust》里的意思是：一段听起来头头是道的解释不算数，摆在眼前的产出物才算。

直播里她干脆定成了硬规定：每一次提交，都要附上视频或截图。

放到日常也一样：让 Bot 交活时附截图、链接、前后对比，你扫一眼就能判断，不用从头查一遍。

设计一条闭环，她给了 4 个问题：

  1. 什么信号触发它？
  2. 每一步由谁做？
  3. 每一步交什么证据？
  4. 哪一步保留你的否决权？

我的外卖流程就是照这个设计的：

  • 确认页的店、每样菜、地址、用了哪些券、券后合计，全部读回给我
  • 做成 A/B/C 选择题等我拍板
  • 我说”提交”它才提交，提交完就停在收银台
  • 付款，我在手机上自己点

最后那一步留在你手里，它就算选错了，也只是一单没付的外卖。

还有一条：先小样本，再放量。

我们想用 Grok Bot 做一个 X 帖子里能直接玩的小游戏。动用 Bot 额度之前，先做了个 demo 自己试玩，两次都觉得不好玩，直接砍了。

省下来的，是一整周的额度。 poteto 自己用 Bot 做游戏，80% 的时间也花在试玩和给 Bot 反馈上。

7. 国内用户才会踩的 4 个坑

这几条，官方工程师不会讲，因为她用不到。

坑 1：云电脑的出口 IP，不一定在美国。

官方口径（@grok 11-03 的回复）：云电脑跑在美国，默认走机房的共享出口；只有你在电脑客户端的设置里打开”通过本机路由”，它才改用你本地的网络。

我让 Bot 自己查过：出口在美国，机房 IP，而且跟上次查的不是同一个。

但社区里，Kin 和铁柱这两周都在说 IP 乱飘，有人的出口直接变成了国内、香港。

IP 一乱，三件事会出问题：

  • 在云电脑上跑 Claude Code 不稳定。铁柱已经直接劝大家别这么接了。
  • 在云电脑登录谷歌、X 这类账号，怕 IP 对不上被封。有人重置了 Bot 帮他注册的 Gmail 密码，号当场没了。
  • 反过来，用美国机房的 IP 去刷抖音、小红书，会被限流。

怎么办：

  • 手机、电脑用 Bot 时，都开着美国梯子。
  • 要登录重要账号、或者上国内平台，用电脑客户端打开”通过本机路由”。注意它只管浏览器，Shell 命令和连接器还是走云端；客户端一关就断。
  • 非要在云电脑上跑 Claude Code，Kin 的方案是再套一层美国静态住宅 IP。

坑 2：额度不够，先别急着升级套餐。

现在是大一统订阅：Grok、Grok Bot、Cursor 共用一个每周池，$30 的 Premium 起才有 Bot。多订几份不叠加，只按额度高的那份算。

我的做法是第 3 节说的：让 Bot 装上 Grok CLI、Codex CLI，把已经付过钱的额度先用满。

坑 3：国内服务大多没给个人开放接口。

比如美团，没给个人开放外卖下单的接口。能走连接器、API 的一定先走；走不了，就让 Bot 用云电脑的浏览器去点网页版，再用 Skill 把每一个容易翻车的地方写死。

国内的生态也在一点点接上，铁柱一个人就做了俩：

  • Grok Bot Clipper 浏览器插件：刷抖音、小红书看到好内容，直接分享给你的 Bot。
  • Grok Bot Anywhere：把 Grok Bot 和微信打通（Mac，内测中）。

坑 4：让 Bot 批量运营账号，难的从来不是内容。

我用 Grok Bot 做 TikTok 矩阵，一开始 5 个号全被限流，后来养回来 3 个，有 1 个 0 粉也拿到了破千播放。

批量出爆款素材是最简单的；难的是账号的 IP、运维和养护。 这部分 Bot 帮不了你太多，跟坑 1 是同一个根。

───

8. 一页速查 + 7 天上手

她说的 12 条，和我实测对上的地方

  • 一切关于信任 → 我：先交找、填、盯、催，付钱永远自己来
  • 你就是瓶颈 → 我：还在复制粘贴的那一步，就是该交出去的
  • 先只用一个 Bot → 我：外卖这一件事，就磨出了一个 skill
  • 语音倾倒，让它复述 → 我：复述对了再开工，省一轮返工
  • 信任四步 → 我：外卖走完了前三步，第四步故意没开
  • 例程最多每小时一次 → 我：每 15 分钟一次 = 一周 672 次唤醒
  • 能写脚本就别手动 → 我：Bot 只调度，重活交给 CLI
  • 好 Bot 只干一件事 → 我：别开群聊，别让主 Bot 群发派活
  • 交活必须带证据 → 我：确认页全部读回，做成选择题
  • 每一步都能叫停 → 我：提交完停在收银台
  • 倒金字塔：能强制的别靠规则 → 我：写进共享记忆的规矩，它想起来才做
  • 每次纠正都是信号 → 我：每一次翻车，都改成 Skill 里的一条限制

7 天上手

  • 第 1 天： 自我介绍，连上你常用的工具；语音讲一遍你的工作，让它复述。
  • 第 2 天： 挑一件每天都有、只读不发、错了也没损失的事，比如每天领外卖券、每天一份 X 摘要。看着它做，当场纠正。
  • 第 3 天： 让它把你纠正过的标准存成 Skill，推到私有 GitHub 仓库。
  • 第 4–5 天： 只说 Skill 的名字，看它能不能不用你纠正就做对。
  • 第 6 天： 设成例行任务，最多每小时一次。
  • 第 7 天： 抽查这一周的产出，找反复出错的地方，改 Skill，而不是每次骂它。

第一件事跑稳了，再用同样的四步交出第二件。
