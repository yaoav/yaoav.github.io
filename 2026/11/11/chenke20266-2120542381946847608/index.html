我把前几天那Polymarket机器人改了下，这个还是AI给我的，它觉得这样最务实。于是我就改下，还跑了几天

我想要的不是「自动赚钱」，是「不用每天早上想着今天该领哪个水」。先说结论：能自动的只有「检查」和「打开页面」，真正决定成败的三步必须你亲手做。这不是技术做不到，是安全边界——一旦越过，被偷的不是一次空投，是钱包里的全部。

整套系统没有数据库，只有两个文件：

data/tasks.json 是给人看的任务清单，data/airdrop_log.json 是运行历史（只留最近 90 条）。三个文件都能直接用记事本改，不需要重启。

判断「要不要领」就是一个阈值比较，没有任何模型参与：

balance() 就是一次 eth_getBalance 的 JSON-RPC 调用，不花 gas、不需要授权。

四、需要领水时：五个状态

一旦判定要领，runner 会另起一个进程跑 airdrop_auto.py。它是个状态机，每个状态写进 data/auto_state_.json：

python scripts/airdrop_auto.py –start –project push
python scripts/airdrop_auto.py –status –project push

–start 之后它做的事很无聊：打开一键加网络页面 → 等 10 秒 → 打开水龙头 → 每 15 秒查一次余额 → 余额涨了就打开任务页。

为什么要写盘：中途关了、钱包卡了、网断了，重开后 –status 能看到卡在哪个状态，而不是从头再来。

15 分钟超时是刻意的。等太久说明水龙头有问题（或者你压根没去点），继续等只是浪费。

五、安全筛查只做四件事

check_site() 是我最不放心、也最值得写的一段。它检查四样：

为什么值得单列：空投是钓鱼的重灾区。假水龙头、假任务页、假官方推文，目的一律是让你连接钱包然后签一笔授权。

四件事各有分工：

  • 白名单挡「你贴错链接」
  • 跳转检查挡「官网跳到一个看着很像的域名」
  • 标题检查挡「域名对但页面被换掉」
  • HTTPS 是底线，不是保障

这套检查不完美，但它把「一眼假」的挡在了自动打开这一层。

三个数字：

push 在 11/10 09:02 被判「余额不足」并自动打开页面，09:09 再查已经是 0.99，11/11 变成 1.99——两次领取都到账了。arc 一直 39.8，因为它的水龙头门槛就是 20，早就够了，所以从来没触发过领取。

七、三个踩过的坑

站点检查失败 ≠ 项目死了

rome 连续三天 ok: false，没有状态码。这种「连不上」比「404」更值得警惕——可能是域名过期被抢注，也可能是网络问题。我的处理是降级到 dropped，但保留记录，过两周再看一眼。

同一天启动两次

11/10 的 09:02 和 09:08 各启动了一次 push 流程。原因很简单：09:02 那次余额还是 0，09:08 计划任务又跑了一轮，判断仍然是「不够」，于是又开了一次页面。

现在靠 data/airdrop_auto_armed.json 里的 armed 开关兜底，紧急情况改成 false 就只检查不动手。但正确做法应该是加幂等键（项目 + 日期），这是还没补的债。

门槛不能统一

push 是 0.5，arc 是 20。差 40 倍，因为两条测试网的代币面值完全不同。如果用一个全局门槛，要么 push 永远不触发，要么 arc 天天重复领。

八、为什么留着三个人工步骤

第三条还有个更现实的原因：项目方最终会审查地址行为。全自动、规律到秒、多号并行的地址，大概率在快照那天被剔除。你省下的那点时间，换来的是零。

九、复刻清单

  1. 建一个一次性钱包，私钥放 .env 的 BURNER_PRIVATE_KEY，别用主钱包
  2. 写 data/projects.json，每个项目至少填 id / stage / official / faucet
  3. 配 BALANCE_RPC：每个项目一条 RPC + 一个「够用」的余额门槛
  4. 挂计划任务，每天固定时间跑 airdrop_runner.py –auto
  5. 观察一周，看 airdrop_log.json 里的 actions 和站点检查结果

十、几句实话

  • 空投的期望值：单个项目 $10~200，周期 1~6 个月，大多数会归零
  • 它不产生现金流，是用时间换一张彩票
  • 多号刷量（女巫）不是效率更高，是直接取消资格
  • 任何要助记词、要预付费、要你先授权再领的，一律是骗局
