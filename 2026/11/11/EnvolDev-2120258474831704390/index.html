The AI Masterclass: Why the Best Model Is Rarely the Right One

发表于2026-11-11|行业观察
|浏览量:

本文转载自 X 博主 @EnvolDev（Tony） 的长文，原文链接，版权归原作者所有。

How to build real things with AI, and which model to use for each job: from your first prompt to your first app to a team of agents.

I don’t write code. I build by directing AI agents: 3D films, SaaS tools (online software people subscribe to), iOS and Android apps, even the desktop app I run all my agents from and the benchmark app I test every model in.

Six months ago, I couldn’t do any of this. In May 2026, I knew nothing about coding or AI agents. It took me less than three months to build my first app, Laeli, and I launched it on July 21. Today I work at a really advanced level. If I can do it, anyone can.

Not knowing is no longer an excuse. Don’t understand something? Ask your agent. It never sighs, never judges and never gets tired of explaining. If you remember one thing from this masterclass, remember that.

An AI agent is an AI that doesn’t just chat: it works on the files on your computer, runs programs and checks its own work. You’ll meet them properly at level 3.

This masterclass is for anyone who wants to do the same: learn to code with AI, vibe code your first app (build it by describing it in plain words), or just get real work done. It takes you step by step: which AI to use for each job, what it really costs, how to build without writing code, and how to run a team of AI agents. No experience needed.

Everything in it comes from my own work. Since September I’ve given the same tasks to more than 12 AI models, over 70 runs. That’s what a benchmark is: the same test for every model. Most were short 3D films the model had to code in Three.js (3D code that runs in a web page) and then render in 4K (turn into finished video frames); some were video games. I kept track of what each one cost and how long it took.

Why films and games? They’re the fastest way to compare quality, cost and time: one look shows which model did better. That’s how I learned which model to trust with what, and how to put each one to work on real tools, apps and everything else in this masterclass.

Those runs taught me one thing above all: the best model and the right model are rarely the same one.

My main AI model is still Claude Opus 5.5 (@claudeai), even now that Fable 5.2 is out. Why, and when it shouldn’t be yours, is in here.

Just out: Fable 5.2. Anthropic, the company behind Claude, released Fable 5.2 yesterday, Nov 9: its most capable public model, faster and 20% cheaper than Fable 5.1. I tested it the same day. The last part of this masterclass puts it through everything you’re about to learn, with every result, cost and time, so it comes last.

And one more, just in: about two hours before I posted this, Google released Gemini 4 Carbon, its strongest model. It’s already running through my benchmark. More at the end.

What you’ll learn, in order

It’s one class, from start to finish. Each part builds on the one before, so read it in order, even the parts that look too basic or too advanced. Here’s the path:

  1. Meet the models. Who makes which AI, and what each one is good at.
  2. Climb the five levels. From your first good question to running a team of AI agents.
  3. Build something real. Seven steps to your first app, even if you’ve never written code.
  4. Understand the cost. The six words that decide your bill, and why the cheapest model isn’t always the cheapest job.
  5. Know what to pay for. Which plan to buy, and when an upgrade is worth it.
  6. Pick a model for each job. Design, coding, writing, research, data, images and video.
  7. Test it yourself. Did a model get worse? How to check with your own prompts.
  8. Write a brief that works. The one prompt I share, taken apart piece by piece.
  9. Run a team. One lead model, cheap helpers and a fresh pair of eyes to check the work.
  10. Avoid costly mistakes and keep up. Seven habits, and how to stay current when model names change every month.
  11. Final test: Fable 5.2. Anthropic’s newest model, checked against the rules in this guide.

Along the way, you’ll see what I saw: the same film costing $26 or $682 depending on one setting, a half-price model run up the bigger bill, a kart-racing game balloon to $154.83, and a top model skip the job and call its image generator in 81 seconds.

The cheat sheet near the end, just before the final test, puts it all on one page. It’s a reminder, not a shortcut: it only makes sense once you’ve read the rest.

How to read my numbers

  • Dollars: what each run would cost at the makers’ pay-as-you-go prices (their API, the pay-per-use way developers plug a model into their own software), not what I paid. I run my work on monthly subscriptions, and part 5 explains why that matters.
  • Time: how long each run took, from my logs.
  • Same prompt for every model on each film. Each model ran in a coding app, the agent apps you’ll meet at level 3: Claude in Claude Code, GPT models in Codex, most others in OpenCode. So every result is a model plus its app.
  • From scratch, every time. Every run starts in a fresh, empty folder, and my briefs forbid importing any existing film or prebuilt scene. The model builds everything itself.
  • One shot per film. One prompt, one run: the film you see is what that run made.
  • Quotes with no name are mine, from my posts and replies on X.

Before we start: talk to your AI, don’t type

This one habit changed my work more than any model. I don’t type to my agents. I press a button and talk, the way I’d explain the job to a person. Speaking is much faster than typing, and you naturally give more detail. For me, it multiplies my speed 10 to 20 times.

My agent workspace has voice input built in. You don’t need my app: a dictation app like Wispr Flow, one of the best out there, lets you talk into any chat or coding agent.

Then let an AI write the prompt for you. I built an agent that takes my rough idea, spoken or typed, and gives me back the best vibe-coding prompt possible. Mine is much more detailed and advanced, but this one is a great place to start, in any chat:

Who makes what, in 30 seconds

Think of it as casting a film. You’re the director; each maker offers a lead, a workhorse and a budget hire. Facts and prices as of Oct 30, 2026 (Fable 5.2: Nov 9; Gemini 4 Carbon: Nov 10).

A price like “$8 / $40” is per million tokens, the small chunks of text an AI reads and writes: the first number is what it reads, the second what it writes. The cost section explains why that matters.

One thing that confuses everyone: the model and the app aren’t the same. The model is the brain: Opus 5.5, GPT-6.1 Sol, Gemini 4 Argon. The app is where you talk to it: Claude, ChatGPT, Codex, Gemini. Most apps let you switch between their maker’s models.

Fable is Anthropic’s premium line: Opus 5.5 beat the older Fable 5.1 on Anthropic’s own tests, which is why Opus became the lead. That’s the cast. You don’t need to remember it all: most of this guide comes down to two names, Claude Opus 5.5 for design and GPT-6.1 Sol in Codex for code. Next: where you are today, and how to level up.

PART 2 OF 11

Five levels: start where you are, then climb step by step

Level 1 is for complete beginners. Level 5 is advanced: it’s how I work every day. Start where you are, get comfortable there, then climb one step at a time.

Level 1: Ask well

One task per chat. Say what you want, who it’s for and how you’ll judge the answer. Allow “I don’t know,” and check any fact that matters.

Quick win: give the same small task to two free models and compare. That’s my method in miniature.

Level 2: Give it memory

A short file of standing instructions the AI reads at the start of every session (each new conversation), so you never repeat yourself: CLAUDE.md for Claude Code, AGENTS.md for Codex and many others (coding agents like these are level 3). In a chat app, the same idea is called custom instructions, or a project. Claude Code’s docs say keep it under about 200 lines. Three are enough to start:

Pasting the same instructions again? Make them a skill, a saved recipe the agent loads when needed. My low-tech version: I ask an agent to “give me a prompt of what you’ve been doing exactly, so I can give it to another agent,” and paste the answer into the next one.

Level 3: Hand an agent a brief

A brief is the written description of the job. Coding agents (Claude Code, Codex, Google Antigravity, OpenCode) work in your project folder, run commands and check their own work. Claude Code comes with every paid Claude plan; Codex with ChatGPT Plus. To start one: install the app, open it in an empty folder, and type what you want (step by step in part 3). Give the agent a pass/fail check: a test (a small check it can run), a build (the app starts without errors), a screenshot to match. Without one, Claude Code’s docs warn, you become “the test suite”: the one checking everything by hand.

Level 4: Cast each job

One model per job, chosen by what the finished job costs: Opus for the look, a GPT coder for the code, a cheap model for the bulk work. Part 6 casts every job.

Level 5: Run a team

A lead model plans and reviews, cheap models work in parallel, and a different model checks the result. That’s where I work, and where the two big reviews happen: the deep review and the completeness review (part 9).

PART 3 OF 11

Build something real: vibe coding, step by step

The levels are how you use AI. This is how you build with it.

“Vibe coding” means telling an AI what you want in plain words and letting it write the code. Andrej Karpathy (@karpathy) named it in February 2025, and Collins Dictionary made it its 2025 word of the year. The vibes get you a demo. A loop gets you something people can actually use.

Where to build: four ways to use AI

People mix these up all the time, so here they are, from simplest to most powerful:

  1. The browser. ChatGPT or Claude on their websites. Great for questions, writing and ideas. Don’t build an app here: the chat can’t work on the files on your computer.
  2. The desktop app. Claude, ChatGPT or Codex installed on your computer. You can build real things here: Claude Code and Codex both run inside their desktop apps, and you can accomplish a lot. The builds tend to be simpler, though. If you want to build a really great SaaS or something more advanced, and run many agents at once, you want the next one.
  3. The terminal. The text window on your computer where coding agents like Claude Code, Codex and OpenCode live. You say what you want, and the agent works in your project folder: it writes the files, runs them and checks its own work. It looks scary at first, but it’s way better to work in, and easier than it looks. This is where you build.
  4. A workspace. An app that runs many agents side by side, sometimes called an ADE (agentic development environment). That’s what my agent workspace is: many terminals in one window, each with its own agent and its own task.

The terminal also lets you plug things in. An API key lets your agent use almost any model. MCP (Model Context Protocol) is a standard way to connect your agent to other tools, like GitHub, a database or your browser.

Real vibe coding is multitasking. It isn’t one chat doing one thing. It’s 15, 20, 30 tasks at once: one agent builds a feature, another fixes a bug, another reviews the code, another tests a different model. That means many terminals open at the same time, each on its own job. If you want to be a real vibe coder, that’s where you’re heading. No workspace app? Open two terminal windows, start an agent in each, and give each one its own task and its own files, so they never edit the same thing.

Your first 10 minutes

  1. Pick one coding agent. Claude Code comes with any paid Claude plan, Codex with ChatGPT Plus. Install it from the maker’s official site and sign in with your plan.
  2. Make an empty folder, called something like my-first-app, and open it in the app. In the terminal, you go into the folder and type “claude” or “codex”.
  3. Type your first job: “Build a simple to-do list page I can open in my browser. Tell me how to open it.”
  4. Read, then allow. The agent asks before it creates files or runs a command. Read what it wants to do, then allow it.
  5. Stuck? Copy the exact error and paste it back: “What does this mean, and what do I do?”

Start in the desktop app. Move to the terminal when you want several agents at once.

Seven steps from idea to shipped

  1. Pick one small, real problem. Yours or a friend’s: a tool for your job, a page for your business, a tracker, a small game. Small enough to finish in a weekend.
  2. Write a one-page brief. What it does, who it’s for, what “done” looks like. A seven-line template, with an example, is in part 8.
  3. Ask for the plan first. “Tell me your plan and which files you’ll create. Don’t build yet.” Fixing a plan is cheaper than fixing code.
  4. Build one piece at a time. One feature, then open it and click everything yourself. If something breaks, paste the exact error back.
  5. Save every working step. Ask the agent to commit (save a snapshot) to git each time something works. Git keeps every version on your computer, so any bad change can be undone in one step. GitHub is different: a website that keeps a copy online, private if you want, so nothing is lost if your computer dies. Ask: “Set up git and a private GitHub repository for this project.”
  6. Have a different model review it. “You didn’t build this. Find the bugs, the security holes and anything that breaks with real users.” The full reviewer prompt is in “Run a team.” Only one plan? A fresh session of the same agent works too: it didn’t watch the build.
  7. Put it online, then in front of one real person. Ask your agent: “Put this online so I can share a link. Use a free host, and walk me through every step.” Then watch someone’s first five minutes. You’ll learn more than from a week of prompting.

Protect what already works. Every time you ask for a change, add this line: “Do not break any functional code. No regressions.” A regression is when a new change breaks something that used to work. It’s one of my favorite lines to give an agent.

When it breaks, don’t panic. Paste the exact error, not “it doesn’t work.” If two fixes in a row fail, say: “Go back to the last version that worked.” That’s what the git snapshots are for. Then start a fresh chat and explain the problem from the beginning.

Learn to code while it builds. You don’t need to write code to start learning it. After each step, ask: “Explain what you changed and why, in plain words, for a beginner.” Read the answer every time, and code slowly stops looking like noise.

Keep secrets out of the chat. API keys (the passwords apps use to reach paid services), passwords and payment keys never go in a prompt. Keep them in a private settings file called .env, and make sure the agent lists it in .gitignore so it never gets uploaded to GitHub. Anything that takes logins or payments gets a security review from a fresh model before launch. Not sure what a .env file or .gitignore is? Ask your agent: “Explain .env and .gitignore to me like I’m a beginner.”

What I build this way: every film in this guide, my SaaS tools, my iOS and Android apps, and the two Mac apps I work in every day:

  • My agent workspace, the desktop app I run all my agents from. Claude Code, Codex and OpenCode sit side by side in one window, each in its own pane, with each agent’s tokens, estimated cost and usage limits in one place. Claude Code and Codex run on my two subscriptions. OpenCode is how I reach every other model: I connect it to OpenRouter, one account that gives access to almost any AI model from companies I don’t subscribe to, like DeepSeek, Kimi, MiniMax, Gemini or Muse, paid per use.
  • My benchmark app, built to run tests like the ones in this guide and compare the films side by side. You’ll see it in part 7.

I didn’t write the code for either one. I directed it.

Every level up, and every build, burns tokens. So before we cast anyone, here’s what you’re paying for.

PART 4 OF 11

Six words that decide what AI costs you (even on a subscription)

1. Tokens. Chunks of text. You pay for what you send, what the model writes and its hidden thinking, which Anthropic, OpenAI and Google bill as output: the second, pricier number in a price like “$4 / $20”. On a subscription, tokens drain your limit instead: Anthropic says how fast you hit it “depends on the model you use, how long your chats are, and how large your files are.”

From my runs: a 20-second rotor animation took Claude Opus 5.5 about 20.8 million tokens. Only 1.1% were output, yet output was about 41% of the bill.

2. Context window. The model’s working memory for one session: about 1M tokens for current Claude and GPT-6 models in the API, often less in chat apps. Bigger isn’t better: accuracy drops as it fills (Anthropic calls it “context rot”), and every turn resends the whole conversation. Fix: a fresh chat per task.

3. Effort. How hard the model thinks before answering. The dial runs low, medium, high, Extra High (xhigh) and max. In Claude Code you change it by typing /effort; in other apps, look next to the model picker. On SWE-bench Pro, a public set of real-world bug fixes, Anthropic reported that Opus 5.5 solved 87.4% of tasks at low effort for $0.11 each, and 96.7% at Extra High for $0.74. Each step up buys less. Opus defaults to medium; Anthropic pairs Extra High with agent jobs over 30 minutes and low with sub-agents (helper agents, covered in “Run a team”), but says to test on your own work. My Claude and OpenAI runs mostly used Extra High, one step below max. And not just my tests: everything I build, my apps, my SaaS tools, everything I use, runs on Extra High. For me, it’s the best overall for quality, cost and time.

From my runs: one film, four effort settings. My post on it drew 280K+ views, because everyone wants to know if effort matters.

Same model. Same prompt. $26 at High. $682 at Ultra.

Cathedral of Ice, same prompt: Claude Opus 5.5 at High, Extra High (xhigh), Max and Ultra

High: $26.01 · 2h 17m. Extra High: $45.97 · 3h 11m. Max: $84.93 · 3h 38m. Ultra: $681.91 · 10h 48m. Ultra cost 26 times High and 8 times Max, for one 25-second film. Ultra here means max effort plus ultracode, a Claude Code mode that puts whole teams of agents on the build and the review, not the Ultra plan.

My take: “Ultra looked best to me, but the improvement didn’t justify the extra cost and time.” Extra High is my sweet spot for quality, time and money, so it’s what I pick. GPT-6 Astra showed the same climb at a smaller scale on my Alpine Gold film: $8.99 at High, $59.75 at Ultra.

One caveat: the Extra High film ran on Oct 29. High, Max and Ultra ran together on Nov 3 and shared one Mac’s graphics chip, which slowed their renders.

4. Cached input. Because every turn resends the whole conversation (see #2), most of what an agent reads is a repeat. Makers keep a copy, the cache, and charge a steep discount for re-reading it: $0.20 per million tokens on Opus instead of $4. In my runs it was 97 to 99% of what the model read. Without the cache discount, the same tokens on that rotor run would cost about $87 instead of roughly $11.70.

5. Subscription vs API. A flat monthly plan vs paying per token. My figures are the API version: “I was running my sub! But you still get the rundown for what the API would have cost.”

6. Harness. The program wrapped around the model, like Claude Code or Codex. An analysis by Epoch AI, an independent research group, found the harness has “the single biggest impact” on benchmark scores. It also decides how much gets sent each turn, so the same model can cost differently in different apps. That’s why my results are a model plus its app.

Now for the number that fools almost everyone.

Price the finished job, not the token

Anthropic’s own cost guide: “Compare models on cost per completed task, not per token, because you pay for completed tasks.”

From my runs: GPT-6 Astra’s tokens cost 2.5x Opus 5.5’s, and 5x on cached reads, which are most of what an agent reads. Yet on the six clean head-to-head briefs in my October table, Astra was cheaper and faster every time. Opus made the better film every time.

Why? Appetite. On a four-stroke engine brief, Opus read 14 times as many cached tokens as Astra and wrote 6 times as many. Artificial Analysis sees the same pattern: about 173K output tokens per task for Opus and 52K for Astra, both at max effort.

Same inside one company. GPT-6.1 Terra’s tokens cost half of GPT-6.1 Sol’s, yet on Alpine Gold Terra came to $4.90 and Sol to $3.62. Terra pushed 46.1M tokens to Sol’s 17.7M, and 82 of its requests (each call the app makes to the model) ran past 272K tokens, where OpenAI charges more per token.

Alpine Gold, same prompt: GPT-6.1 Sol vs Claude Opus 5.5 vs GPT-6.1 Terra

Against Opus, Terra was still far cheaper. Against Sol, it wasn’t.

Watch out: Claude Haiku 5.5’s $0.10 / $0.50 price holds only under 100K tokens per request; above that it’s $0.50 / $2.50. On my Alpine Gold run, 227 of its 230 requests went past that line: $6.93 instead of $1.41.

My rule for when a pricier model only adds the last 20% of quality: “Depends what’s in that last 20%. If it’s extra visual polish, I can live without it. If it’s hours of fixes before shipping, I’ll pay more upfront.”

The flip side: when a cheap model is good enough, run several and keep the best. “At roughly 50 cents a run, you can easily run several at the same time.”

Which raises the question most people actually have: what should I pay for?

PART 5 OF 11

What to pay for

$0 to start. Free Claude gives you Sonnet and Haiku, not Opus. Free ChatGPT runs GPT-6 Luna. Free Gemini runs Flash-Lite. Fine for drafts. For facts, double-check: on Artificial Analysis’s test, when Luna didn’t know an answer, it guessed 79% of the time.

About $20 a month: one plan, matched to your main job.

  • Design and UI (user interface: the screens and buttons people use) → Claude Pro ($20). Adds Opus 5.5 and Claude Code.
  • Code → ChatGPT Plus ($20). Codex with GPT-6.1 Sol, Terra and Luna. Astra is capped at an estimated 5 to 45 messages every 5 hours, so Sol is the everyday model.
  • You live in Google’s apps → Google AI Pro ($19.99, @GoogleAI). Gemini 4 Argon.

Most plans have usage limits that refill every few hours and every week, and some models get their own share.

$100 to $200, only when you hit limits every day. Claude Max ($100) and Ultra ($200) now include the same amount in monthly API credits, and Ultra drops the 5-hour limit for verified accounts, keeping only a weekly one. ChatGPT Pro ($100, $200 or $500) drops the 5-hour cap. Google AI Ultra starts at $99.99, and it’s the plan that gets Gemini 4 Carbon in the Gemini app.

A team? Claude Team is $25 a seat ($20 billed annually) and doesn’t train on your content by default. ChatGPT Business is $25 a user ($20 billed annually).

The API is for building a model into your own product or running bulk jobs: route each job to the cheapest model that passes it. Batch jobs, the ones that don’t need an answer right away, are half price at Anthropic, OpenAI and Google.

My own split: Claude for design, Codex for code, mostly on subscriptions.

“I don’t have that kind of money”

I read this in my comments every day, so let’s be clear. The dollar figures in this masterclass are API estimates: what each run would cost if you paid per token with API credits. That’s not what I pay.

I run my work through my subscriptions. Anyone on Claude Max ($100 a month) or Ultra ($200 a month) has more than enough to create anything they want. I’m on Ultra, and with Opus 5.5 I’ve never run out of usage, never even come close. Fable 5.2 is another story, and you’ll see why in the final test.

Today, one Claude subscription and one ChatGPT subscription for Codex cover everything I do. At one point, I was paying for three top-tier Claude subscriptions plus Codex. Using AI keeps getting cheaper.

Is $100 or $200 a month a lot? Compare it with what you can build: apps, tools, films, a whole business, and the money they can make you. And your plans go further when you match models to jobs, as you’ll see next. In Codex, for example, GPT-6 Astra brings the big ideas, and GPT-6.1 Sol runs an army of agents that gets the work done. For me, it’s well worth it. Start with one $20 plan, and move up when you hit the limits every day.

So who gets which job? Here’s how I cast them.

PART 6 OF 11

A pick for every job, and what to skip

Each job gets a pick, a cheaper pick and what to skip, from my runs where I have them and independent leaderboards where I don’t (leaderboards as of Oct 30, before Fable 5.2 and Gemini 4 Carbon’s full release).

Design and UI: pay for the lead when the look is the product

Whenever people will judge the work with their eyes, I cast Claude Opus 5.5. “That’s why we use Opus 5.5. Great at design!”

From my runs: here’s the Lighthouse brief. Same prompt, four top AI models.

The Lighthouse brief, same prompt, four frontier models side by side: Gemini 4 Argon, Claude Sonnet 5.5, Claude Opus 5.5, GPT-6 Astra

The best film, my call, came from Opus: $53.57. Gemini 4 Argon (@GoogleDeepMind) made a good one for $6.30, about 8.5x less. Even after Argon’s introductory price doubles on Dec 1, Opus would still cost about 4x more.

That bill was the outlier: most single-session Opus scenic films (one agent working alone) cost $18 to $32 and took about 1.5 to 3 hours. So why pay for Opus? In those six head-to-heads with GPT-6 Astra from part 4, it made the better film every time, and for visual work the better film is the job. “Opus is so good I wouldn’t mind paying double.”

The boards agree: #1 on @arena’s WebDev board, where people vote blind, and on Artificial Analysis’s Code2Video.

Use it like this: without direction, Anthropic says, Opus “falls back on a few default styles,” so name the exact patterns you don’t want. Claude Design comes with every Claude plan, Free included.

Sonnet 5.5 ties Opus on Artificial Analysis’s 3D board but isn’t reliably cheaper per job. Gemini 4 Argon is: a fraction of Opus per film in my runs, and still cheaper per task on Artificial Analysis at its full December price. As I put it in one reply: “Opus gets my vote for the scenery. Argon gets my wallet’s vote.”

Private and local: run open weights on your own machine

“Local” means the AI runs on your own computer. No internet needed, and nothing you type ever leaves your machine. That’s what you want for private documents, client data, or working on a plane. “Open weights” means the maker lets anyone download the model, so you can run it yourself. People often call it “open source,” but that’s not quite the same: you get the finished model, not the recipe and data used to train it.

Ollama (@ollama) and LM Studio run open-weight models on your own computer for free. Running open weights yourself, or on a host you trust, is the only way to keep prompts entirely off a model maker’s servers. Laptop-class options include Google’s Gemma 4, Qwen3.8-27B and Meta’s Muse Glimmer 30B (fits a Mac with 32GB of memory; the B is the model’s size, in billions).

The price of privacy: as of Oct 30, the best open-weight models score 32 on Artificial Analysis’s index, against 59 for the leader, and they need a server. Laptop-sized ones score lower (Qwen3.8-27B: 20).

For scale: Opus and GPT run on racks of specialized AI chips in giant data centers. Running something like them at home would take a room full of servers, a bigger power line and a very understanding electricity bill. Your laptop runs the small cousins. They’re good for private drafts, summaries and simple code, not for building your next app.

Pick: Gemma 4 or Qwen3.8-27B via Ollama or LM Studio · Skip: expecting flagship quality offline

For generated video, the top of Artificial Analysis’s board (Nov 7) is a near tie: Alibaba’s Wan 3.0 is first, and ByteDance’s Seedance 2.5, the better-known name, is in the same top group. Two reviews before anything ships

For my apps and SaaS tools, every build goes through two reviews. This is level 5 at its most advanced, but the idea is simple.

  • The deep review hunts for bugs. Claude Code and Codex review the app and check each other’s findings. Bugs get fixed, then they check again, round after round, until both agree nothing is left.
  • The completeness review hunts for what’s missing. A bug hunt can’t find a bug in something that doesn’t exist. So this review goes back to what the app is supposed to do and checks that every step a user needs is really there and works. Whatever is missing gets built.

Deep review first, then completeness. Together, they take an app from “it runs” to “it’s done.”

Seven habits that prevent the costliest mistakes

  • The right model for the job, priced per finished job, not per token.
  • One task per chat.
  • A done check the model can run: a test, a build, a screenshot.
  • Effort matched to the job, not maxed.
  • Scope bounded: levels, features, a finish line.

  • Anything that matters, tested twice.

Nothing else is confirmed. The one real sign: on Nov 1, some Codex users saw “gpt-6.2-astra” in their usage stats while the model picker still said GPT-6 Astra. Opus 5.6 and GPT-6.2 Sol are my guesses, not announcements.

When they land, they go through the same prompts. The names will change. The rules in this guide won’t.

The best model wins the leaderboard. The right model finishes your job.

Tonight: paste the Night Train prompt into a coding agent (two, if you have them, to compare), or take step 1 of your own build. Reply with what you got.

Your first week: day 1, set up one coding agent and build the to-do page from “Your first 10 minutes.” Days 2 and 3, pick one small, real problem and write its seven-line brief. Days 4 and 5, build it one piece at a time, saving every working step. Day 6, have a fresh session review it. Day 7, put it online and show one real person.

Questions? Ask anything in the comments. I answer every single one.
