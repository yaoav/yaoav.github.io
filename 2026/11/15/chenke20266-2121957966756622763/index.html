一晚上从零搭好 Grok Bot：完整配置 + 一套可直接复制的跑路盘过滤器

发表于2026-11-15|交易策略
|浏览量:

本文转载自 X 博主 @chenke20266（上车的乘客） 的长文，原文链接，版权归原作者所有。

大多数人认识 Grok Bot，是从别人晒的盈亏截图开始：打开它、丢给它一张 K 线图，然后把第一个 50美元亏在一枚「买入前就已经凉了」的币上。机器人不是问题所在——没人告诉过它「凉了」长什么样。

如果今晚让我从头再来，我会照这套搭：一个 bot，一个文件夹，十个小文件。它不找百倍币，它的主要工作是杀掉代币；侥幸活下来的那几个，还得先让Grok读一遍 X，一分钱才能动。

01–07是第一个晚上：机器人、密钥、限额、离场。08–12是跑路过滤器，14 项检查，每一项都写成代码。13和14把它设成自动跑，先跑纸面。

如果你看过我那篇「八个智能体交易台」，这篇就是那张台子的地基。

怎么用：打开你的 Grok Bot，把整篇文章粘进去，说一句「在 /workspace/desk 里把这套台子搭出来，纸面模式，任何碰钱包的动作先问我」。它会在自己的电脑上把每个文件写出来。

你要守住的分工：代码杀，Grok读 X，你签字。台子上没人干别人的活。

01. 开始之前准备四样东西

每样都写清楚：是什么、今晚你要做什么、为什么需要。

1. Grok Bot 就是雇具名bot的那个应用。每个bot在一台有浏览器、文件系统和终端的云电脑上跑，你合上笔记本它也在跑。 做什么：去 x.ai/bot 下载、登录、选 Create your own。 为什么：整张台子都活在那台电脑上——文件、例行流程、告警，都在一个地方，手机也能打开。

2. 一个 xAI API key从代码里付费调用Grok，自带 X 搜索。 做什么：console.x.ai → API Keys，建一个。先别粘到任何地方，第 03 步说它放哪。 为什么：例行流程没法在聊天里坐着想四十个代币；一个脚本可以一个代币发一次调用，而且每次答案都记成同一种格式。

3. Rugcheck 和 DexScreener 两个免费公开 API。Rugcheck 读合约：权限、LP、持有人、内幕、dev 钱包；DexScreener 读池子：深度、年龄、买对卖。 做什么：什么都不用做，不用注册，读接口不要 key。 为什么：事实先于观点。mint 权限开着不是判断，是事实，而事实先杀。

4. 一个一次性钱包——但今晚不用 一个全新的 Solana 钱包，从没装过别的东西。 做什么：今晚什么都不做，第一周跑纸面。 为什么：台子永远不持有私钥。真上线时，它告诉你买什么，你自己签。

02. 雇一个 bot，不是八个

我的台子现在跑八个。它不是这么起步的，你的也不该。第一天八个bot，就是同时有八个东西要 debug。一个bot一个职责，会告诉你另外七个以后需要什么。

04. 先把整条漏斗看明白，再动手

八道关卡，免费的先跑。只有活过免费关卡的才花一次Grok调用；只有被 Grok判BUY的才花钱。这一周连钱都不花。

代码块

mint 权限开着不是判断，是事实，而事实是免费的。 Grok 永远只看到已经通过所有脚本检查的代币。

05. 把所有数字放进一个文件

存成 config.py。台子上每个数字都活在这里，所以调参时你只改一个文件，别的都不用动。这些是我的，按 25 美元一单调的——不是建议，是一个你一定会改的起点。

06. 先跑限额，再干别的

存成 book.py。台子上最便宜的检查，是那个根本不调API的检查。今天已经亏了 50美元，台子连看都不看这个代币；四个仓位开着，一样。

这个文件也是台子的记忆：positions.json 和 trades.csv，两个你自己就能打开的文件。

07. 先写离场，再写进场

大多数人是在盯着一根绿柱的时候决定什么时候卖的。那是最不适合做决定的时刻。在这张台子上，每个离场条件都在买入之前就存在，机器人只是每10分钟检查一遍：

  • 流动性相对入场撤走40%：全出，不问
  • 跌35%：出
  • 涨100%：出一半，剩下的是市场的钱
  • 涨200%：再出四分之一
  • 第一次止盈之后，价格从峰值跌30% 就走
  • 六小时没涨20%：出——这个仓位比希望值钱

08. 学会代币的 14 种死法

如果只能留一样，我留这个。它不需要任何bot也能用：下次买之前，拿同样的 14 项在 rugcheck.xyz 和 dexscreener上手动跑一遍，你会跳过大部分本来会后悔的币。

13 项是代码——比较，没有模型，没有观点。第 14 项才需要Grok。

09. 让代码杀掉那些显而易见的

检查 1–9。它拉一份报告，只保留台子会读的字段。Grok永远看不到原始报告——肥的 payload 既费 token 又掉准确率。

一个常被忽略的细节：池子自己的金库和锁仓合约也出现在前十持有人名单里。把它们算进去，每个币都像鲸鱼币。代码会先把它们剔掉，再算前十。

10. 检查池子，不只是合约

检查 10–13。合约可以完美，池子照样不让你出来。这段读该代币最深的池子，问四个无聊的问题：里面钱够不够、我这一单相对它多大、它多老、到底有没有人在卖。

11. 让Grok读代码读不出来的东西

第 14 项。这就是这张台子跑 Grok 而不是别的模型的原因：它边想边搜 X。

一个币可以通过全部 13 项，却还是个换了合约地址的仿盘；或者是一场四十个上周才注册的账号、在同一分钟发同一句话的发车。没有 API 能返回这个。X 能。

存成 grok.py（唯一读密钥、唯一和 xAI 通信的文件）和prompts.py（你真正会反复读的那个文件）。核心提示词长这样：

同一个 ticker 下另一个合约地址：仿盘风险。SKIP。
需要的字段是null时，永远不回答BUY。
永远不提价格目标，你不知道。

14. 先跑一周纸面，再谈一分钱

PAPER = True意味着这台子除了钱，其他都是真的：真代币、真价格、真离场，假成交。七天后打开checks.csv，像读陌生人写的东西一样读它。

你要看三件事：哪一项检查杀得最多、那些BUY是不是你会买的、有没有哪个 SKIP 理由看着就不对。纸面成交按屏幕价算，实盘永远不会——所以纸面结果是天花板，不是预测。

真上线时把 PAPER改成False，除了最后一步什么都不用变。check.py不再买入，而是发一行审批：你自己在钱包里买25美元，然后一条命令把它记进账本，watch.py开始盯着它。
