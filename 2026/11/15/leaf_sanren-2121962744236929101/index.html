一、一份规则，6 个 AI 共用：让 DSH 记住你的规矩

Claude Code 每开一个会话，都会先读 ~/.claude/CLAUDE.md，你写的称呼、做事习惯、红线，每个窗口都生效。

DSH 不读这个文件。它的全局规则只认两个位置：~/.dsh/AGENTS.md 和 ~/.agents/AGENTS.md。装好以后，这两个文件默认都不存在。

也就是说，你在 Claude Code 里调教了几个月的规矩，到 DSH 里全部作废。

我的做法：只维护一份正本

我手上不止 DSH 一个 AI。Claude Code 是主力，Codex、Gemini、Grok、Factory Droid 也会派活。以前每家一份规则，改一条要改五遍，总有一家忘了改，结果它还按老规矩干活。

现在我只改 CLAUDE.md 这一份，写了个同步脚本：改完跑一下，另外 5 家的全局规则一起重新生成。

配之前，先给规则瘦个身

DSH 给全局规则和项目规则各留 64KB。超出的部分会被丢掉或截断，优先保留离你当前文件夹最近的那份。规则写得越胖，越可能有一段你最在意的红线根本没被读到。

Anthropic 官方最近给的 Claude Code 最佳实践里，判断标准就一句：这条信息，模型自己读代码能不能看出来？看得出来就删。

  • 删：技术栈、目录结构、去哪找文件，模型自己读得出来
  • 删：满屏的 IMPORTANT、NEVER 和感叹号。官方的说法是，这是写给老模型的，对现在的模型反而会带偏，工具调用变多，结果变差
  • 留：代码里看不出来的事，比如「这个服务还在用一个老数据源，代码里没直接引用」

参考一下尺寸：有人转述过 Claude Code 作者 Boris 的配置，他的 CLAUDE.md 只有大约 2.5K token。他的习惯是每被纠正一次就加一行，同一个流程重复两次就做成一条命令。

二、100 多个 skill，一行命令接进 DSH

DSH 会去 5 个地方找 skill：项目里的 .dsh/skills 和 .agents/skills、你自己配的目录、/.dsh/skills、/.agents/skills

唯独没有 ~/.claude/skills。

我这边更省事一点：~/.agents/skills 里本来就放着 100 个 skill，是之前给 Codex 那几家共用建的，DSH 原生就认。只缺 6 个新装的，同步脚本顺手补上软链接。现在 DSH 里能用的有 106 个。

格式基本通用，都是一个文件夹放一个 SKILL.md，开头写 name 和 description。有两点要注意：

  • 只认第一层。 skills/写作/写推/SKILL.md 这种多套了一层分类的，DSH 找不到

MCP 是给 AI 接外部能力的插头。我在 Claude Code 里接了豆包搜索和剪辑软件 ChatCut，让它「搜一下」走的是豆包，剪片子直接操作 ChatCut。

我接的时候踩了三个坑：

  • 一定要用 - insert: 包起来。 我第一次直接写条目，报 entry not found。这个文件默认只能改已有的配置，加新东西得用 insert
  • API key 不会自动传进去。 DSH 启动 MCP 的时候，会把名字里带 KEY、TOKEN 的环境变量清掉，要用的 key 得在 env 里写明。我没把 key 明文抄进配置，而是写了一行代码，让它启动时去 Claude Code 的配置里现读，这样 key 只存一份
  • 要登录授权的 MCP 暂时接不了。 远程那种要先在网页上登录授权的，DSH 的 MCP 插件还没有对应的设置项，只能先等

四、DSH 没有 deny rule：密钥和 .env 自己守

在 Claude Code 里，绝对不能发生的事，可以写成 deny rule。比如禁止读 .env，那就连 cat .env 这种命令，都会在执行前被直接拦下。

官方的原则说得很直白：想要保证，只能靠工具本身强制执行。写在规则文件里的，只是请求。

DSH 现在没有按文件拦截的规则。它有四档权限（只读、工作区内修改、完全权限、自动授权审查），加三档沙箱。

问题出在沙箱上：它管的是 AI 能往哪里写文件，网络它不管，官方文档里写得很清楚。

落到实际就是：你让它跑一下 npm test，这个命令看着人畜无害，你肯定点允许。可如果里面某个依赖被投了毒，它照样能联网，把你电脑上的东西发出去。你在规则里写一百遍「不准碰密钥」，也拦不住一个不归 AI 管的依赖包。

我的做法：

  • 日常用「工作区内修改」。 能干活，又有边界，完全权限只在确实需要时临时开
  • 密钥、.env、SSH 这些，不放在工作区里。 它碰不到的东西，最安全
  • 跑陌生仓库、试第三方插件，放进一次性的虚拟机或容器。 DSH 官方的安全说明也是这么建议的
  • 「自动授权审查」别当成保险。 它是让模型先审一遍每次操作，会误放，也会误拦，每次还要多花一次 token

───

五、DSH 没有 hook：用 /goal 验收，重活交给 Claude Code

AI 一跑几十分钟，最怕的是它最后说一句「完成了」，你只能信。

Claude Code 的解法是 hook：每次改完文件自动跑一遍检查，想把任务标成完成，得先过测试。官方还专门提醒过一个细节：测试失败的退出码要改成 2，Claude Code 才会挡住这次「完成」，让它回去接着修。

DSH 目前没有这种能自己配的 hook。

8 月有条两万多浏览的帖子说，DSH「能原样用上你的 Claude Code hooks」。我把 0.2.2-rc.1 安装包里的插件全翻了一遍，连 hook 的事件名都没找到。别指望把配置拷过去就能用。

硬拦搬不过来，但验收这件事，还有几个办法：

1. 动手前先用 /plan，把「做完是什么样」写清楚

官方举过一个例子：让 AI 把登录功能迁到新接口，同一句话能跑出三种结果。迁完了老接口还留着；只对新登录生效；把所有已登录的用户全踢下线了。三种看着都像完成了。

所以计划里要写能分出对错的检查，比如「已经登录的老用户不会被踢下线」。

2. 长任务用 /goal，把验收标准写进目标

/goal 会一轮接一轮地做，直到完成、卡住，或者到轮次上限（默认 256 轮）。你在目标里写清「某某测试必须通过，做完把实际输出贴给我」，它判断自己做没做完的时候，手里就有一把尺子。

3. 做完另开一个对话来审

写代码的会话和审代码的会话分开，审的那个从零看改动和测试结果。Anthropic 内部就是这么做的。

4. 重活直接交给 Claude Code

DSH 有个官方插件叫 Claude Code 子智能体（Codex 也有一个）。装上以后，你可以在 DSH 的对话里，让它把某个任务交给你电脑上的 Claude Code 去做。Claude Code 独立跑完把结果交回来，不占 DSH 这边的上下文，花的是你 Claude Code 账号的额度。这是 @long_jingai 发现的：

写在最后

我的 Claude Code 好用，靠的从来不是开箱即用，是这些一条条配出来的规则、skill 和 MCP。DSH 一样能配，只是得知道往哪放。

规则、skill、MCP 配好，它就认得你、会用你的工具。deny rule 和 hook 暂时没有，就用工作区边界、/goal 和 Claude Code 子智能体兜住。
