今天拆透一套「主脑规划 + 多工兵并行 + 独立验货」的省钱高效Agent编排方案

早上打开面板看配额，我的 Claude Opus 和 Sonnet 周额度双双躺在了刺眼的 0%，得干等到下周四才刷新

转头切进 Google Antigravity，刚好撞上 Google 在 11 月 12 日推上线的几张硬牌：Gemini 4 Hydrogen、Orchestrator，以及多智能体原生的 Antigravity Swarm（原生蜂群）

把官方文档和本机实测数据对在一起看，我直接长舒一口气：大厂终于把我们这帮重度用户折腾了大半年的「高低档混编 + 多工兵隔离协同」，做成了开箱即用的原生能力

先摆三组实打实的效率账单：

  • 单会话纵向动态接力（Orchestrator）：在 Google 官方 Terminal-Bench 实测里，Orchestrator 让 Carbon 和 Hydrogen 在同一会话里动态换挡，拿下了逼近纯 Carbon 的任务成功率，同时立省 24% 额度、提速 19%
  • 同 IDE 原生蜂群并发（Antigravity Swarm）：昨天我直接在 Antigravity Swarm 里拉起 5 路 Hydrogen (High) 造物工兵 + 1 路独立只读 verifier + 1 路停摆巡检 monitor 并行跑 5 个零素材 3D 原型，跑满 24 分 04 秒，Antigravity 总额度仅掉了 1%（19% → 18%）
  • 跨宿主横向铺开工兵（@zseven-w/dsh-crew）：结合我自己本机跑过的 21 场 Claude Code 多工兵编队，以及我们团队把这套经验写成的开源插件，主脑留在 Claude Code / Codex / Grok 原地不动，也能一键扇出 18 个廉价工兵并行干脏活，主会话上下文干净得像刚新建一样

不用先搭复杂框架也能直接用：哪怕现在只在 Antigravity 里切到 Orchestrator (Carbon) 跑一轮，或者把下面第一段「只读规划 + 自包含施工单」提示词贴进日常对话，当场就能省下一大截白烧的额度

文中所有编排约束提示词、零上下文派工模板与开源插件一键配置命令均可直接复制，动手前建议先点收藏放在手边

一｜Google 连发 Hydrogen 与 Orchestrator：为什么「静态路由」早就该淘汰了？

这次更新如果只看模型名字，很容易漏掉最核心的工程信号：Google 正式拿 Gemini 4 Hydrogen 接替了沿用多年的 Flash 命名

它不再是过去那种「便宜但经常漏条件」的缩水小弟，而是直接从旗舰 Carbon 演化出来、专门针对高频代码编辑与工具调用打磨的 实干工兵（The Doer）：

  • 全窗口拉平计价与高吞吐：原生 100 万 Token 输入输出窗口，API 价格统一拉平在输入 $1.50 / 百万 Token、输出 $7.50 / 百万 Token；日常编码速度比上代 3.8 Flash 快 2.5x，实测输出吞吐飙到 168–236 tokens/s
  • 四档思考深度按需拧：在 Antigravity 里开放了 Low / Medium / High / XHigh 四档，Artificial Analysis 智力指数默认 High 档 51、拉满 XHigh 冲到 54（直接反超老款大参数 Argon 默认档）
  • 能扛真实终端重活：Terminal-Bench 4.1 拿下 57.0%，在 Antigravity-CLI 跑仓库级子任务的 SWE-sweep 拿到 13.5%（同台对照的 Sonnet 5.5 为 3.1%，GPT-6.1 Terra 为 5.8%）

光有快马还不够，真正戳中重度开发者痛点的是同场登台的 Orchestrator

用过市面上各种自动选模型功能的朋友都知道，过去的「静态路由（Static Router）」有多鸡肋：
它只看你第一句提示词长不长，开局盲猜一次难度，然后整场对话把你死死锁在同一个模型里

如果你开局挂着 Carbon 或 Opus 聊架构，前五分钟确实惊艳；可接下来半小时装 npm 包、改十几个文件的变量名、跑测试修拼写错误，每一轮百万上下文回传都在狂烧最昂贵的旗舰配额

而 Orchestrator 直接把「动态换挡」塞进了同一条会话轨迹里：

  1. 第 1 棒 · 只读规划期（Carbon / Argon 领衔）：先在只读模式下扫描代码依赖、消解模糊需求，输出结构化改造蓝图，并提前写明触发重规划的边界条件（Re-planning Triggers）
  2. 第 2 棒 · 高速施工期（Hydrogen 接管）：蓝图敲定后，无缝切给 Hydrogen 飞速写代码、升依赖、跑测试套件
  3. 第 3 棒 · 受阻动态回传（Dynamic Recovery）：一旦 Hydrogen 在跑测试时撞上未预料的报错或工具失败，控制权当场交回给 Carbon 检查现场、修补方案，再把执行权派回下层

告别开局盲猜难度的静态路由：Carbon 只读定蓝图、Hydrogen 2.5 倍速干脏活、遇错秒级回传重规划，实测省 24% 额度且快 19%

说白了，这才是符合人类工程直觉的分工：让架构师留在白板前做关键决断，别让架构师蹲在地上拧每一颗螺丝

二｜Antigravity 原生蜂群（Swarm）：把多工兵防踩踏纪律直接焊进 IDE 调度层

Orchestrator 解决的是**「单条会话里怎么动态省额度」**；可一旦遇到能同时拆成三五块并排推进的大项目，光靠一个会话顺序干还是不够快

Google 紧接着在 Antigravity 里放出的 原生蜂群（Native Swarm），干脆把我们在多智能体实战里摸索了大半年的协同规矩，原封不动焊进了四个底层原语里（swarm、post_message、read_board、swarm_wait）：

  1. 共享留言板 + 零消耗休眠（@name 与 #seq）：Coordinator 协调器自己绝不抢着写代码，只负责把大活拆成互不冲突的领地，按职责命名（parser、verifier、docs）发进共享留言板；工兵交接不再靠人工来回复制粘贴长报告，直接喊序号互引（比如 @verifier check #4 and #6），空闲工兵调 swarm_wait 原地休眠等点名，等待期间 0 Token 消耗
  2. 原生隔离工作区（share / branch / inherit）：这是最直击痛点的一刀——以前怕并发写互踩全靠口头求自觉，现在给每个写工兵配 workspace: “share”，系统自动给它分一套共享底层仓库的独立工作副本（branch 则是完整独立克隆），只读侦察和验收留 inherit，各自改完提交再统合落盘，然后 kill 清理副本
  3. 防僵死与防假绿双保险（verifier + monitor）：Swarm 规范明确按每 2–4 个写工兵配 1 个独立只读 verifier 查 diff 跑测试，只验不改、有问题直接打回原作者修；同时可常驻一个 monitor 巡检员，一旦全队静默卡死就精准点名能打破僵局的成员，杜绝集体“哑火”
  4. 热上下文分叉（fork）+ 运行时热换挡（model）：调查中途分裂成两条线时，不用冷启动重读全仓，直接 fork 已有成员的对话上下文接力；万一某个工兵跑一半撞上限流或额度吃紧，也不必杀掉重来，直接对其原地执行一次 model 切档就能保留历史记忆接着干

单线还是蜂群？Orchestrator 是在 1 条对话轨道上动态换棒，Swarm 是在共享留言板下让多工兵进各自 share 隔间并跑

为了摸清这套蜂群带着 Hydrogen 干重活的真实成色，我昨天直接拉起 5 路 Hydrogen (High) 3D 工兵 + 1 路独立 verifier + 1 路 monitor，同时在共享留言板上并排赶工 5 款零外部素材的纯代码 Three.js 3D 原型（含《掌中造物星盘》）：

  • 效率账单：5 个从源码到单文件 HTML 打包、Chrome 零报错实跑、60fps 演示录屏全检走完，总墙钟耗时 24 分 04 秒（其中《掌中造物星盘》单独耗时 23 分 08 秒，交付 8 个源码文件 86.7 KB / 2,649 行；同题盲测丢给 Codex GPT-6.1-Sol (Max) 单跑则耗时 40 分 05 秒）
  • 额度损耗：7 个协同会话并排跑满整整 24 分钟，面板上的 Antigravity 总额度仅仅掉了 1%（从 19% 掉到 18%）

真机面板实拍：左图 Board #1–#7 划死独立目录并挂上 @verifier 与 @monitor，右图 Graph 实时点亮 5 路运行绿灯，24 分钟全程仅掉 1% 额度

三｜从「13 个 Opus 豪华团」到额度清零：我在 Claude 编排里交过的三次真学费

看到 Google 把「主脑只读规划 + 工兵快速执行 + 失败升档回传」做成官方原生的那一刻，我之所以格外感慨，是因为翻开我自己电脑 ~/.claude/teams/ 目录下的 21 场真实编队配置，里面全是用真金白银和烧穿的周额度换来的同款教训

拿我们打磨 6700+ Star 开源设计工具 OpenPencil 和 10 款 DSH 插件的过程来说，前后刚好经历了三次蜕变：

1. 第一阶段：13 个 Opus 同场开火的「土豪火力覆盖」

做 OpenPencil v0.8.3 演示模板扩产那次，我一场会话直接拉起了 13 个 Agent 组成的完整流水线：
1 个 team-lead 坐镇，底下配齐 2 个只读侦察兵（分头扫本地资产与线上合规参考）、1 个设计架构师、3 个并行产稿工（同时造 6 套 .op 模板）、语料工、修复管线工、集成工、探针取证工、画布重排工，最后再蹲 1 个只准 rebase + commit 绝不准 push 的专职收口工

活干得确实漂亮，但事后复盘账单差点心梗——底下 12 个工兵清一色全挂着旗舰 opus

哪怕只是「把 6 页横排画布改成上下两行排布，只算 x/y 坐标不动设计内容」这种纯算术搬砖活，也在照单全收旗舰模型的长上下文计费；连跑两场大编队，一周的订阅配额直接见底

2. 第二阶段：9 个工兵挤同一工作区的「口头警告地狱」

紧接着赶桌面端交互冲刺时，我又试过同时拉起拖图填充、批量导出、图片比例适配、缩放卡顿诊断等 9 个工兵共用同一个未提交目录

为了防止工兵 A 把工兵 B 改到一半的文件顺手提交或格式化掉，我被迫在每条任务简报末尾贴满冗长的免责声明：
「工作区已有大量他人未提交改动（质量显性化 15 个文件 + templates/），一律只读别碰，绝不 git commit」

结果证明：靠自然语言求 AI 守规矩是最脆弱的防线——只要有一个工兵调错一次全局格式化命令，整片共享工作区立刻搅成一锅粥

3. 第三阶段：「280 个测试全绿」教我永远别轻信工兵自述

更隐蔽的翻车发生在验收环节

我们在审校自动化测试插件 dsh-qa 时，仓库里躺着 280+ 单元测试、102 条对抗语料和 5 万例随机 fuzz，跑起来满屏全绿；结果真人拿去测真实动态网页，一口气抓出了 7 个自动化测试完全漏掉的真缺陷

最哭笑不得的是第 7 个缺陷：有个工兵发现某类边界输入会触发报错，它没有去修底层逻辑，而是悄悄缩窄了 fuzz 生成器的随机范围，让触发报错的数据结构不再生成——用例数没变、通过率 100%、绿灯照亮，但真实防御面直接被挖空了一块

21 场 Claude Code 真实编队沉淀出的四条铁律：算力按档切分、简报自包含零假设、目录物理隔离、只信产物与独立验收

如果你现在主力还在用 Claude Code、Codex 或 Antigravity 单兵带子代理，下面这段浓缩了上面三次学费的编排契约，可以直接复制贴进你的 CLAUDE.md 或开局系统规则里：

📋 抄作业 1：直接贴进 CLAUDE.md 的「主脑 × 工兵 × 验收」三段式契约

本项目多步骤任务严格执行「只读主脑 → 零上下文工兵 → 独立验收」三段式纪律：

  1. 主脑只读探路：动代码前先在只读模式下盘清依赖与接缝归属（Seam Owner），严禁未定方案直接派写手下场
  2. 自包含施工单：子代理默认零历史记忆，每次派活必须写死【涉及文件的绝对路径】+【明确验收命令】+【严禁触碰的目录/锁文件】+【严禁自行 git commit / push】
  3. 读写严格互斥：同一工作目录同一时刻只允许 1 个写工兵落盘；并行写任务必须先拆进完全不相交的文件领地或独立 worktree
  4. 只信产物不信自述：工兵回报完成后，主脑或独立只读验收工必须亲自跑 git status、git diff 与真实测试脚本，严禁为凑绿灯删断言或缩窄测试输入

四｜跨出单一 IDE 怎么白嫖高速工兵？我们把这套护栏做成了开源插件 dsh-crew

聊到这儿，其实就看清了 2026 年底多 Agent 编排的三块核心拼图：

Google 的 Orchestrator 和 Swarm 分别解决了 Antigravity 内部 的单线切档与原生蜂群并行；但一到真实开发现场，我们手里的工具往往是跨阵营混搭的——

比如你习惯待在 Claude Code 里用顺手的终端交互和主脑判断，但 Anthropic 的周额度金贵得要命；又或者你想在 Codex、Antigravity、Grok 里保住当前主脑不动，把「15 国语言文档翻译、全仓符号重命名、补齐成批单测、扫 6 个仓库的边界缺陷」这种吞 Token 巨兽，统统外包给便宜大碗的 DeepSeek V4 Flash / Pro

这就是我们团队动手造出 @zseven-w/dsh-crew（刚发到 0.1.0-rc.15）的初衷：让你不离开自己最顺手的宿主界面，直接把外部完整的 DSH Agent 当成原生子代理使唤，顺手把防翻车护栏焊死在工具层

1. 一次派发两个视角：18 个工兵并发干活，状态栏实时跳账单

装好插件后，派出去干活的不是一次裸的模型接口请求，而是跑在开源 DeepSeek Harness 里的完整 Agent 会话（自带工具链、沙箱预设和 Web 会话记录）

之前我们给项目做 15 国语言 README 同步本地化，主脑一句话直接扇出 18 个并行 worker 同时开工：

  • 在 Claude Code 宿主侧：18 个任务整整齐齐列在原生子代理面板里，底部 claude-hud 状态栏实时滚动当前在跑的档位、耗时和 Token 消耗（⚙dsh 5▶pro 1m15s 14.6k/334 · flash 1m4s 16k/1.2k）
  • 在 DSH Crew 看板侧：hub-1 到 hub-18 每个任务由哪个宿主派出、用的什么档位、跑到哪一步一目了然，点开就能围观完整执行过程

主脑留在原地不动，18 个 DSH 工兵并发跑完多国文档本地化：上方为 Claude Code 原生状态栏，下方为 DSH Crew 任务看板

2. 跟 Google Orchestrator 不谋而合的「按结果自动升档」

日常派活最让人纠结的就是「这活派给快模型怕它写挂，派给强模型又肉疼额度」

我们在 dsh-crew 里直接内置了 escalate_on_failure（失败自动升档） 开关：
拿不准难度的任务，默认一律先派飞快便宜的 ds-flash 上去试水；万一阻塞任务跑挂了，工具层自动切到推理更强的 ds-pro 重试一次

这跟 Google Orchestrator 让 Hydrogen 先冲、遇挫再回传 Carbon 的底层逻辑完全一致：永远用真实执行证据，而不是开局拍脑袋来决定花多少钱

3. 不靠提示词自觉，把 3 道防崩护栏写进代码执法层

吃够了前面「9 个工兵挤脏目录」的苦头后，我们把所有安全边界全做成了发车前强制拦截的硬护栏：

  • cwd 工作区咨询锁：同一个仓库目录只要有 1 个写任务正在跑，第 2 个派发请求进来会当场报错拒绝，并把当前锁持有者的 Job ID、后端和启动时间明明白白返回给主脑（绝不静默排队，只有纯只读侦察才准显式传 allow_concurrent_cwd: true）
  • 递归套娃深度封顶（默认 3 跳）+ 环路拒绝：严防工兵自己又去拉工兵无限套娃把账单跑爆
  • 后台无人值守防挂死 + 孤儿任务显影：后台工兵一旦试图调 ask_user_question 等人回答，会立刻以 needs_input 状态干净停机回报主脑，绝不在后台傻等半小时超时；就算中途服务重启，断连任务也会在看板标为孤儿状态（Orphan Ghost），绝不无声消失

📋 抄作业 2：3 行命令把 dsh-crew 一键装进四大宿主

dsh plugin –profile web add @zseven-w/dsh-crew@latest
dsh web

一键注册 Claude Code / Codex / Antigravity / Grok 集成与状态栏：

node src/install/cli.mjs all

装好重启会话后，派活时直接套用下面这张**「零上下文工兵施工单」**，成功率比随口喊一句高出一个数量级：

📋 抄作业 3：直接喂给 ds-flash / ds-pro 或 Hydrogen 工兵的标准施工单

请派给 ds-flash（若涉及跨模块权衡改派 ds-pro）执行以下自包含任务：

  • 目标文件：仅允许修改 【填写绝对路径，如 /abs/path/src/auth.ts】 与对应单测 【/abs/path/test/auth.test.ts】
  • 完成标准：修好 【具体问题现象】，补充覆盖该边界的单测，并亲自运行 【npm test】 确认通过
  • 禁碰红线：严禁修改 package-lock.json、生成产物目录及其他未点名模块；严禁执行 git commit 或 push
  • 诚实回报：返回实际改动的 git diff –stat 摘要与测试终端原始输出；若有未跑通项必须如实标明 not verified

  • 大任务能拆成多个独立模块并行冲刺（同 IDE 内）：直接在 Antigravity 里拉原生 Swarm，给写工兵配 workspace: “share” 隔离副本、配齐 verifier 和 monitor，让 5 个 Hydrogen 并行造物也能做到只掉 1% 额度
