零基础怎么用 AI 搭一个能收款的网站？

发表于2026-11-16|行业观察
|浏览量:

本文转载自 X 博主 @momo_peggy（夏林果的出海日记） 的长文，原文链接，版权归原作者所有。

从两次“打不开”讲清网站怎么上线。每一步都附一条可以复制给编程 AI 的提示词。

如果你也想做一个网站，把文里的提示词复制给能写代码的 AI，就可以一步一步搭起来。 先把方括号换成你的需求，让 AI 做出一个能在自己电脑上打开的版本。再按需要加表单、登录或收款，最后部署上线。每做完一步，照着提示词里的检查方法亲手试一次。

先看上面这条访问主线。下面的支线按网站功能选用，做作品集只走主线也可以。

我的网站两次打不开。第一次，隔着网络敲门明明有人应声，浏览器就是进不去。后来我换了个对外访问的地址（公网 IP），网页恢复了。第二次，服务器里的程序还在跑，最后却是给云账户充钱才恢复。

01｜在我电脑上能跑，离别人能打开还有多远？

我做了一个卖 AI Skill 和课程、可以在线收款的交易网站。AI Skill 就像给 AI 的操作说明书，让它按你定好的方式做一类事。

网站在我电脑上能跑，别人还打不开。我得找个能一直开着、让别人来访问的地方。云服务器就是租来的远程电脑，我选了阿里云香港 ECS，当时的考虑是网站还没做 ICP 备案。ICP 备案就是向工信部门登记网站信息。也可以用托管平台，相当于把网页交给对方代管，自己省去不少管机器的事。阿里云备案说明

搭站提示词
在当前目录搭一个可以在本地打开的 [作品集／报名站／交易站]，列出用户要做的三件事：[填写]。用 Next.js 实现页面，先给示例数据、启动命令和浏览器验收步骤。需要记录提交或订单才加数据库。现在先跑通本地版本。

02｜打开一个网站，先经过哪些环节？

域名是店名，公网 IP 是互联网能找到的地址，DNS 像通讯录，帮浏览器从名字查到地址。查到地址后，浏览器才出发。

到了门口，浏览器会先看网站的证书，就像核对对方的身份证。核对通过后，HTTPS 给双方的通信加密，就像把要传的话装进只有双方能打开的信封。我用的 Caddy 像门口的接待员，接到请求后转给里面负责办事的程序。Caddy 自动 HTTPS

前端是客人看得到的页面和按钮，后端是收到指令后实际办事的程序。作品集只展示照片和介绍，先把页面做出来就行。报名站还得记住谁提交了什么，交易站还要管付款和交付。选好你的网站要做哪几件事，再往下加对应的功能。

部署提示词
按 [托管平台／云服务器] 部署当前项目。托管就用平台提供的域名和 HTTPS 能力；自建就生成 Docker Compose 和 Caddy 配置。列出我要填的 DNS 记录、目标地址和部署步骤。部署后从外网检查域名解析、证书和页面，分别报告这三关是否通过。

03｜记录放数据库，文件放哪里？

数据库像一份能查能改的账本，适合记报名信息、账号和订单。对象存储像仓库，专门放照片、视频和压缩包。阿里云的仓库服务叫 OSS。小网站文件少，可以先用托管平台自带的空间。

要把私有文件交给有权限的人，可以用签名链接。它就像限时取货单：网站查完权限才发单，用户凭单直接向仓库取文件。谁拿到有效的单子，通常都能用，所以有效期可以设短一些。阿里云 OSS 签名下载说明

数据和文件提示词
为 [报名／账号／订单] 建表、写入和查询接口，重启后数据仍要在。如果需要私有下载，把文件存入 OSS，后端检查权限后才生成短时签名链接。演示新记录可查、有权限可下载、无权限拿不到链接、过期链接无法发起新下载。

04｜网站什么时候需要发邮件？

作品集可以只留个联系邮箱。需要注册、找回密码或发预约通知时，再接邮件服务，让它替网站送信。

比如验证邮箱，网站寄出一封带链接的信，用户点开链接回到网站，网站才知道他收到了这封信。就像寄信加回执：送到了和收到回执了是两回事。配置时如果看到 SPF，可以把它理解成「谁有权帮我寄信」的名单。DKIM 像防拆封条，让对方能检查来信有没有被动过。阿里云发信域名说明

邮件提示词
给当前站点做 [邮箱验证／找回密码／预约通知]。先在本地用测试邮箱或模拟发信走通。需要验证时使用限时、一次有效的链接。接入真实邮件服务时，列出发信域名、SPF 和 DKIM 要填的位置；测试正常、过期和重复点击。交付实际验证到的结果。

05｜自动收款，网站怎么知道钱到了？

去商店买东西，店员先开单，你去收银台付钱。收银台确认收到钱，店员才给你发货。网站接支付宝或微信支付，也可以这样想。

支付 API 是网站找收银台办事的通道，用来开付款单、查付款结果。Webhook 在这里就是支付回调，像收银台主动送回来的收款回执。网站核对回执是真的、对应的是这一单，才把订单改成「已付款」。回执没收到，网站也能主动去查。页面上出现「支付成功」四个字，不能代替查收款记录。微信支付开发指引 · 支付宝官方 SDK

可以先用模拟付款把流程跑通。要收真钱，还得在支付平台开通对应的商户产品，具体怎么接交给下面这条提示词。

支付提示词
给项目加 [微信支付／支付宝]。先跑通模拟支付，再按所选产品的官方文档实现下单、可从外网访问的 HTTPS 回调地址和后端查单。金额由后端计算。回调用对应平台的官方验签方式，核对订单号、金额、币种、商户身份和支付状态。仅在确认付款后更新状态并交付，同一条或并发通知只能交付一次。浏览器返回页只显示后端确认的状态。跑通成功、取消、假通知、金额不符、重复通知和漏通知后查询补记。列出商户需要手动完成的设置，所有秘密凭证只在服务端配置。

06｜两次打不开，查出来是两件事

第一次，我的公网 IP 能 ping 通，也就是隔着网络敲门，有人应声。但我用在线工具从几个地方试了 443，都连不上。443 像这栋楼里加密网页通常使用的窗口，敲门有回应，窗口也可能没开。换 IP 后网页恢复了。旧地址为什么连不上，我没有证据下定论。

第二次，服务器里的程序正常，外面却打不开。服务器虽然包月，弹性公网 IP 这项可以独立申请、绑定到服务器的地址服务却单独扣费。账户欠费，公网连接受限，充值后网站恢复。就像店租交了，店里的宽带还有一张账单。阿里云弹性公网 IP 欠费说明

排障提示词
先只读排查 [网址]：按域名解析、443、证书、入口日志、程序和云资源状态逐层检查。给出每一步的证据和第一个失败点。不要把 ping 通当成网页正常，也不要没查账单就重启服务。

07｜每月要养哪些东西

账单可以分三份看。域名和主机是定期续费的；文件下载、发信可能按用量扣钱；用了收款功能，还可能有交易手续费。把它们分别列出来，再设续费和余额提醒。否则有一天网站又打不开，你可能查半天代码，最后发现是漏付了一张账单。

成本提示词
根据我的 [云厂商、套餐、预计访问量与下载量] 查官方计费规则，分开列固定、用量和交易费用。缺参数用区间或标为待确认，告诉我哪些资源要单独设余额提醒。

08｜如果你也要上线，可以照这张清单验收

上线时，拿手机关掉 Wi-Fi，用流量当一回访客：打开正式网址，做一件这个网站最重要的事。作品集就打开一个作品，报名站就提交一张表，交易站就先在测试模式里下一单。

更新前留个备份，就像给账本留一份副本。页面改坏了，可以先换回旧版程序；账本本身坏了，才考虑找回数据。拿旧副本盖住整个账本前，记得查一下备份以后有没有新的记录。

发布验收提示词
为项目生成可执行的发布步骤和回退方案。先备份并在测试库演练恢复，再按顺序构建、迁移、更新。最后用外网验收 HTTPS 和实际功能。失败时说明能否只退回程序，以及恢复数据会影响哪些新记录。

09｜我学到的，是怎么把问题交代给 AI

以前我想问 AI 的是「帮我把网站搭好」。现在我会说：「先让我在浏览器打开页面，然后让我提交一次表单，并告诉我在哪里能看到这条记录。」做到哪一步，我自己点一遍就知道。

做第一个站，用得上什么再加什么。先跑通页面和主要功能，再考虑发信、下载或收款。AI 可以写代码、跑测试，购买域名、开商户和填正式凭证仍要用你自己的账户完成。

我是 Hardy，AI连续创业者。我在这里记录怎么用 AI 做各种应用，分享实用工具，拆解最新信息。

如果你也想把脑子里的点子做成真的东西，欢迎关注我。往期长文可以在主页找到。
