Polymarket 自动交易机器人创建方法

发表于2026-11-05|交易策略
|浏览量:

本文转载自 X 博主 @chenke20266（上车的乘客） 的长文，原文链接，版权归原作者所有。

一个可插拔策略、带完整风控、默认纸面模拟的Polymarket交易机器人。 先纸面/回测跑通，再手动开实盘。默认状态下它不会动你一分钱。

0. 先说清楚风险（真的请读完）

预测市场是 0/1 结算：仓位不是”浮亏”，而是可能直接归零。自动交易程序能做的只是 “按规则执行 + 限制损失规模”，不能保证盈利，也不能避免亏损。

2026 年Polymarket的真实成本结构（实测自 API）：

实测结论（2026-11-04，扫描前 80 个市场）：二元Yes+No套利在扣手续费后全部为负 （约 -10bps）。也就是说：网上教程里”买Yes+买 No稳赚”的说法在当前费率下基本不成立。 negRisk 篮子套利偶尔有空间，但深度很小、且必须拿到事件的全部腿。

1. 它能做什么

  • 套利策略：二元互补（买 Yes+No < 1）、negRisk 多结果篮子（买齐所有 Yes < 1）、残腿再平衡。
  • 做市策略：双边报价赚价差，库存自动偏移，maker 零费率。
  • 纸面撮合：真实盘口 + 悲观假设（按档位吃单、额外滑点、深度不足只部分成交）。
  • 回测：用 CLOB 历史价格序列重放策略（注意：没有历史订单簿，只能方向性参考）。
  • 风控：单市场/总敞口、日内亏损、最大回撤、滑点、冷却、挂单数、STOP 文件熔断。
  • 账本：SQLite 记录每一单的决策原因，重启后恢复持仓与挂单。

2. 它不能做什么（诚实清单）

  • ❌ 不能保证赚钱，也不能避免亏损。
  • ❌ 回测不能当收益预期：只有价格序列，没有历史订单簿，成交模型是近似。
  • ❌ 纸面模式不会自动结算：持仓按中价标记权益；市场结算后不会自动把仓位兑现成 1/0。 实盘请在网页 redeem 后再以实际到账为准（程序不会替你赎回）。
  • ❌ negRisk 篮子套利需要事件全部腿的盘口；缺腿时策略会主动放弃（不会瞎算）。
  • ❌ 实盘代码按官方 SDK py-clob-client-v2 1.2.1 编写，但没有用真钱验证过（本项目交付时没有你的凭据）。 第一次实盘请用极小金额。
  • ❌ 不是高频/低延迟系统：同步轮询（默认 3 秒）适合套利/做市这一档；抢单级别的延迟做不到。

6. 策略原理（为什么这样设计）

  • 意味着手续费在 p=50% 附近最贵（本金的 2%3.5%），在 p=2%/98% 处只有 0.1%0.2%。
  • 所以：50/50 附近的套利几乎不可能（Yes+No 的 ask 之和通常 ≥ 1.001，再加 2% 手续费）。
  • 结论：套利只在极端价格或 negRisk 篮子里可能有机会；做市靠 maker 零费率才是主战场。

6.2 二元互补套利

买 1 份 Yes + 1 份 No，成本 c，结算必得 1。净收益 1 - c - fee_yes - fee_no。 策略会：①算两腿深度能支撑的最大对数；②扣手续费后 edge ≥ min_edge_bps 才出手； ③两腿用 FOK 同时发，避免挂单留下裸敞口；④若只成交一腿，下一轮自动卖出多的那侧。

6.3 negRisk 篮子套利

一个事件下 N 个互斥市场，买齐 N 个 Yes 成本 < 1 即锁定利润。 必须用事件详情拿全 N 条腿——实测只取扫描子集里的 2 条腿会算出 +9900bps 的假机会， 所以策略会校验 ctx.event_market_counts，腿数不一致直接跳过。

6.4 做市（默认关闭）

预测市场的做市不是”先买后卖”，而是同时报两个买单：买 Yes @ m−½s、买 No @ (1−m)−½s。 两边都成交 = 用 1−s 的成本换 1 的结算价值，毛利 s。风险是单边成交造成库存， 策略用库存偏移（skew）纠正：多 Yes 就压低 Yes 买价、抬高 No 买价。

7. 实盘上线清单（按顺序做，别跳）

  1. 跑够纸面：至少 2~3 天，report.py 里没有异常事件、没有反常识成交。
  2. 理解费率：doctor.py 会打印”某概率下买 100 份的手续费占本金比例”，看清你要打的市场类目。
  3. 准备钱包：Polygon 钱包 + USDC。若用 Polymarket 网页账号， POLY_SIGNATURE_TYPE=2 + POLY_FUNDER=<网页个人页钱包地址>；自己导入的钱包用 0。
  4. 授权与 pUSD：2026 年抵押品是 pUSD，需要先 approve 新版交易所合约（V2）。 首次实盘前建议先在网页手动成交一笔小额，确认账户状态正常。
  5. 派生 API 凭据：
  1. 打开三重闸门：config.yaml → mode: live
    .env → POLY_CONFIRM_LIVE=I_UNDERSTAND_THE_RISK
    命令行 → –confirm-live
  2. 先清理未知挂单：python scripts\live.py –cancel-all
  3. 极小金额试跑：把 max_total_exposure_usdc 设成 20，–ticks 5 跑一次，人工核对 网页上的挂单/成交是否与本地账本一致。
  4. 持续运行：确认无误后再放大。建议同时挂 STOP 文件作为一键停机开关。

一键停机：在项目根目录创建名为 STOP 的空文件，主循环下一轮就会停止开新仓并退出。

8. 常见问题

Q：doctor.py 报 /book 单边盘口？ A：正常。接近结算的市场常只有一边有单。脚本会换几个市场找双边盘口验证；找不到才报错。

Q：扫描出来一堆 -10bps 的负 edge？ A：这才是真实情况——手续费吃掉了理论价差。不要为了”让它出手”把 min_edge_bps 调成负数。

Q：纸面模式为什么一直不成交？ A：纸面撮合刻意保守：限价单要等盘口真的穿过才成交，吃单按档位逐级。这是为了防止 回测/纸面出现虚假的乐观收益。另外默认 enabled 的套利策略在当前市场确实很难出手 （实测二元套利 edge 普遍 -10bps 左右）。

Q：重启后它会忘掉持仓吗？ A：不会。启动时从 SQLite 恢复持仓、现金、峰值权益与熔断状态（data/risk_state.json）， 实盘还会接管交易所上已有的挂单、用代币余额校准持仓。纸面模式想从零开始用 –fresh。

Q：为什么套利被拆成两笔、还可能出现”残腿”？ A：Polymarket 没有原子化多腿订单。程序用 FOK 尽量减少半成交，并在下一轮做再平衡 （二元卖多的那一侧、negRisk 篮子卖超出部分回到等量）。再平衡会实现一点价差损失， 这是可接受的代价——比裸着单边仓位过夜安全。

Q：实盘的手续费在账本里准吗？ A：按市场费率估算（size × rate × p(1-p)），与实际可能有小差异；最终请以交易所流水为准。

Q：Windows 下 pwsh 直接启动失败 0xC0000142？ A：这是本机 DSH 沙箱限制，与程序无关。用普通 PowerShell/终端运行上面的命令即可。

**Q：实盘下单报 **order version mismatch？ A：SDK 与账户订单版本不匹配。先 python scripts/doctor.py 看版本，再 pip install -U py-clob-client-v2。

Q：我能改策略吗？ A：可以。实现 strategies.base.Strategy.decide() 返回 StrategyDecision(intents=[…])， 在 strategies/init.py 的 REGISTRY 登记，再在 config.yaml 加参数即可。策略不需要碰网络。
