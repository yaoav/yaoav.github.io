One Gist Killed Manual Note-Linking

发表于2026-10-29|行业观察
|浏览量:

本文转载自 X 博主 @garrytan（Garry Tan） 的长文，原文链接，版权归原作者所有。

Linking notes by hand was never building a second brain.
It was killing one.

Karpathy published one gist that puts the model in charge of every cross-reference, every summary, every contradiction check. Seven repos already run the pattern, with about 255,000 GitHub stars between them.

What is inside:

  • The gist and the shift it makes
  • Three layers of a self-maintaining vault
  • The three operations that drive the system
  • Seven repos sorted by what they do
  • A starter route based on where your knowledge lives

[PATTERN] A gist that made the model the operator

llm-wiki.md lives under gist.github.com/karpathy. One file, one revision, created April 4, 2026.

It lays out an LLM that incrementally builds and maintains a persistent wiki of interlinked markdown files. Knowledge compiled once and kept current, not pulled from raw documents on every query.

Obsidian is the viewer. The model does the programming. The wiki is a codebase it maintains. The gist also points to Obsidian graph view, Web Clipper, Marp and Dataview as companion tools.

No plugin. No hosted service. One page of instructions that turns the model into a full-time vault caretaker.

[LAYER] Three layers that never mix

The gist splits a vault into three parts.

  • Immutable raw sources. PDFs, clippings, highlights, bookmarks. Nothing gets edited after it lands.
  • An LLM-owned wiki. Structured markdown notes the model writes, links and rewrites on its own. You read them. You do not maintain them.
  • A schema file. CLAUDE.md in the gist’s example. It tells the model how the wiki is organized, what qualifies as a good page and when to update.

Raw material enters at the bottom. Compiled knowledge lives in the middle. The schema sits on top and governs every move.

[INGEST] Drop a source, the vault rewrites itself

Ingest is the first of three operations.

  • Trigger: a new raw source enters the vault.
  • Action: the model reads the source, writes a wiki summary, updates every related page.
  • Result: new or revised notes with cross-references already in place.
  • Record: index.md and an append-only log.md track what changed.

One file dropped in triggers a cascade. The model traces connections back through the existing wiki and rewrites whatever shifted.

[QUERY] Ask the wiki, file the answer back

Query is the second operation.

  • Trigger: a question from the vault owner.
  • Action: the model answers from compiled wiki pages, not from the raw layer.
  • Result: the answer gets filed back as a new wiki page when it holds lasting value.
  • Effect: the next question on the same topic finds a compiled page, not a re-derived answer.

Answers that hold weight become pages. The vault compounds instead of repeating work.

[LINT] Flag what drifted before it spreads

Lint is the third operation.

  • Trigger: a periodic pass across the entire wiki.
  • Action: the model checks for contradictions between pages, stale claims, orphan pages, missing cross-references.
  • Result: flags on notes that conflict, gaps where links should exist, pages that nothing points to.

Two notes that disagree get flagged. So does a page with zero inbound links, or a claim that aged past its source. You set the schedule.

[STACK] Seven repos, about 255,000 stars

The gist defines the pattern. These repos turn it into running code.

  • graphify. Parses codebases, docs, SQL schemas, configs and PDFs into a queryable knowledge graph. Runs as a skill in Claude Code, Cursor, Codex and Gemini CLI, all parsing local with tree-sitter. About 137.9k stars, Apache-2.0 and MIT.
  • Understand-Anything. Turns your codebase into a browsable graph you can search and query directly. 88.8k stars, MIT.
  • claude-obsidian. Keeps sources untouched, builds linked cited notes, answers from the vault, saves good answers back, runs health checks for broken links and orphan pages. 15.9k stars, MIT, 351 commits.
  • obsidian-second-brain. Persistent memory for Claude Code, Codex and six other agents, stored as plain markdown in the vault. About 5.0k stars, MIT, 647 commits.
  • mcp-obsidian. One MCP server with seven tools: list files in vault and in directory, get contents, search, patch content, append content, delete file. Needs the Obsidian Local REST API community plugin and its API key, defaults to 127.0.0.1:27124. 4.5k stars, MIT.
  • claudesidian. A ready-made vault built for Claude Code, structured from the ground up. 2.6k stars, MIT.
  • second-brain. An Obsidian wiki the model keeps current, built on the llm-wiki.md pattern. 764 stars.

[ROUTE] Pick one repo by where your knowledge lives

  • Your knowledge lives in code. Start with graphify. It turns your repo into a graph without leaving your editor.
  • Your knowledge lives in Obsidian already. Start with claude-obsidian. It files sources into linked notes and answers from the vault.
  • You want the model to remember across sessions. Start with obsidian-second-brain. Plain markdown, six agents can read it.
  • You live in Claude Desktop. Start with mcp-obsidian. Seven tools wire one MCP server to the whole vault.

One repo. One evening. The vault starts maintaining itself.

[COMPILE] The model is the programmer now

The pattern is model-agnostic. The gist names Obsidian as the viewer and CLAUDE.md as one schema example. Whatever LLM you run fills the programmer slot.

mcp-obsidian ships with delete_file and patch_content. Any agent with write access can damage a vault. Keep a git history or a backup before you wire anything in.

Three operations handle the rest. Ingest files each source, query compounds every answer, lint catches what drifted.

You stopped being the librarian. The vault is a codebase now.
