Jev: Stop Paying Frontier Models to Make Simple Decisions

发表于2026-09-22|行业观察
|浏览量:

本文转载自 X 博主 @alannnfx（Alan） 的长文，原文链接，版权归原作者所有。

Most of what you pay a frontier model for isn’t thinking. It’s a yes or a no

Your agent sits in a loop, picking the next worker, checking if a result is good enough, deciding whether to keep going.

Each one of those is a full model call that costs tokens, waits on generation, and comes back as a paragraph you have to parse.

That’s a $0.03 hammer driving a thumbtack.

Those decisions don’t need a brain that writes, they need a brain that decides, and that’s the gap Jev is built for.

The paradox nobody’s talking about

There’s a rule from 1865 called the Jevons Paradox.

When a steam engine got more efficient at burning coal, total coal consumption went up instead of down, because cheaper fuel didn’t mean less fuel, it meant people used it everywhere.

That’s the global problem for AI right now. Tokens get cheaper every quarter, usage explodes, and the bill stays the same or grows.

Jev is built to break that cycle.

What Jev actually is

Jev is TypeSafe AI’s System One model.

You send it state and predefined questions, and it returns typed answers with probabilities. No text generation, no chat, no autoregressive loop.

It does one thing. It decides.

And it does it roughly 200x faster and 400x cheaper than an LLM doing the same job. Those are TypeSafe’s own workflow evals, so treat them as a ceiling, not a promise.

The underlying advantage is real: no long reasoning traces, no generated output, just a bounded decision.

The whole surface area is three formats

You don’t need to learn a framework, Jev gives you three question types and that’s it.

  • Choice picks one option from a list you define, up to 255 of them. Good for routing and categories

  • **Score **places the input on a scale you define. Good for urgency, quality, risk

  • Noul answers a yes-or-no question as a number between 0 and 1

Every answer comes back with probabilities and a confidence score attached, fully typed, with no JSON prompting, no parser and no retry loop when the model decides to wrap your object in a markdown fence.

Here’s what a call actually looks like when an invoice dispute lands in a support inbox:

Three questions in one call, and because they evaluate in parallel, twenty of them cost roughly what one costs.

Ask everything you want to know about a piece of state at once, since designing around one question per call is the first mistake everyone makes.

The confidence score is the actual product

A classifier hands you a label, and then you have to decide whether to trust it with nothing to decide with.

Jev hands you a label and a calibrated number saying how sure it is, and the docs tell you to treat anything under 0.3 to 0.5 as a signal to stop and ask a human instead of acting.

That’s the difference between a fast classifier and a decision layer. The label tells you what it thinks, and the confidence tells you whether you’re allowed to act on it, without it you’re back to hoping.

The pattern that falls out: your escalation policy becomes a number in a config file instead of a paragraph in a system prompt.

Feed it candidates, don’t ask it to invent

Every implementation that impressed anyone follows the same shape: build the option set in code, then let Jev pick from it.

  • A browser agent builds its action space from the DOM each step, and Jev chooses the next click.
  • A retriever fetches chunks as normal, and Jev deletes the ones that don’t belong.
  • A launcher ranks files and Jev re-ranks them on every keystroke.

The API call is trivial, the taxonomy is the work. One builder who spent a week trying to break the model concluded that if the grading is wrong, nothing else matters.

What people are actually shipping

Four patterns are worth stealing because each one generalizes.

Model routing. Put Jev in front of your model fleet and let it decide which brain handles each request. It’s the most-cited job in the ecosystem for a reason: the routing decision was always the cheapest part of the request, and it always got made by the most expensive thing in the stack.

Context compaction. Coding agents hit the context ceiling and run a summarization prompt. Replace that with a Jev pass that scores every tool call for relevance and drops the dead weight. One run took a session from nearly a million tokens down to 86K in about a second.

Safety review before execution. Every coding harness runs a classifier asking “should this command actually execute?” before auto mode lets it. One team benchmarked Jev against their current reviewer and reported it up to 18x faster at p95, and more accurate.

Real-time loops. A browser agent with a new action space every step, DOM as the state, a small LLM only waking up when something needs typing. Zürich to London on Google Flights in 7.073 seconds, for $0.0039.

The marketing gets one thing wrong

“Jev can’t hallucinate” has been doing a lot of work in the launch copy, and it isn’t right.

Jev cannot emit an invalid type, that’s real, and it’s why the output drops straight into your code with no validation layer.

But it can emit a wrong value that happens to be a valid one, and type safety is not correctness.

A schema-valid mistake can still refund the wrong customer, route an incident incorrectly, or approve a dangerous command. The safer sentence is: Jev cannot break the declared output schema, but it can still be wrong.

The shift

An LLM creates the work, Jev decides what happens next, and code executes the decision.

That split changes the entire agent stack. Let the LLM research, plan, and write, let Jev route, score, approve, or escalate, and let code run the branch.

Most builders will keep spending frontier-model tokens on every yes, no, route, and score. The few who separate thinking from deciding will build faster agents at a fraction of the cost.

Where to start

Don’t rebuild your agent around Jev, just find one decision that currently requires a slow LLM call or a regex that keeps breaking.

Give Jev the minimum state, define the possible answers, and log its probabilities beside the current result, letting it prove that it deserves one branch before you hand it the whole workflow.

Start with one repeated decision, measure it, then replace the next one.

The most useful mental model stays the simplest one: Jev adds judgment where an ordinary if statement understands the values but not their meaning.

Bookmark this before your next agent, then go find the one decision you’re overpaying for.
